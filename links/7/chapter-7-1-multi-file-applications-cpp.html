Chapter 7.1 - Multi-file applications - multiple .cpp files

Posted Apr 13, 2025
By Filip Kwiatkowski
5 min read

Splitting code into smaller fragments

As it is known, when the entire program is written within one function (e.g., in main()), it becomes huge and challenging to analyze. A good idea is to separate its individual parts into separate functions, which we will then call within the original one.

In this way, more code may be created, but at the same time, the readability of the entire program will significantly increase.

A similar situation occurs when the number of functions in a given file reaches enormous values. Sometimes it’s a good idea to split such a file into several others.

Let’s write some C++ application and split it into multiple files. The first one will be an application using a simple function isEven():

Here’s the list of issues:

  • The file even.cpp is not part of our application. It is located in the same place as main.cpp or CMakeLists.txt, but CMake is not aware of it.
  • Within the main.cpp file, there is no knowledge of the existence of a function named isEven(). It is undeclared.

To fix these issues, we need to:

  • Modify the CMakeLists.txt file to include the even.cpp file. After all, it needs to be compiled and linked to our application.
  • Add a declaration of the isEven() function in main.cpp. Just including it in the project is not sufficient — for the same reason that when implementing a function below main(), it needs to be declared above it.

So, the following changes need to be made:

When creating multi-file applications in C++, remember to add their names to add_executable(). Additionally, it’s crucial to ensure that a function is declared before it is used. This is especially evident in the case of multi-file applications.

.cpp files are called implementation files or source files.

Using other libraries in separate .cpp files

Let’s expand our program with an additional file — printer.cpp:

1
2
3

auto print() -> void {
    fmt::println("Hello");
}

Of course, it’s important to remember to add its name to the list of files in add_executable() within CMakeLists.txt.

Unfortunately, even if we add the declaration of the print() function within main() and try to call it:

1
2
3
4
5
6

auto isEven(int const n) -> bool;
auto print() -> void;

auto main() -> int {
    print();
}

We are going to encounter a compilation error:

1
2
3

printer.cpp:2:5: error: 'fmt' has not been declared
    2 |     fmt::println("Hello");
      |     ^~~

It’s worth noting that this time the error concerns the printer.cpp file rather than the main.cpp file. It indicates that within this file, the fmt namespace is not known.

This is because we haven’t added #include <fmt/base.h> in this file. Implementation files (.cpp) do not share #include directives among themselves. It needs to be added for the program to work:

1
2
3
4
5

#include <fmt/base.h>

auto print() -> void {
    fmt::println("Hello");
}

Now the program will work correctly.

Summary of changes and project structure description

Currently, our application consists of three source files:

  • main.cpp
  • even.cpp
  • printer.cpp

And one configuration file: CMakeLists.txt.

main.cpp serves as the “starting point” of the application. We have declared functions in it that are defined in other files (even.cpp and printer.cpp).

printer.cpp uses fmt::println(), so it needs to have the appropriate #include <fmt/base.h>. main.cpp, Even though it calls print(), which in turn uses {fmt}, does not need to include the header from this library itself. main() doesn’t need to know how print() works. It’s enough for it to know its header1.

The CMakeLists.txt file, using add_executable(PJC main.cpp even.cpp printer.cpp), creates an executable file PJC (.exe), which consists of compiling and linking the main.cpp, even.cpp, and printer.cpp files.

Additionally, by using target_link_libraries(PJC fmt), we include the {fmt} library in our application, making it visible to all files (so they can #include it and use it).
