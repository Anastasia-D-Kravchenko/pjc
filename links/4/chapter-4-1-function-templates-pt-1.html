Chapter 4.1 - Function templates, pt. 1

Posted Mar 24, 2025
By Filip Kwiatkowski
8 min read

Reducing code duplication to a generic, single implementation

Function templates are used to replace an implementation that works for one type with an implementation that works for many different types.

Using templates is a “step further” in the hierarchy of using functions and then using function overloads.

For example, let’s assume we don’t have access to the {fmt} library, and we often want to display several kinds of vectors. It seems that in this case, the best solution would be to create a set of function overloads, for example, like this:

auto print(std::vector<std::string> const& vec) -> void {
    for (auto const& element : vec) {
        std::cout << element << ' ';
    }
    std::cout << '\n';
}

auto print(std::vector<double> const& vec) -> void {
    for (auto const& element : vec) {
        std::cout << element << ' ';
    }
    std::cout << '\n';
}

A simple conclusion immediately arises here — we are dealing with code duplication. Effectively, the bodies of all print() function overloads are identical. In such cases, it is worth replacing such a set of overloads with a single template:

template <typename T>
auto print(std::vector<T> const& vec) -> void {
    for (auto const& element : vec) {
        std::cout << element << ' ';
    }
    std::cout << '\n';
}

Now let’s discuss in detail the elements visible in the implementation of the print() template:

Firstly, we see the line template <typename T>. This line indicates that the element directly below it will be a template. When we write auto print(std::vector<T>& vec) -> void { ... } just below such a line, the compiler knows that print() is a template. A template that introduces the name T (because we wrote <typename T>).

T is a so-called template parameter. You can think of it as a kind of placeholder that will be matched to the type that is needed.

For example, when we call print(ints), the compiler looks for a matching name print that can be called as a function passing the object ints. It doesn’t find one, so it starts looking to see if any template can be matched so that this call succeeds.

Here comes our print() template. The compiler checks if the argument matches the parameter. The argument is std::vector<int>, and the parameter is std::vector<T>. Fortunately, T is a template parameter that can be matched to any type. The compiler substitutes T with int, making the argument match the parameter. The matched template generates an implementation that is called.

Templates generate code.

A function template is not a function. When the compiler needs to use a template and parameter matching succeeds, it generates the appropriate implementation with the parameters replaced.

The whole situation repeats when the compiler sees print(strings). It looks for a name print that can be called as a function taking the argument strings. There isn’t one. So it looks for a template. It finds our print() and tries to match T to std::string. It succeeds (why wouldn’t it — we’ll see later when such a situation might fail), so an implementation is generated with the same code as our template, but with the type std::string substituted instead of T.

A similar situation occurs when calling print(doubles).

An interesting situation arises when we call print(ints) (or any other print() with a type for which the template has already been instantiated). Let’s recall that earlier we learned that the compiler first looks for a name (e.g., a function) that can be called as a function with a given argument. Let’s imagine that main() looks like this:

auto main() -> int {
    auto const ints = std::vector<int>{1, 2, 3};

    print(ints);
    print(ints);
}

We already know what happens when the compiler reaches the first print(). It looks for a matching name (function, lambda, function object, really anything that can be called as a function taking ints). It doesn’t find one. Instead, it finds our template. It substitutes T = int, and then generates a function implementation that behaves like the code in our template.

The interesting situation mentioned a moment ago occurs with the second print(ints). Why? Because the compiler has just generated the appropriate implementation. This means it doesn’t have to do it again. It will reuse the implementation it generated just now.

Templates with multiple template parameters

The presence of <typename T> introduces a placeholder for a type. However, it’s not limited to single use. There’s nothing stopping us from accepting more parameters of this “type”:

#include <iostream>
#include <vector>

template <typename T>
auto printBigger(
        std::vector<T> const& first, std::vector<T> const& second
) -> void {
    auto const& bigger = first.size() > second.size() ? first : second;

    for (auto const& element : bigger) {
        std::cout << element << ' ';
    }
    std::cout << '\n';
}

auto main() -> int {
    auto const ints1 = std::vector<int>{1};
    auto const ints2 = std::vector<int>{1, 2};
    auto const ints3 = std::vector<int>{1, 2, 3};

    printBigger(ints1, ints2);
    printBigger(ints2, ints3);
}

As you can see, in the printBigger() template, we used T twice. This template will display the contents of the longer of the vectors passed as arguments.

At this point, one might wonder if using std::vector is necessary when using templates. It’s not. The example with their usage was chosen to present a simple yet practical problem.

There’s nothing stopping us from using template parameters as “standalone” parameter types:

#include <iostream>

auto printBigger(T const& first, T const& second) -> void {
    if (first > second) {
        std::cout << first;
    } else {
        std::cout << second;
    }
    std::cout << '\n';
}

auto main() -> int {
    auto const x = 10;
    auto const y = 20;
    auto const z = 30;
    printBigger(x, y);
    printBigger(y, z);
}

However, one must be careful in situations where it seems that the code should work correctly, but the compiler (rightfully) protests. For example:

   17 |     printBigger(x, y);
      |     ~~~~~~~~~~~^~~~~~
main.cpp:4:6: note: candidate: 'template<class T> void printBigger(const T&, const T&)'
    4 | auto printBigger(T const& first, T const& second) -> void {
      |      ^~~~~~~~~~~
main.cpp:4:6: note:   template argument deduction/substitution failed:
main.cpp:17:16: note:   deduced conflicting types for parameter 'const T' ('int' and 'double')
   17 |     printBigger(x, y);
      |     ~~~~~~~~~~~^~~~~~

The error, although exceptionally expressive, speaks quite directly about the problem — printBigger() requires both arguments to be of the same type. This is because we used the same placeholder T in both cases. However, we passed int and double as arguments. Obviously, it’s impossible to match T to be both an int and a double simultaneously. In such a case, the compiler protests.

But how can we fix this error? After all, there’s nothing wrong with comparing an int to a double. The following code compiles correctly:

auto main() -> int {
    auto const x = int(10);
    auto const y = double(10.5);

    if (x < y) return 0;
    else return 1;
}

To fix the discussed problem, all we need to do is introduce a second template parameter. Instead of introducing a single template parameter T, let’s introduce two different placeholders. For example, T and U1:

#include <iostream>

template <typename T, typename U>
auto printBigger(T const& first, U const& second) -> void {
    if (first > second) {
        std::cout << first;
    } else {
        std::cout << second;
    }
    std::cout << '\n';
}

auto main() -> int {
    auto const x = int(10);
    auto const y = double(10.5);

    printBigger(x, y);
}

The solution sounds quite logical — we have two different types, so we introduce two different placeholders.

  1. The names T and U are, of course, arbitrary — there’s nothing stopping us from using A, a, or even FirstParameter instead of T. ↩
