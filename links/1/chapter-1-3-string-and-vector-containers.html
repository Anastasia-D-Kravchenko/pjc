Chapter 1.3 - std::string and std::vector containers

Posted Feb 25, 2025
By Filip Kwiatkowski
9 min read

std::string container

One of the most popular data types in programming is the string type. Java’s String has its counterpart in C++ in the form of the std::string class. Both of these classes are used for storing and modifying text.

The most noticeable difference between String (Java) and std::string (C++) is the access to their elements (individual characters) and the ability to modify them.

In Java, access to characters is done using the .charAt() method. There is no possibility to change the stored text — to do this, a new String must be created.

Operations on strings in C++ closely resemble operations on convenient character arrays. Not only can you access a specific character using indexing (similar to arrays — using []), but you can also change the contents of std::string objects without the need to create new ones.

Immediately, three very important facts about using text objects in C++ can be noticed:

  1. All the above code snippets introduce a new line with the #include <string> directive. This directive, just like #include <iostream>, is a preprocessor directive that pastes the contents of the <string> header into our code file.
  2. An object of type std::string can be indexed just like arrays. The “classic” for () loop additionally illustrates that std::string (like any container in the C++ standard library) provides the .size() method, which tells how many elements are in the object.
  3. std::string (like any container in the C++ standard library) supports iteration over it using the range-based for () loop.

The above examples illustrated only ways to display text. But what about modifying it?

For example, let’s change the first letter to lowercase and the last one to an exclamation mark:

#include <iostream>
#include <string> 

auto main() -> int {
    auto text = std::string("Programming in C++");

    auto firstIndex = 0;
    auto lastIndex  = text.size() - 1;

    text[firstIndex] = 'p';
    text[lastIndex]  = '!';

    std::cout << text;
}

The result of running this code is the display of the text programming in C+!.

It turns out that when accessing individual elements of a collection, programmers are most often interested in the first and last ones. Therefore, selected containers in C++ (including std::string) provide additional, dedicated methods for precisely these operations:

#include <iostream>

auto main() -> int {
    auto text = std::string("Programming in C++");

    text.front() = 'p';
    text.back()  = '!';

    std::cout << text;
}

The result of executing the above code is also the display of the text programming in C+!.

The syntax on lines 7 and 8 may seem strange — as if we’re assigning something to a method or its result. In fact, that’s exactly what’s happening — the second of these associations is correct. This is thanks to references, which will be explained in more detail in the near future.

Of course, you can use the .front() and .back() methods not only to overwrite elements but also to simply display them.

Using the .front() or .back() methods on an empty container results in Undefined Behavior (UB).

Characters can be added to a std::string in many ways. The most common way to do this is using the += operator.

#include <iostream>
#include <string>

auto main() -> int {
    auto text = std::string();

    auto first  = std::string("Programming");
    auto second = std::string("in");
    auto third  = std::string("C++");

    for (auto chr : first) text += chr;
    text += ' ';
    for (auto chr : second) text += chr;
    text += ' ';
    for (auto chr : third) text += chr;

    std::cout << text;
}

Running the above code will display the text Programming in C++. It’s worth noting that, just like in Java, you can omit braces under loops or if () statements if a single instruction is to be executed within the body.

The .substr() method allows you to construct a new std::string object containing the specified fragment of the original text. The first argument is the starting index, and the second argument is the number of characters to copy.

C++ prioritizes application performance. Therefore, it’s not difficult to imagine that creating a completely new object (which often implies memory allocation and copying) when the programmer is interested only in working on a fragment of the original std::string is not always the best idea. At this point in PJC, there’s no need to worry about this, but if someone wants to read about potentially more efficient alternatives, it’s worth delving deeper into this topic 1.

std::vector container

std::string is a container that stores characters. It’s easy to guess that there exists a more generic container — one that can store anything. It’s called std::vector.

std::vector and std::string are the most commonly used containers in C++.

When declaring a variable of type std::vector,2 you need to specify what type of elements it will store. This is illustrated in the following listing:

#include <string>
#include <vector>

auto main() -> int {
    auto integers    = std::vector<int>();
    auto realNumbers = std::vector<double>();
    auto words       = std::vector<std::string>();
}

We notice a new header — #include <vector>.

We specify the type of vector elements within angle brackets (<>).

Instead of using the default constructor, you can create a vector already filled with elements. We use braces ({}) instead of parentheses (()).

    auto integers    = std::vector<int>{1, 2, 3};
    auto realNumbers = std::vector<double>{3.14, 2.71, 1.61};
    auto words       = std::vector<std::string>{"Hello", " ", "World"};

If you don’t know what elements the vector will store, you can create it empty and then add elements using the .push_back() method. It adds a new element to the vector, placing it at the very end of the container (effectively increasing its size by 1):

#include <iostream>
#include <string>
#include <vector>

auto main() -> int {
    auto integers = std::vector<int>();

    for (auto i = 0; i < 10; i++) {
        integers.push_back(i);
    }

    for (auto element : integers) {
        std::cout << element << ' ';
    }
}

A vector, similarly to std::string, supports methods like .size(), .front(), and indexing.

Naturally, adding elements is only half the battle. Sometimes you also need to remove them. To remove an element from the end of the vector, you should use the .pop_back() method, which removes an elements from the vector’s back (effectively decreasing its size by 1):

#include <iostream>
#include <vector>

auto main() -> int {
    auto integers = std::vector<int>{1, 2, 3, 4, 5};

    auto toRemove = 0;
    std::cin >> toRemove;

    if (toRemove > integers.size()) {
        toRemove = integers.size();
    }

    for (auto i = 0; i < toRemove; i++) {
        integers.pop_back();
    }

    std::cout << integers.size() << '\n';
    
    for (auto element : integers) {
        std::cout << element << ' ';
    }
}

The above listing will prompt the user to enter the number of elements to remove from the vector. If the entered number is greater than the number of elements in the vector, it will be adjusted accordingly. Finally, the number of remaining elements in the vector is displayed.

std::string also supports .push_back() and .pop_back(), although in the case of this class, the .push_back() method is rarely used. Most containers share many methods, although sometimes some of them are used very rarely.

std::string class versus C-string literals

Surely, some have already noticed the first presentation of a text type, more precisely the explicit specification of the type std::string. So what’s the difference between "Text" and std::string("Text")?

It would be a very minor mistake to reply “everything.”

1

auto string = std::string("Text");

1

auto rawText = "Text";

A C-string is the “rawest” form of text stored in a computer. It doesn’t represent any object in the conventional sense of the term. It’s simply an unmodifiable array of characters stored in computer memory, accessible via its address. With such a variable rawText, we can’t perform any interesting operations.

Variables representing access to C-strings support indexing, but, for example, they won’t tell us how many characters they consist of (they don’t have the .size() method) because they don’t support any methods. Effectively, they can only be used for displaying or initialization of objects of the std::string type.

If we’re not interested in any methods and only need to specify a text literal, we don’t need to put it in an object of type std::string — simply use a C-style string literal, as demonstrated in the examples above, such as in std::cout << "kg stands for kilo".

However, most of the time when storing text, we’ll create objects of type std::string for convenience.
