Conversion operators

The final type of operators we will discuss is conversion operators. Like with most operators, we have already dealt with them, only we didn’t realize it. Specifically, when working with text files, more precisely, when automating loading.

So how does this code display all the words from the file?

#include <fstream>
#include <string>

#include <fmt/base.h>

auto main() -> int {
    auto file = std::fstream("../data.txt");

    for (auto word = std::string(); file >> word; ) {
        fmt::println("{}", word);
    }
}

In the second part of the for() loop (where file >> word is located), there must be a logical value. A bool, or at least an expression that returns a bool.

This is because the expression file >> word returns a reference to file, and file is of type std::fstream, which, in turn, has the operator bool defined. Therefore, when something expects a bool but receives std::fstream, it uses this operator to — according to some logic — check if this type is in a valid state.

Such an operator bool simply checks if the state of the object is “valid” and if so, returns true.

Conversion operators can help the programmer create one type from another. For example:

#include <string>

#include <fmt/base.h>

struct Person {
    std::string name;
    std::string surname;

    operator std::string() const {
        return name + " " + surname;
    }
};

auto main() -> int {
    auto p = Person("Dio", "Brando");
    auto text = std::string(p);
    fmt::println("{}", text);
}

1

Dio Brando

Normally, you cannot create an std::string from an object of type Person. How could you? std::string doesn’t have such a constructor.

However, when our object knows how to transform itself into an std::string, it ceases to be a problem!

Similarly, std::fstream can transform itself into a bool.

A practical example could be an abstraction representing a pixel consisting of three colors — red, green, and blue:

But we can provide the ability for automatic conversion from Pixel to std::array<int, 3>:

#include <array>

#include <fmt/ranges.h>

struct Pixel {
    int red;
    int green;
    int blue;

    operator std::array<int, 3>() const {
        return {red, green, blue};
    }
};

auto drawPixel(std::array<int, 3> pixel) -> void {
    fmt::println("drawing: {}", pixel);
}

auto main() -> int {
    auto pixel = Pixel(1, 33, 7);
    drawPixel(pixel);
}

1

drawing: [1, 33, 7]

One could think that a constructor dictates how a particular object should be created, while a conversion operator specifies what an object can be transformed into. In the end, both of these elements in some way govern the creation of something based on something else, but in a sense, “from different sides.”
