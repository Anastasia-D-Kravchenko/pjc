Chapter 8.3 - Operator overloading, pt. 1

Posted Apr 24, 2025
By Filip Kwiatkowski
3 min read

Operator overloading

The fact that we can compare two objects of type std::string or std::vector<T> using == instead of using methods like .equals() is thanks to operator overloading. This tool allows us to change the behavior of built-in language operators, such as ==, !=, <, >=, and even !, [], and (). Thanks to them, we achieve language consistency. It’s very convenient that accessing elements in a vector, array, or string is done using indexing ([]) instead of dedicated (sometimes differently named) methods, isn’t it?

Let’s start our adventure with operator overloading with one of the Big Three, namely the assignment operator.

operator=

Overwriting an object, whether it’s primitive or composite, is one of the key operations at a medium level of abstraction. For example, we can’t iteratively find the largest or smallest element without overwriting any auxiliary variable. The logic of overwriting an object is controlled by the assignment operator, operator=.

Operator overloading seems very strange at first glance. To define the logic of overwriting for a known class Point, we need to use the following constructions:

struct Point {
    int x = 0;
    int y = 0;

    Point(int const x, int const y) : x(x), y(y) { }

    auto operator=(Point const& other) -> void {
        x = other.x;
        y = other.y;
    }
};

At first glance, it looks terrifying, but you quickly realize that it’s nothing more than a specially named function. There’s auto, there are parameters, there’s a return type, and a body. It’s just the name that’s strange — operator=. When we overload an operator, we’re actually defining a function with a special name (like operator=).

“Logic-wise,” such an operator should overwrite the fields of the point on which it’s called with the values of the fields that are being copied. For example, if p1 and p2 were of type Point, then p1 = p2 would call our overloaded operator. The fields to be overwritten would be p1.x and p1.y, and other would be p2.

It’s also worth knowing that typically operator= should return something other than void. Specifically, it should return T&, where T is the class type for which it’s defined. To implement it fully correctly, we would need to use a tool we haven’t covered yet1, so for now, let’s simplify this part and assume that we’re returning void.

Alright, but is there any sense in having this overload in our Point structure? What does it give us in this context?

Nothing. C++ by default supports generating such operators, although automatic generation doesn’t always give the expected result. Perhaps sometimes we don’t want to copy all the fields, or we even want the copying to do something else — for example, inform a database that our type has been cloned. Defining the = operator allows us to control the behavior triggered when someone overwrites one Point with another.

Other types of operators

In the further part of the chapter, we’ll learn about many more operators that we can overload — with appropriate classification into groups. There are plenty of them, and proper terminology will help us reason about them better, so let’s start with the classification of the assignment operator, =:

operator= is a binary operator, which must be implemented as a method.

A binary operator is one that has two arguments. Examples of binary operator calls include x = y, x + y, x <= y, etc.

Some operators must be overloaded as methods, while others must be overloaded as free functions. However, most of them can be overloaded as both methods and free functions.
