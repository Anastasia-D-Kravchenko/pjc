Natural sorting

A common pitfall in the default sorting method available in most programming languages is how numbers in text are treated. Simply put, when a string contains digits, the resulting sorting orders can be surprising. For example:

auto main() -> int {
    auto fileNames = std::vector<std::string>{
        "lecture 1", "lecture 2", "lecture 3",
        "lecture 10", "lecture 11", "lecture 12",
        "lecture 35", "lecture 39", "lecture 92",
        "lecture 101", "lecture 111", "lecture 133",
        "lecture 159", "lecture 212", "lecture 221"
    };

    std::ranges::sort(fileNames);

    fmt::println("{}", fmt::join(fileNames, "\n"));
}

Undoubtedly, this is a surprising result, especially if someone was not aware of this behavior beforehand.

Nevertheless, such behavior is justified — after all, the text is compared lexicographically, i.e., dictionary-wise. If "aaa" should come before "z", then why shouldn’t 111 come before 9, right?

On the other hand, this is not the behavior we usually desire, especially when — for example — sorting files on a computer.

The sorting algorithm that would arrange these elements according to our intuition is called natural sorting. If we applied this sorting instead of the default std::ranges::sort(), the result would be:

Implementation

Modify the code listing presented earlier so that the sorting algorithm sorts the elements of the fileNames vector according to natural sorting.

Improving the implementation

The created comparator (or projection) is likely to be quite extensive. Enhance the implementation by creating a namespace pjc, in which you will place the naturalOrder() function, which will return the created comparator. Using the new namespace, extract helper functions / lambdas used in the implementation of naturalOrder().
