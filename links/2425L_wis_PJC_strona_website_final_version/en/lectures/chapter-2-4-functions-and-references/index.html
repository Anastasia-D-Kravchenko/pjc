Chapter 2.4 - Functions and references

Functions in C++

One of the most significant elements of programming are functions. They allow us to give a name to a certain piece of code and, using that name, succinctly specify what kind of operation should be performed at a given point.

Functions in C++ serve the same purpose as in Java. Once a function is written, it can be called multiple times with appropriate arguments. Let’s look at the example below:

#include <fmt/base.h>

auto sayHello() -> void {
    fmt::println("Hello!");
}

auto main() -> int {
    sayHello();
    sayHello();
}

Hello!
Hello!

A popular programming practice (which is even suggested in Robert C. Martin’s timeless “Clean Code”) is defining functions after they are used. The idea is that when reading the code from top to bottom, one should not wonder why we need the sayHello() function. We aim for the person reading the code to first see main(), understand how (and why) sayHello() is used, and then (only if they have a need) read further and become acquainted with its definition.

So let’s refactor appropriately and place the definition of the sayHello() function below main():

1

#include <fmt/base.h>

auto main() -> int {
    sayHello();
    sayHello();
}

auto sayHello() -> void {
    fmt::println("Hello!");
}

Unfortunately, this code will not compile. Depending on the compiler used, the error message may differ, but ultimately it will indicate something similar to this:

1

error: 'sayHello' was not declared in this scope

How come? The sayHello() function is declared and defined within this file. It’s on line 8.

That’s true. While this is not problematic in Java, unfortunately such a construction will not pass the compilation process in C++. This is because the compiler will not search for declarations throughout the rest of the file or project.

In order to use a created entity (variable, function, class, etc.) in C++, it must be declared beforehand.

Declaration and definition are not the same.

Declaration
An instruction informing the compiler about the existence of a given entity.
Definition
An instruction informing the compiler about all the details of a given entity.

In our case, the problem is that the compiler, when trying to compile the body of the main() function, does not know that a function named sayHello() exists. In the previous version of the code, when the entire definition was placed inside main(), the compiler knew everything.

Let’s go back to the original version of the code.

1

#include <fmt/base.h>

// Declaration and definition
auto sayHello() -> void {
    fmt::println("Hello!");
}

auto main() -> int {
    sayHello(); // usage
    sayHello(); // usage
}

As stated in the comment on line 3, when a function definition appears that has not been previously declared, it also serves as its declaration.

All right, but is it possible to put the body of sayHello() below main() at all?

Yes, you just need to separate the function into a declaration and a definition:

#include <fmt/base.h>

// Declaration
auto sayHello() -> void;

auto main() -> int {
    sayHello(); // usage
    sayHello(); // usage
}

// Definition
auto sayHello() -> void {
    fmt::println("Hello!");
}

Function declaration involves specifying its header without the body. Later, you can define the function (providing both the header and the body).

It’s not an ideal solution, but it’s still better than defining all functions in the reverse order of what interests the programmer.

References

Let’s assume the following task:

Write a function modify() that takes an int variable as an argument. The function should increase the value of the passed number by 10.

Now, let’s assume we got this task in a Java course, meaning we solve it in Java. With code like this:

1
2
3
4
5
6
7

public class Main {
    public static void main(String[] args) {
        int x = 5;
        modify(x);
        System.out.println(x);
    }
}

It’s not possible to implement the modify() function so that the print statement on line 5 displays anything other than 5.

In Java, all arguments are passed by copy (but due to the semantics of references, when we pass a reference type variable, a copy of the reference itself is passed, so we work on the original object). Modifying a primitive type parameter won’t have any effect on the original argument.

Now, let’s go back to C++ and repeat the same task. Is there a way to define the modify() function so that the code below displays 15?

1
2
3
4
5
6
7
8
9

#include <fmt/base.h>

auto modify(int x) -> void;

auto main() -> int {
    auto x = 5;
    modify(x);
    fmt::println("{}", x);
}

Without a slight modification — no. But with a slight modification (which concerns only the modify() function) — yes.

The tool that will help us with this is references. Let’s look at an example of their usage:

1
2
3
4

auto main() -> int {
    auto  x   = 5;
    auto& ref = x;
}

ref is a reference, and as you can see, we explicitly declare it by adding an ampersand (&) after auto.

Fantastic, but what does it do? How do we use it? What does it give us? Why would we want to use it? What exactly is the type of a reference variable?

These are very good questions. Let’s start with a brief definition, and then we’ll answer them in detail.

A reference is an alias for an existing object. It’s like a second name or entity that allows you to refer to an existing object. A reference is always bound to some object.

Now, let’s move on to detailed answers to the questions you asked earlier.

What does a reference do?

By declaring a reference, we create a new entity that allows operations to be performed on the original object. The reference itself doesn’t do anything. It’s only when we do something with it that we can see its purpose.

How do you use it?

Exactly like the object it’s bound to. For example:

#include <fmt/base.h>

auto main() -> int {
    auto  x   = 10;
    auto& ref = x;

    fmt::println("{} {}", x, ref);

    x = 15;

    fmt::println("{} {}", x, ref);

    ref = 20;

    fmt::println("{} {}", x, ref);
}

10 10
15 15
20 20

As you can see, trying to modify the reference to the variable x effectively modifies the value of x itself. Reading the value of the reference ref actually reads the value of the variable x.

Any operation on a reference results in that operation being performed on the object it’s bound to.

In memory, there’s only one int object in the above program — our x1. The reference itself is not stored anywhere.

Since any operation on a reference will be performed on the connected object, rather than on the reference itself, there’s no way to “rebind” a reference to another object:

1
2
3
4
5
6
7

auto main() -> int {
    auto  x   = 5;
    auto  y   = 10;
    auto& ref = x;

    ref = y;
}

The statement ref = y doesn’t “reset” the reference ref to be bound to the object y. Instead, it effectively overwrites the value of variable x with the value of variable y. It’s effectively the same as x = y.

What does it give us?

It offers us a way to access the original object using another entity.

Why would we want to use it?

Because we need it to solve the problem presented at the beginning of this section.

Let’s take another look at creating references:

1

auto& ref = x;

What happens here is that we create the entity ref, which gives us full access to the object x.

Let’s read that sentence again — slowly.

What happens here is that we create the entity ref, which gives us full access to the object x.

Now, let’s consider what would happen if ref were a function parameter and x were its argument:

#include <fmt/base.h>

// Change the parameter type from int to int&
auto modify(int& ref) -> void;

auto main() -> int {
    auto x = 5;
    modify(x);
    fmt::println("{}", x);
}

auto modify(int& ref) -> void {
    ref += 10;
}

In line 8, we call the function modify(). Its argument is the object x. This variable initializes the parameter ref, which is of type int&, a reference to an int.

Effectively, within the body of the modify() function, the parameter ref is a reference to some external variable, an object “from the outside”.

And since every operation performed on a reference results in that operation being performed on the object it’s bound to, the statement ref += 10 will result in modifying the value of the original variable x.

Thanks to references, we can write functions that modify the values of originally passed data.

What is the actual type of reference variable?

The answer to that question was partially provided in the code example from the previous subsection, but for completeness, let’s repeat it here. In the following example:

1
2
3
4

auto main() -> int {
    auto  x   = 5;
    auto& ref = x;
}

The type of the variable ref is int&, which means it’s a reference to an object of type int. You read it “from right to left”.

Back to functions

Let’s briefly return to functions. There are two more topics we need to discuss.

Function overloading

C++, like Java, supports function overloading. In both languages, we overload functions by creating another one with the same name but with a different number or types of parameters.

You cannot overload functions solely based on the return type. However, if you add a legal overload (with different parameters), you can change the return type in that overload.

In C++, you can overload non-static methods (functions within classes) not only based on different parameters, but we won’t delve into that topic just yet. This aspect will be covered in more detail when we discuss object-oriented programming.

Default arguments

Let’s say we want to write a function that can be called with one, two, three, or four arguments. For example, let’s say we’re displaying a vector and we want to offer the option to specify custom delimiter characters, a custom prefix, and a custom suffix.

For example, {fmt} by default displays a vector in the following format:

#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    fmt::println("{}", std::vector<int>{1, 2, 3});
}

Here, the prefix is [, the suffix is ], and the elements are separated by , (comma and space).

The goal is to write a function that allows convenient modification of these characters. For example, we might want to display @1 2 3# instead of [1, 2, 3].

Of course, we can achieve this using appropriate formatters and tools from {fmt}:

}

Default arguments are a small and simple element of the language, but a few rules regarding them must be remembered:

  • The list of parameters with default arguments must be at the end of the list of all parameters. You cannot add a parameter without a default value after a default argument.
  • Default arguments are specified after the = sign.
  • Default arguments are specified only in the function declaration. If we are simultaneously creating a declaration and definition (i.e., we have not created just a declaration without a body earlier), we can also specify them. However, if we have specified them in the declaration and have a separate declaration and definition, we do not repeat them in the definition.
