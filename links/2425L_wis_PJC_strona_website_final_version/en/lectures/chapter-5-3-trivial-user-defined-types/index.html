Chapter 5.3 - Trivial user-defined types

Posted Mar 30, 2025
By Filip Kwiatkowski
7 min read

User-defined typers

Creating custom types allows a programmer to precisely express intentions. Everything could be stored as int or std::string, but then the entire context of the program’s operation would have to actively exist in the programmer’s mind at all times. Types enable transferring some of this information from the mind to easily analyzable constructs in the code.

In the previous part of the chapter, we learned why we need enumeration types. Additionally, we saw that by using an enumeration type that doesn’t offer any other range of values than the built-in one (in that case — bool), we can also improve the readability (and sometimes safety) of our code.

Now we’ll learn how to create arbitrary (not just enumerative) user-defined types. We’ll be able to:

  • Instead of thinking about two std::strings and an age, think about a person (Person);
  • Instead of thinking about two ints, think about a point (Point);
  • Instead of thinking about a vector of double, two std::strings, and an int, you can think about a student with grades (Student).

And so on…

Creating a custom class

In C++, we have two keywords for creating something intuitively understood as a “class”. These are class and struct. Let’s look at two ways of defining classes:

1

class Point { };

1

struct Point { };

Both of these declarations are equivalent.

Of course, we can’t define a class (or anything else) twice, so we’ll place them in separate namespaces to make it easier to reason about their differences:

auto main() -> int {

p1 and p2 are clearly of different types, although their “representation” is identical — both are “empty”.

Such “empty” classes sometimes make sense, although not in this case — let’s add some fields to them:

The only difference between class and struct is that with class, everything is private by default, and with struct, everything is public by default.

That’s it. That’s the only difference.

namespace clazz {

    public:
        int x;

    struct Point {
    private:
        int x;
        int y;

auto main() -> int {
    auto p1 = clazz::Point();
    auto p2 = strukt::Point();

    p1.x = 1;
    p1.y = 2;

    p2.x = 1;
    p2.y = 2;
}

The problem remains the same, but now it concerns access to the .x and .y of the p2 object, not p1.

As you can also notice, unlike Java, in C++ we don’t use public or private for each field. These keywords introduce sections of elements that are public or private (there’s also protected, but we won’t talk much about it).

Why are there two keywords in C++? Which one should we use?

Great questions. The struct keyword must exist because the C++ language aims to be as backward-compatible with the C language as possible. This means that eventually all code written in C should be compilable (and behave the same) by a C++ compiler. It’s not 100% true, but ultimately this is the direction of C++ architecture. class was added so that programmers could more easily distinguish the idea of a “simple structure” from a “class in the object-oriented programming sense.” In the end, this distinction turned out to be unimportant. Unfortunately, we’re left with two keywords.

As for the second question, you can remember the following guideline:

If our type doesn’t represent some internal behavior (no limited invariants), it’s worth using struct. If the type has methods that maintain invariant behaviors, it’s worth using class.

The abstraction of a point in mathematics doesn’t impose any restrictions on coordinates, so it’s worth using struct.

Constructing objects of custom classes

In the previous example, we created objects p1 and p2, to which we then tried to assign coordinate values. However, there’s a simpler way to achieve this — we can use constructors.

The thing is, with such simple types, C++ doesn’t require us to define constructors. It allows us to initialize values in the same order as they were declared in the class:

#include <string>

struct Point {
    int x;
    int y;
};

struct Person {
    std::string name;
    std::string surname;
    int age;
};


auto main() -> int {
    auto point  = Point(3, 14);
    auto person = Person("Dio", "Brando", 121);
}

If point and person (or p1 and p2 from previous examples) were marked as const, the modification of their fields (.x and .y alongside .name, .surname, and .age) would obviously result in compilation errors. const object prevents others from modifying its fields.

Value semantics

It’s important to remember about value semantics in C++. We operate on objects, not references to them (as in Java). This means that the following code will display two different lines of text:

#include <fmt/base.h>

struct Point {
    int x;
    int y;
};


auto main() -> int {
    auto point1 = Point(3, 14);
    auto point2 = point1;

    point1.x = 1;
    point1.y = 61;

    fmt::println("{} {}", point1.x, point1.y);
    fmt::println("{} {}", point2.x, point2.y);
}

1
2

1 61
3 14

In the case of Java, however, two identical lines would be displayed.

In C++, point1 and point2 are completely separate objects. One is used to create the other, but after this construction, their relationship disappears. point2 is a completely independent copy. Therefore, changes made to it are not visible to the first object.

If we wanted to have a second reference to the same object, we would have to use references:

auto main() -> int {
    auto point1  = Point(3, 14);
    auto& point2 = point1;  // auto& vs auto

    point1.x = 1;
    point2.y = 61;

    fmt::println("{} {}", point1.x, point1.y);
    fmt::println("{} {}", point2.x, point2.y);
}
