Chapter 3.2 - Control elements for standard algorithms

Posted Mar 16, 2025
By Filip Kwiatkowski
8 min read

Changing the sorting rule for the sorting algorithm

I would like to use the std::ranges::sort() algorithm to sort a vector in descending order. Is it possible to do this, or is the only option to sort it and then use std::ranges::reverse()?

Certainly, there is a way to directly sort numbers (or elements of any other type) in descending order. This is done through the second argument of the std::ranges::sort() algorithm. It’s called a comparator.

A comparator is a tool that allows you to control the sorting rule of elements in algorithms.

The “standard” invocation of std::ranges::sort() looked like this so far:

#include <algorithm>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto numbers = std::vector<int>{3, 5, 1, 4, 2};
    std::ranges::sort(numbers);
    fmt::println("{}", numbers);
}

1

[1, 2, 3, 4, 5]

Let’s take a closer look at it:

1

std::ranges::sort(numbers);

At first glance, everything looks simple — we call the algorithm with one argument — the vector numbers.

That’s not entirely true. This algorithm actually takes more than one argument. For now, let’s assume that it actually takes two arguments, where the second one is optional. In that case, the “full” invocation would look like this:

1

std::ranges::sort(numbers, std::ranges::less());

std::ranges::less is a type whose variables act as comparators. In the above invocation, we pass as arguments:

  1. The vector numbers.
  2. A temporary object of type std::ranges::less. The empty parentheses are calling the default constructor. For example, like with auto text = std::string().

std::ranges::less represents the logic that corresponds to the less-than relationship (hence the name), i.e., the < operator. It’s the default comparator used in standard algorithms.

For simplicity, you can think of std::ranges::sort() as grouping elements in such a way that it places those matching the comparator’s logic at the beginning. For example, sorting with std::ranges::less will place smaller elements at the beginning.

The opposite of less is greater. The following code will sort the elements of the vector in descending order (because greater elements will come first):

#include <algorithm>
#include <functional>   // std::ranges::less 
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto numbers = std::vector<int>{3, 5, 1, 4, 2};
    std::ranges::sort(numbers, std::ranges::greater());
    fmt::println("{}", numbers);
}

1

[5, 4, 3, 2, 1]

Changing the sorting rule for text in the sorting algorithm

We already know that std::ranges::less and std::ranges::greater allow us to explicitly define the desired order of elements in sorting algorithms. But what about when we sort not std::vector<int> but, for example, std::vector<std::string>?

Actually, there’s nothing new here. We can still use the same approach:

#include <algorithm>
#include <functional>   // std::ranges::less 
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "hello", "there", "and", "welcome"
    };

    std::ranges::sort(words, std::ranges::greater());

    fmt::println("{}", words);
}

1

["welcome", "there", "hello", "and"]

As you can see, the stored strings have been sorted in lexicographically descending order, which means “reversed-alphabetically”.

Sorting text based on a different property

Now I’d like to sort strings in ascending order, but based on their length, not their alphabetical position. Is that possible?

Of course! This can be achieved by specifying a slightly more complex comparator, but we’ll get to that later. For now, we’ll achieve this goal in a simpler manner. Additionally, we’ll discover the whole truth about std::ranges::sort(), namely that it takes not two, but three arguments.

The first argument of the sorting algorithm is the range to be sorted. This can be a single object or a pair of iterators (then it’s the first and second argument). The next argument is the comparator, used to specify which object should be placed before which. The third is the projection, allowing us to look at the object through a different lens — from a different perspective.

What does it mean to “look at the object through a different lens”?

The easiest way to answer this question is by inspecting an example. The first projection we’ll learn about is std::ranges::size. This is a special function object that takes any argument and returns its size:

#include <ranges>   // std::ranges::size
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto const words    = std::vector<std::string>{"hey", "there"};
    auto const word     = std::string("Hello");
    auto const sentence = std::string("Hello There");

    fmt::println(
            "size of {} is {}\n"
            "size of \"{}\" is {}\n"
            "size of \"{}\" is {}\n"
            "size of \"{}\" is {}",
            words,          std::ranges::size(words),
            words.front(),  std::ranges::size(words.front()),
            word,           std::ranges::size(word),
            sentence,       std::ranges::size(sentence)
    );
}

In the end, it sounds very simple. It effectively calls .size() on the passed arguments1.

Since std::ranges::size() tells us how many elements a given object has / what its size is, we can use it as a projection in the sorting algorithm to sort strings from shortest to longest:

#include <algorithm>
#include <functional>   // std::ranges::less
#include <ranges>       // std::ranges::size
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "those", "are", "extremely",
            "random", "words", "in",
            "this", "particular", "example"
    };

    std::ranges::sort(words, std::ranges::less(), std::ranges::size);

    fmt::println("{}", words);
}

1

["in", "are", "this", "those", "words", "random", "example", "extremely", "particular"]

For a better understanding, let’s try to inspect every single part of this call:

1

std::ranges::sort(words, std::ranges::less(), std::ranges::size);

So:

  • std::ranges::sort — sort…
  • words — …the elements of the words vector…
  • std::ranges::less() — …placing the smallest elements first…
  • std::ranges::size — …but consider only their sizes — nothing else.

In practice, what happens is that the std::ranges::sort() algorithm, while sorting, takes two elements that it needs to arrange in some way, and passes them through a projection, in our case it obtains their sizes. Then it passes those results to the comparator, which (at this point, receiving only numbers — the sizes of the sorted std::string elements obtained through the projection) says that the smaller number should be placed first. The algorithm thus determines that the shorter of the strings must be placed at the beginning.

It sounds complicated.

But it’s not — really, just a bit of practice and everything will intuitively “click”.

Why do we use () with std::ranges::less, creating a temporary object, and not with std::ranges::size?

…A difficult question.

Formally, the answer is as follows:

std::ranges::less is a type (a class), so in order for the algorithm to use it, an object of that type must be created. std::ranges::size is already a (global) object (like std::cout or std::cin), so we use it directly.

Nevertheless, it’s a much more complex topic than it seems. If someone really wants to read further (which is not recommended unless someone already knows something about CPOs (Customization Point Objects) or niebloids, as this knowledge goes far beyond the scope of the discussion), they can start here.

So for now, we just have to accept that some “algorithms” or “functions” are sometimes used as types, where objects of those types need to be created, and sometimes as pre-defined objects. A bit more will be explained in the next chapter, where we’ll talk about lambdas.

Searching text based on another property

Just like std::ranges::sort(), many other algorithms we’ve learned about earlier support specifying a comparator and a projection. For instance, we can use std::ranges::max_element() to remove the largest element from the vector:

#include <algorithm>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto numbers = std::vector<int>{3, 5, 2, 4, 1};
    numbers.erase(std::ranges::max_element(numbers));
    fmt::println("{}", numbers);
}

#include <algorithm>
#include <functional>
#include <ranges>
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "short", "loooooooong", "medium"
    };


    auto const longestWordPosition = std::ranges::max_element(
            words, std::ranges::less(), std::ranges::size
    );
    words.erase(longestWordPosition);
    fmt::println("{}", words);
}

1

["short", "medium"]

The use of std::ranges::less() might be surprising here. What does std::ranges::max_element() have to do with std::ranges::less()?

The algorithm in question accepts any comparator. Perhaps we want to compare std::strings based on which one has more vowels? Maybe we want to use an even more complicated comparison?

That’s why this algorithm accepts both a comparator and a projection. All algorithms that need to compare elements in some way default to using std::ranges::less2. std::ranges::max_element() knows this — it simply remembers the element that std::ranges::less points out as not lesser.
