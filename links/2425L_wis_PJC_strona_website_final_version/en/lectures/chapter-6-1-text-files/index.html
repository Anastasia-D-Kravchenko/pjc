Chapter 6.1 - Text files

Posted Apr 7, 2025
By Filip Kwiatkowski
14 min read

std::fstream class

In C++, the standard way to interact with files is by using the std::fstream class. It allows reading from and writing to both text and binary files. For now, we will focus solely on text files.

To read from or write to a text file, you need to create objects of the std::fstream class and pass the appropriate path to it.

Objects of this class enable sort of a “connection” with a file. For example, if next to the application’s executable file we have a file named data.txt, creating an std::fstream object that connects to it might look like this:

1
2
3
4
5

#include <fstream>  // std::fstream

auto main() -> int {
    auto file = std::fstream("data.txt");
}

Let us now inspect reading from and writing to such a file.

Reading words from a file

To read data from a file, you need to have a place to store it. We typically store data in objects, which are usually represented as variables (or as parts of some collection).

From a text file, you can always read a std::string — after all, text files are nothing more than one big chunk of text. Of course, here we ignore cases where the file is corrupted or empty.

To read a std::string from a file, you first need to create an appropriate variable, and then use the same operations as with input-output streams, namely << and >>. In this case, we are interested in >>:

#include <fstream>
#include <string>

#include <fmt/base.h>

auto main() -> int {
    auto file = std::fstream("data.txt");
    auto word = std::string();
    file >> word;

    fmt::println("{}", word);
}

Assuming that the data.txt file looks like this:

1

Hello!

The above code will display the following output:

1

Hello!

Nothing surprising — the file contains a single fragment of text, which we read using the operation file >> word (just as if we were reading from std::cin), and then displayed it.

But what if there are multiple words in the file? Will such an operation read the entire file? Let’s check:

By word, we mean any sequence of non-whitespace characters separated by whitespace characters and / or the beginning / end of the file.

To read the second word, we just need to repeat the reading operation. Assuming the same content in the text file as before, the following code:

#include <fstream>

auto main() -> int {

As you can see, each subsequent >> operation reads each consecutive word. A common question in such cases is:

How does file know that this particular >> call should read the next data word?

Objects of type std::fstream “remember” where the last operation left off. Inside the file object, information is stored about where previous operations (in this case, the first file >> word) ended their execution.

Alright, but what if we don’t know how many words are in the file?

A very good question. In that case, we can still use a loop, but with a modified condition. Instead of iterating a specific number of times, we want to iterate as long as we can read a word from the file:

    auto word = std::string();

        fmt::println("{}", word);

The most crucial element of this code is placing the reading operation inside the loop condition. file >> word attempts to read a word. If it succeeds, file will be satisfied. If not (for example, if all the words have already been read), file will remember this and will indicate that nothing more can be read from it.

The operation file >> word formally returns a reference to its left argument. Hence, after the reading operation (>>), the while () loop receives a reference to file in its condition. When an object of type std::fstream is used in a context where a bool value is expected, it will generate true if everything is fine (the last operation, (e.g., reading a word), succeeded). However, if something went wrong (e.g., the last operation, (e.g., reading a word), didn’t read anything because, for instance, there are no more words in the file), it will generate false.

The paragraph above is a formal and somewhat complicated explanation of the following simplification:

while (file >> word) { } means execute the loop body as long as word can be read from file.

It’s worth noting that if we replace file with std::cin, we’ll be reading words from the user until the end-of-file signal is received.

Writing text to a file

Reading the contents of a text file certainly resembles reading data from the user. In both cases, we use the >> operator. We can apply the same analogy when writing text to a file and displaying it (using std::cout <<).

The following code, instead of reading from a file, will write several words to it. Let’s assume the file is initially empty:

Using {fmt} with std::fstream
Displaying a vector to the standard output using {fmt} is very simple:
  
1

fmt::println("{}", std::vector<int>{1, 2, 3});

Saving the textual representation of the same vector (i.e., what the above instruction would display, i.e., `[1, 2, 3]`) to a file with which we are connected through std::fstream is just as simple:
  
1

fmt::println(file, "{}", std::vector<int>{1, 2, 3});

As you can see, you just need to specify an additional argument at the very beginning — it represents the output stream to which {fmt} should send the formatted text.
The complete listing could look like this:

#include <fstream>
#include <vector>

#include <fmt/ostream.h>    // fmt::print() for std::fstream
#include <fmt/ranges.h>     // formatting ranges

auto main() -> int {
    auto file = std::fstream("data.txt");

    auto numbers = std::vector<int>{1, 2, 3};

    fmt::println(file, "{}", numbers);
}

It will result in the file being saved in the following state:
  
1
2

[1, 2, 3]


It’s worth noting two important facts:
  1. At the end of the file, there is an empty line. This is because fmt::println() wrote <raw-data>[1, 2, 3]</raw-data> to the file and then “added” a newline character. Thus, an empty line appeared as line number 2.
  2. In none of the listings presented in this chapter did we close the file. This is because although std::fstream offers the .close() method, it’s not necessary to use it unless we have a specific reason to close the file earlier than when the object finishes its life cycle. This is possible due to destructors, which will be discussed later in the course. For now, just remember that we don’t need to manually close files in C++.
We shouldn’t manually close files (objects of type std::fstream) in C++, unless we have a very good reason to do so (e.g., wanting to use the same object to open another file).
The next topic to discuss is multiple writes to a file. By this, we mean the reverse situation to reading from a file multiple times. In the latter case, std::fstream “remembered” where we left off reading. How does this work when writing to a file? Let’s examine a few examples.

#include <fstream>

#include <fmt/ostream.h>

auto main() -> int {
    auto file = std::fstream("data.txt");

    fmt::print(file, "{}", "Hello ");
    fmt::print(file, "{}", "There");

What will happen when we run such code?
Surprisingly, the file will look like this:
  
1

Hello Therext in this file.

The saved text Hello There replaced the first characters in the file. We probably expected something else, such as:
  • Appending text to the end of the file.
  • Replacing the entire contents of the file with new text, i.e., clearing its contents and starting to write elements using fmt::print().
But that’s not what happened. By default, std::fstream starts reading and writing from the same position — the beginning of the file.
We can change this by specifying different arguments to the constructor. These are specified using values of std::ios::openmode.
Flags of std::ios::openmode
When we create an std::fstream object like this:
  
1

auto file = std::fstream("data.txt");

This is equivalent to creating it like this:
  
1

auto file = std::fstream("data.txt", std::ios::in | std::ios::out);

That’s because the std::fstream constructor uses a default argument that looks like the one presented above.
std::ios::in and std::ios::out are self-explanatory — the first represents a mode supporting reading from the file (input), and the second represents writing to the file (output). By combining them using bitwise OR (a kind of concatenation of bitwise flags — |), we get an object that allows both reading and writing simultaneously.
To achieve any of the alternative behaviors mentioned earlier for writing to a file, simply provide the appropriate combination of flags:
  
1

There is text in this file.

#include <fstream>

#include <fmt/ostream.h>

auto main() -> int {
    auto file = std::fstream("data.txt", std::ios::out | std::ios::trunc);

    fmt::print(file, "{}", "Hello ");
    fmt::print(file, "{}", "There");
}

  
1

Hello There

As you can see, combining std::ios::out with std::ios::trunc allowed us to delete the original contents of the file and replace it with what was sent to the file during the program’s execution.
