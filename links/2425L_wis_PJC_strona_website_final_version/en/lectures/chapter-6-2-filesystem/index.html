Working with multiple files simultaneously

We already know how to open a single text file. However, we don’t know what to do when there are multiple files. Potentially, an unknown number of them. In such a situation, tools from the std::filesystem namespace will help us.

Let’s start by checking if the file input.txt is located right next to the executable program file:

As you can see, while writing this chapter, in the test environment, there was no input.txt file right next to the executable program file. Let’s check what files are there.

Before we do that, it’s worth noting that continually writing std::filesystem (specifying the full namespace and namespace subcomponents) is quite tedious. In the examples, we’ll use the following namespace alias:

auto main() -> int {
    namespace fs = std::filesystem;

    auto const path = fs::path("input.txt");

    fmt::println("{}", fs::exists(path));
}

It’s worth using local namespace aliases to reduce code verbosity and the number of details. It’s important to remember to keep these aliases local. This is because in larger code fragments (e.g., a global alias in a large file), such an alias can lead to undesired effects (e.g., it may become unclear exactly which elements we are using — especially when using multiple aliases simultaneously).

Now let’s get back to checking what files are in the folder where our application is located. We’ll use two tools for this:

  • A relative path representing the location where the program is called, which is ".".
  • An iterator traversing the elements of the folder, which is std::filesystem::directory_iterator.

#include <filesystem>

#include <fmt/std.h>    // printing filesystem objects

auto main() -> int {
    namespace fs = std::filesystem;

    auto const path = fs::path(".");

    for (auto const& entry : fs::directory_iterator(path)) {
        fmt::println("{}", entry.path().filename());
    }
}

It’s worth noting that .cmake, _deps, CMakeFiles, and Testing are directories, not “classic” files. A file entry in the file system can be both a “classic” file and a directory.

The std::filesystem namespace contains many helpful tools for analyzing files. Pay attention to:

  • std::filesystem::exists(), which checks if there is a file or folder at the given path;
  • std::filesystem::file_size(), which returns the number of bytes occupied by the file (may not work when passing a path to a folder);
  • std::filesystem::remove() and std::filesystem::remove_all(), which delete a file or folder at the specified path;
  • std::filesystem::rename(), which renames a file or folder;
  • std::filesystem::copy() and std::filesystem::copy_file(), which copy folders or files;
  • std::filesystem::create_directory() and std::filesystem::create_directories(), which create folders.

All of the above tools are functions that take a path or paths to files as arguments.

A slightly more powerful type than std::filesystem::directory_iterator also deserves special attention. We mean std::filesystem::recursive_directory_iterator.

It’s used for iterating over entries, but with the difference that it will also visit the entire contents of subfolders — recursively. If we had used it instead of the non-recursive version in the previous listing, the contents of the .cmake, _deps, CMakeFiles, and Testing folders would also have been displayed.

#include <filesystem>
#include <fstream>
#include <string>

#include <fmt/base.h>

auto numberOfLines(std::filesystem::path const& path) -> int;

auto main() -> int {
    namespace fs = std::filesystem;
    auto nameOfFileWithMostLines = std::string();
    auto mostLinesInFile         = 0;

    for (auto const& entry : fs::directory_iterator(".")) {
        if (fs::is_regular_file(entry)) {
            auto const path = entry.path();
            auto const linesInThisFile = numberOfLines(path);
            if (linesInThisFile > mostLinesInFile) {
                mostLinesInFile = linesInThisFile;
                auto const thisFileName = entry.path().filename().string();
                nameOfFileWithMostLines = thisFileName;
            }
        }
    }

    fmt::println(
            "File with most lines is \"{}\" and it contains {} lines",
            nameOfFileWithMostLines, mostLinesInFile
    );
}

auto numberOfLines(std::filesystem::path const& path) -> int {
    auto file = std::fstream(path);
    auto line = std::string();

    auto lineCount = 0;

    while (std::getline(file, line)) lineCount += 1;

    return lineCount;
}

The entire algorithm is straightforward, but it’s worth discussing its individual parts:

  1. First, we create variables nameOfFileWithMostLines and mostLinesInFile, which will represent the details of the file with the most lines at the end of the program’s execution. These details are, of course, the filename and the number of lines. During the algorithm’s execution, these variables will be overwritten accordingly.
  2. Using a loop iterating over all entries retrieved by std::filesystem::directory_iterator (from the path representing the location where the application is executed — you can always pass a path to another folder instead of "."), we check if we need to change the values of nameOfFileWithMostLines and mostLinesInFile. The logic consists of the following parts:
    • If the current entry is not a regular file (e.g., a folder), we do nothing. However, if it is a regular file, we proceed with further instructions.
    • We calculate the number of lines in the current file using the logic contained in the numberOfLines() function. This function creates a local std::fstream object and uses it (along with a while () loop and the std::getline() function) to return the number of lines in the file at the given path.
    • If the calculated number of lines is greater than the largest encountered so far, we remember this information by overwriting the previously mentioned variables nameOfFileWithMostLines and mostLinesInFile.
