Chapter 1.6 - Summary and extras

Posted Feb 25, 2025
By Filip Kwiatkowski
8 min read

At the end of each chapter, there will be a summary section covering the material along with some additional notes. Here’s the first one1.

Input and output in C++

Outputting is done via the std::cout object, while inputting is done via std::cin. They live in the <iostream> header (input-output stream).

Control flow

Most control flow operations are shared between Java and C++. An important exception is return, the absence of which won’t result in a compilation error, but if it’s missing in a function other than main() and other than one that returns void, we invoke Undefined Behavior (UB).

Undefined Behavior

Undefined Behavior (UB) is behavior that can manifest literally in any way. It should be avoided at all costs and is usually the result of breaking some significant programming rules of C++.

Almost-always-auto and the old style

The C++ language is changing, and with this change, in the PJC course we adopt a style that prefers the use of auto. It brings the following advantages:

  • Safety by avoiding errors related to uninitialized variables.
  • Saving on typing when specifying long type names (auto i = vec.begin() vs std::vector<T>::iterator i = vec.begin()2).
  • Uniform syntax for defining functions and lambdas (which will be introduced later).
  • A more “mathematical” notation of functions (\(Input \rightarrow Output\)).
  • Sometimes it makes it easier for us to write optimized code for performance reasons, both at runtime and compile time.

It is worth remembering that function arguments, while they can be marked as auto, should be annotated with types in the “classic” way. This is because auto in a function parameter changes its meaning — there it means that the function accepts an argument of any type, and that’s not always what we want.

Preprocessor directives

The #include directive is a preprocessor directive. In the compilation process, one of the first phases is the preprocessor phase. Then, appropriate directives are replaced with textual replacements. #include literally fetches the content of the specified file in angle brackets (e.g., <vector>) and pastes its content in place of the directive.

Another directive is, for example, #define, which allows text replacements in the code. For example, the following code will display the string “Hello World”:

Collection and container terminology

In Java, types that store multiple elements (e.g., List or Set) are called collections. This terminology is also used in many other languages. In C++, it is customary to refer to such types as containers. Strict adherence to this nomenclature is not particularly important.

All containers in C++ support .size()

In Java, you can notice that arrays have .length, Strings have .length(), and the rest of the collections have .size(). In C++, .size() is used everywhere.

Notation and terminology of methods and functions

A function is a named piece of code that takes some (potentially empty) list of parameters and returns some value (or none, in the case of void).

A method is a function that is part of a class. A function that is not a method is called a free function. Generally speaking, when we say “function”, we mean both free functions and methods. The formal English term for a method in C++ is member function.

An argument is something that we send to a function or method.

A parameter is a variable initialized by an argument — it appears in the function signature.

For example:

  • the argument passed to freeFunction() in line 5 is called value.

Additional container methods

Selected popular methods belonging to containers are:

  • .clear(), which removes all elements from the container. After calling it, the .size() of this container is 0.
  • .empty(), which returns true if the container on which it is called is empty.

Values returned by standard algorithms

Algorithms do not return new, modified collections; they modify the original ones. This applies to algorithms like std::ranges::sort() or std::ranges::reverse(). In such cases (and for the time being), we are not interested in the values returned by them.

Of course, a completely different situation arises with algorithms like std::ranges::equal(), which produce results that interest us.

Old and new algorithms

The vast majority of standard algorithms have versions without ranges. For example:

New VersionOld Version
std::ranges::sort()std::sort()
std::ranges::reverse()std::reverse()
std::ranges::equal()std::equal()

Old versions not only do not support passing entire ranges (you always have to write .begin() and .end()), but they also do not support additional control operations for algorithms, namely projections (and some comparators behave differently). Therefore, they are incompatible with the knowledge presented in the chapter. They should never be used if there is a version with ranges (some algorithms do not have a ranges version, e.g., std::accumulate()).

Displaying an arbitrary range

Do I really have to use loops to display the entire std::vector? In Java, List has .toString(), and for arrays, there is Arrays.toString(). Can’t we achieve the same in C++ more easily?

Yes and no.

Standard C++ before C++23 (not sufficiently supported anywhere) does not offer a convenient way to display entire containers in an easy way. Among other reasons, this is why we will quickly say goodbye to std::cout and start using an external library, thanks to which this process will be much more enjoyable.

#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

auto main() -> int {
    using namespace std;    // using directive

    auto vec = vector<string>{"programming", "in", "c++"};

    ranges::sort(vec);

    for (auto element : vec) {
        cout << element << ' ';
    }
}

So by adding a new line (using namespace std;), we get rid of the need to write std::. The same can be applied to std::ranges and other nested namespaces3.

However, one should be very cautious and not overuse the using directive. Abusing it can lead to many difficult-to-identify errors45. Therefore, the general suggestion is as follows — it can be used within shorter functions, and if you want to use it globally in a file, you should use a namespace alias, provided that it is a .cpp file. In other types of files (which will be discussed later), never use global using or global namespace aliases.

#include <algorithm>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2, 0};

    namespace rng = std::ranges;    // namespace alias for std::ranges

    rng::sort(vec.begin(), vec.begin() + vec.size() / 2);
    rng::reverse(vec.begin() + vec.size() / 2, vec.end());

    for (auto element : vec) {
        std::cout << element << ' ';
    }
}

Beware of new

In Java, we often used the new keyword. It was used to create objects. In C++, this keyword also exists, but it should not be used until pointers have been mastered. That is, for a long time.

We use standard algorithms whenever we can

In PJC, we will focus on understanding the mechanisms and architecture of languages and standard libraries. Therefore, to produce the best code, you should always consider using standard algorithms. You should have a good understanding of how these algorithms work and why sometimes it’s worth preferring one over the other, but this analysis will be presented in the ASD course. In PJC, we learn how to use them, not implement them from scratch.

Keyword const

The const keyword modifies any type (e.g., turning int into int const or std::string into std::string const) so that an object with the resulting type cannot be modified. Due to the safety (and sometimes correctness) it provides, it is assumed that const should be used by default.

If a C++ programmer sees that const is used, they won’t think much of it. However, if they come across its absence, a “yellow flag” usually goes up, and they think, “Why isn’t there a const here? Was this intentional? Should I expect modifications?”
