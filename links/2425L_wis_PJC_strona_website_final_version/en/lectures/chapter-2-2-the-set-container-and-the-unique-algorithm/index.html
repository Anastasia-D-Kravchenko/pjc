Chapter 2.2 - std::set container and the std::ranges::unique() algorithm

Storing unique values

Sometimes, we’re interested in functionality that allows us to store data without duplicates. For example, we’re storing data about student names and want to see how many different names we have. Naturally, there’s a high chance that some students share the same name, so we need to somehow filter out duplicates.

One way to achieve this is by using the std::set container.

std::set is a container that does not allow duplicates.

An example of using std::set is creating the container, adding elements to it, and then displaying its contents:

#include <algorithm>
#include <iostream>
#include <set>

auto main() -> int {
    auto set = std::set<int>();

    for (auto newItem : {3, 2, 1, 1, 2, 3, 5, 4, 3, 2, 1}) {
        set.insert(newItem);
    }

    for (auto element : set) {
        std::cout << element << ' ';
    }
}

As you can see, even when adding many identical elements to std::set, the container does not allow duplicates.

Moreover, it’s worth noting that the order of elements has been changed, and it doesn’t match the order in which we added numbers to the set.

std::set stores its elements in sorted order and does not allow duplicates.

There are two more things in the code listing that are worth noting:

  1. To use std::set, you need to include the appropriate header, i.e., #include <set>.
  2. Adding new elements to the created object is done in an interesting way — the range-based for loop iterates over elements in curly braces (line number 8). This is called an initializer list (std::initializer_list), but you don’t need to focus on that too much. It’s just one way to conveniently construct elements. However, it’s important to know that when we place elements directly into the container using curly braces, as shown with std::vector, we are also using this feature of the language.

Instead of using a loop with an initializer list, you can directly use it during the container initialization:

#include <algorithm>

auto main() -> int {

    for (auto element : set) {
        std::cout << element << ' ';

The effect will be the same (displaying the sequence 1 2 3 4 5).

Obtaining unique elements from a set of data with duplicates

std::set does not store duplicates. But what if we have some other set of data (e.g., std::vector) with duplicates, and we want to know how many unique values are in it?

Effectively, there are two simple ways to achieve this — removing duplicates from the original set or creating a separate container that won’t contain duplicates.

The second method will be simpler (although not optimal), so let’s start with it.

Using std::set to remove duplicates

#include <algorithm>
#include <iostream>
#include <set>
#include <string>
#include <vector>

auto main() -> int {
    auto names = std::vector<std::string>{
            "Jonathan", "Joseph", "Jotaro",
            "Josuke", "Giorno", "Jolyne",
            "Jonathan", "Josuke"
    };

    auto uniqueNames = std::set<std::string>();

    for (auto name : names) {
        uniqueNames.insert(name);
    }

    for (auto name : uniqueNames) {
        std::cout << name << ' ';
    }
}

As we can see, thanks to std::set, we found out that we only have 6 unique names.

Range constructor

However, there is a more concise form of the code presented in the previous listing. You can use a range constructor, which takes a pair of iterators to the range from which elements will be copied. This allows you to create a std::set based on a std::vector without explicitly using a loop:

#include <algorithm>
#include <iostream>
#include <set>
#include <string>
#include <vector>

auto main() -> int {
    auto names = std::vector<std::string>{
            "Jonathan", "Joseph", "Jotaro",
            "Josuke", "Giorno", "Jolyne",
            "Jonathan", "Josuke"
    };

    auto uniqueNames = std::set<std::string>(names.begin(), names.end());

    for (auto name : uniqueNames) {
        std::cout << name << ' ';
    }
}

The result of this code is identical (i.e., displaying the text Giorno Jolyne Jonathan Joseph Josuke Jotaro).

Every container provides a range constructor, which allows you to create a data range based on another one.

For example, you can overwrite such a vector containing duplicates with a new vector created based on the set without duplicates:

#include <algorithm>
#include <set>
#include <string>
#include <vector>

auto main() -> int {
    auto names = std::vector<std::string>{
            "Jonathan", "Joseph", "Jotaro",
            "Josuke", "Giorno", "Jolyne",
            "Jonathan", "Josuke"
    };

    auto uniqueNames = std::set<std::string>(
            names.begin(), names.end()
    );

    names = std::vector<std::string>(
            uniqueNames.begin(), uniqueNames.end()
    );
}

This way, only unique names remain in the original vector. There are no duplicates in it.

However, from a performance perspective, this solution is of average quality. It’s certainly relatively simple, but it’s worth examining what exactly we’re doing just to remove duplicates from a set:

  1. We create a new container (uniqueNames of type std::set).
  2. We copy elements from the original vector into it (i.e., names, which stores objects of type std::string, which in turn can be very long, making their copying time-consuming and requiring allocation of a large amount of additional memory).
  3. We create a new vector, into which we again copy elements (from uniqueNames).
  4. We overwrite the original vector with the new one.

That’s… definitely a lot of work just to remove duplicates from the original container. Surely there must be an alternative, more efficient way.

Fortunately, there is one — it uses the std::ranges::unique() algorithm.

Removing duplicates from the original range using std::ranges::unique()

In an ideal world, std::ranges::unique() could simply efficiently remove duplicates from the provided range. However, this is not possible1.

However, delving into why this algorithm was designed this way could take up to a quarter of an ASD lecture2. Therefore, we won’t focus on the reasons, but only on how it works.

To summarize the algorithm’s operation:

The std::ranges::unique() algorithm moves duplicates from neighboring groups of identical elements to the end of the specified range.

This information doesn’t provide much insight into intuitively understanding how the algorithm works, so let’s move straight to practical examples. The simplest one would be to execute this algorithm on a vector containing several identical elements:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>(5, 1);

    std::ranges::unique(numbers);

    for (auto element : numbers) {
        std::cout << element << ' ';
    }
}

When running the above code, we’ll notice that something is definitely wrong. The outcome is not guaranteed (although there’s no UB mentioned), but typically the code above displays 1 1 1 1 1.

Before we find out why std::ranges::unique() didn’t work didn’t do what we expected, let’s take a look at line 6 from the above listing. It’s worth noting that the vector construction uses (5, 1) syntax, not {5, 1} (i.e., we use parentheses instead of braces). The behavior {5, 1} is familiar to us — it would create a vector with two elements: five and one. However, the (5, 1) behavior is different (hence the need to pay attention to parentheses). It is a call to a two-argument constructor, which initializes the vector with five ones.

When initializing a vector with several identical elements, consider using an alternative constructor. Instead of using std::vector<int>{1, 1, 1, 1, 1}, you can use std::vector<int>(5, 1). Some selected containers also provide this functionality (such as std::string, but not std::set).

However, let’s get back to the std::ranges::unique() algorithm. What did it do? Why didn’t it remove duplicates?

First and foremost, it’s important to remember that this algorithm doesn’t remove duplicates. It moves them to the end of the specified range. So, with a vector like {1, 1, 1, 1, 1}, the algorithm “sees” the first one and the remaining four, and then moves those four ones to the end — i.e., to their original positions. It didn’t do anything.

This sounds completely nonsensical. So, how do we use this algorithm correctly?

By removing all elements that it marked as duplicates.

Okay, but how do we know which elements are marked as duplicates? How do we remove them afterward?

By capturing the return value of the algorithm. It returns a subrange — an object representing a view of a portion of the originally passed range. This subrange contains duplicates that need to be removed.

#include <algorithm>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>(5, 1);

    auto duplicates = std::ranges::unique(numbers);
}

duplicates is a view of the last four elements of numbers3. This is because numbers contains five identical elements. Therefore, it has four duplicates to remove.

Fantastic. So, how do we remove elements from numbers referred to by duplicates?

By using the .erase() method. This method takes an iterator (or a pair of iterators) to the elements we want to remove. The following listing illustrates this:

#include <iostream>

auto main() -> int {
    auto numbers = std::vector<int>{1, 2, 3, 4, 5, 6, 7};

    for (auto element : numbers) std::cout << element << ' ';
    std::cout << '\n';

    numbers.erase(numbers.begin()); // removing first element

    for (auto element : numbers) std::cout << element << ' ';
    std::cout << '\n';

    numbers.erase(numbers.end() - 1); // removing last element

    for (auto element : numbers) std::cout << element << ' ';
    std::cout << '\n';

    numbers.erase(numbers.begin() + 1, numbers.begin() + 3);
    
    for (auto element : numbers) std::cout << element << ' ';
}

The most interesting part is the .erase() method call in line 20. The rest of the calls should behave intuitively.

The mentioned call operates on a vector containing the following elements: 2 3 4 5 6. Therefore, numbers.begin() + 1 points to the number 3 in the vector. numbers.begin() + 3 points to the number 5. .erase(), like any algorithm in C++, works on a right-open range, so it will remove all elements from 3 to 5 (inclusive of 3 but excluding 5).

As we can see, the .erase() method allows for the removal of elements from any position in the vector (unlike the .pop_back() method we learned earlier, which only removes the last element). Its counterpart is the .insert() method, which allows for adding elements at any position in the container.

Armed with this knowledge, we now know how to remove multiple elements at once from a vector. Now, all we need to do is obtain iterators to the elements covered by the duplicates view. This is very simple because the object returned by the std::ranges::unique() algorithm has .begin() and .end() methods, which return iterators pointing to the elements of the original range that were affected by the call to the algorithm:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>(5, 1);

    auto duplicates = std::ranges::unique(numbers);

    numbers.erase(duplicates.begin(), duplicates.end());

    for (auto element : numbers) {
        std::cout << element << ' ';
    }
}

Success. std::ranges::unique() moved all duplicates to the end of the range, returning an object telling us exactly where they are. We used it with the .erase() method to remove the mentioned duplicates.

It might seem like that’s all, but unfortunately, it’s not. Let’s look at the following code example:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>{1, 2, 3, 1, 2, 3, 1, 2, 3};

    auto duplicates = std::ranges::unique(numbers);

    numbers.erase(duplicates.begin(), duplicates.end());

    for (auto element : numbers) {
        std::cout << element << ' ';
    }
}

1

1 2 3 1 2 3 1 2 3

It seems like the algorithm didn’t do anything. Effectively, this is true. It saw that there are no neighboring duplicates, so it didn’t move anything to the end. The returned duplicates object consists of two identical iterators pointing to numbers.end(). Calling numbers.erase(numbers.end(), numbers.end()) (or numbers.erase(x, y), where x and y are iterators pointing to the same element) won’t do anything (because the algorithm doesn’t touch the element pointed to by the second iterator — it doesn’t matter that the first one also points to it).

For clarification, let’s revisit the algorithm’s description:

The std::ranges::unique() algorithm moves duplicates from neighboring groups of identical elements to the end of the specified range.

What now? How do we make the algorithm do what we intuitively expect, i.e., remove duplicates regardless of their positions?

Answering this question literally — you can’t.

However, don’t lose hope. It’s not that std::ranges::unique() won’t help us. It will, but you need to prepare the data properly. You need to prepare them in such a way that all identical elements are next to each other. In the case of the numbers vector from the previous listing, you need to ensure that all ones are next to each other, all twos are next to each other, and all threes are next to each other.

It turns out that the simplest way to achieve this effect is by sorting the data4:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>{1, 2, 3, 1, 2, 3, 1, 2, 3};

    std::ranges::sort(numbers);
    auto duplicates = std::ranges::unique(numbers);

    numbers.erase(duplicates.begin(), duplicates.end());

    for (auto element : numbers) {
        std::cout << element << ' ';
    }
}

Success! Moreover, full success. Sorting the data before using the std::ranges::unique() algorithm is a very popular operation. Typically, you need to sort the data, use the std::ranges::unique() algorithm, and then use the .erase() method to actually remove the duplicates.

As you can see, sorting the data and using the std::ranges::unique() algorithm is undoubtedly more complicated than using the std::set container. However, in terms of performance, the approach using the container is usually worse. Therefore, it’s valuable to know both ways to achieve the desired goal.
