Chapter 10.2 - Pointer arithmetic

Posted May 20, 2025
By Filip Kwiatkowski
5 min read

Using a pointer as an iterator

An iterator, in short, is an object that supports access to data via the * operator. Similarly, a pointer to an individual element works.

An interesting case of an iterator is the one from std::vector — it not only allows for the aforementioned dereferencing (*), but also for movement, using operators like ++, --, +=, and -=. Interestingly, a pointer to an element in an array also does this. This means that a pointer supports the same operations as an iterator from std::vector.

A pointer is an iterator. Calculating a new address through arithmetic operations on a pointer (such as ++ or +=) is called pointer arithmetic.

It’s worth examining what addresses are calculated during pointer arithmetic. However, before we move on to such examples, it’s important to note that these results may differ between different runs of the program. Let’s see:

auto main() -> int {

    fmt::println("{}", fmt::ptr(pointer));

#include <vector>

#include <fmt/format.h>

auto main() -> int {
    using fmt::ptr;

    auto const ints = std::vector<int>{5, 2, 8};

    auto const pointerToFirst  = &ints[0];    // notice the `&`
    auto const pointerToSecond = &ints[1];    // notice the `&`

    fmt::println("{}", ptr(pointerToFirst));
    fmt::println("{}", ptr(pointerToSecond));
}

0x1f2abe61ab0
0x1f2abe61ab4

As it can be observed, these addresses differ only by a value of 4. When running this program a few more times, the result may change, of course (as the vector will allocate its elements elsewhere), but it will certainly remain true that the difference in bytes between these addresses will be exactly 41.

Thus, it follows that an int occupies 4 bytes, but is analyzing addresses the only way to find out how much memory a given data type occupies?

No, it’s not the only way. A better way would be to use the sizeof() operator:

#include <fmt/base.h>

auto main() -> int {
    fmt::println("bool\toccupies {} byte(s)", sizeof(bool));
    fmt::println("char\toccupies {} byte(s)", sizeof(char));
    fmt::println("short\toccupies {} byte(s)", sizeof(short));
    fmt::println("int\toccupies {} byte(s)", sizeof(int));
    fmt::println("float\toccupies {} byte(s)", sizeof(float));
    fmt::println("double\toccupies {} byte(s)", sizeof(double));
}

However, such “manual” analysis was not unfounded — we ensured that the data in std::vector are laid out consecutively in memory.

Returning to pointer arithmetic, the aforementioned vector can be displayed using a pointer that sequentially points to each element of this container:

#include <vector>

#include <fmt/format.h>

auto main() -> int {
    auto const ints = std::vector<int>{5, 2, 8};

    auto pointer = &ints[0];

    fmt::print("{} ", *pointer);
    ++pointer;
    fmt::print("{} ", *pointer);
    ++pointer;
    fmt::print("{} ", *pointer);
}

To obtain a pointer to the internal array of elements allocated by the vector, one can use .data() instead of retrieving the address of the first element obtained through the indexing operator:

#include <vector>

#include <fmt/format.h>

auto main() -> int {
auto const ints = std::vector<int>{5, 2, 8};

    auto pointer = ints.data(); // change

    fmt::print("{} ", *pointer);
    ++pointer;
    fmt::print("{} ", *pointer);
    ++pointer;
    fmt::print("{} ", *pointer);
}

Pointers support not only ++, but also + by itself, which means that it’s easy to calculate a pointer to a more distant element. This allows us to immediately calculate a pointer to a non-existent element representing the end of the vector sequence, which in turn allows us to iterate through this container with a loop like this:

#include <vector>

#include <fmt/format.h>

auto main() -> int {
    auto const ints = std::vector<int>{5, 2, 8};

    for (auto pointer = ints.data();
         pointer != ints.data() + ints.size();
         ++pointer
    ) {
        fmt::print("{} ", *pointer);
    }
}

It closely resembles a loop using iterators from a vector:

#include <vector>

#include <fmt/format.h>

auto main() -> int {
    auto const ints = std::vector<int>{5, 2, 8};

    for (auto iterator = ints.begin();
         iterator != ints.end();
         ++iterator
    ) {
        fmt::print("{} ", *iterator);
    }
}

That’s because a pointer fulfills all the requirements of an iterator for the std::vector template. Moreover, some implementations of the C++ standard library use raw pointers as vectors’ iterators!

Does this mean that calling .begin() on — for example — std::vector<int> might simply return an int*?

Exactly! After all, a pointer is a legal iterator.

  1. This assumes, of course, that an int occupies 4 bytes. It is almost always the case, but formally an int could occupy a different number of bytes. Similarly, formally a byte doesn’t necessarily have to be 8 bits, but effectively, it doesn’t matter much. ↩
