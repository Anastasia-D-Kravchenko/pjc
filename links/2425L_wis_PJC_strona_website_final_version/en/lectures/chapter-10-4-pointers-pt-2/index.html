Pointers

Pointers introduce a lot of syntactic complexities. Is the fact that they are required for dynamic memory allocation the only reason they are used?

No. Pointers allow for a bit more. For example, they enable referencing multiple different objects during their lifetime.

One pointer referring to multiple objects

Pointers can be reassigned to point to different data during their lifetime. This couldn’t be achieved with references:

#include <fmt/base.h>

auto main() -> int {
    auto x   = 10;
    auto y   = 20;
    auto ptr = &x;
    fmt::println("{}", *ptr);
    ptr = &y;
    fmt::println("{}", *ptr);

    *ptr /= 10;
    ptr = &x;
    *ptr /= 10;

    fmt::println("{} {}", x, y);
}

In the above example, we have two ints — x and y. Using a single pointer ptr, we display the values of both these ints. We achieve this by assigning the memory address of the x object to ptr (using ptr = &x) and later by assigning the memory address of the y object to ptr (using ptr = &y).

The syntax of using pointers is undoubtedly quite complicated, so let’s examine seemingly similar examples and explain the differences between them.

Here’s how overwriting the pointer itself looks like:
1

ptr = ...;
Here’s how overwriting the object to which the pointer points to looks like:
1

*ptr = ...;

If we overwrite the pointer itself, we change the memory address it holds. Then it points to a different object.

For example, examining the contents of our program’s memory after executing the following operations:

However, if we overwrite the object pointed to by the pointer, the address stored by the pointer does not change. Only the contents of the object being pointed to change.

Let’s consider such an example:

auto main() -> int {
    auto x   = 10;
    auto ptr = &x;
    *ptr = 20;
}

Then, the operation *ptr = 20 will make the memory look like this:

Pointers vs. references
