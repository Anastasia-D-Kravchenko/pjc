Rozdział 1.3 - Kontenery std::string i std::vector

Kontener std::string

Jednym z najpopularniejszych typów danych w programowaniu jest typ przechowujący tekst. Javowy String ma swój odpowiednik w C++ w postaci klasy std::string. Obydwie te klasy służą do przechowywania i modyfikowania tekstu.

Różnica, która najbardziej rzuca się w oczy między String (Java) a std::string (C++), polega na dostępie do ich elementów (poszczególnych znaków) i możliwości ich modyfikacji.

W Javie dostęp do znaków odbywa się przy pomocy metody .charAt(). Nie ma możliwości zmiany przechowywanego tekstu — trzeba do tego stworzyć nowy String.

Operacje na tekście w C++ bardzo przypominają operacje na wygodnych tablicach znaków. Nie dość, że dostęp do danego znaku odbywa się przy pomocy indeksowania (jak przy tablicy — za pomocą []), to dodatkowo można zmieniać zawartości obiektów typu std::string bez potrzeby tworzenia nowych.

Od razu można zauważyć trzy, bardzo istotne fakty dotyczące używania obiektów tekstowych w C++:

  1. Wszystkie powyższe fragmenty kodu wprowadzają nową linijkę z instrukcją #include <string>. Instrukcja ta, tak samo jak #include <iostream>, jest dyrektywą preprocesora, która wkleja zawartość nagłówka <string> do naszego pliku z kodem.
  2. Obiekt typu std::string można indeksować tak, jak tablice. “Klasyczna” pętla for () dodatkowo obrazuje, że std::string (jak i każdy kontener w bibliotece standardowej C++) udostępnia metodę .size(), która mówi, ile elementów znajduje się w danym obiekcie.
  3. std::string (jak i każdy kontener w bibliotece standardowej C++) wspiera iterowanie po nim przy użyciu pętli zakresowej for ().

Powyższe przykłady zobrazowały jedynie sposoby na wyświetlanie tekstu. A co z jego modyfikacją?

#include <iostream>

auto main() -> int {
    auto text = std::string("Programming in C++");

    auto firstIndex = 0;
    auto lastIndex  = text.size() - 1;

    text[firstIndex] = 'p';
    text[lastIndex]  = '!';

    std::cout << text;
}

Wynikiem uruchomienia tego kodu jest wyświetlenie tekstu programming in C+!.

Okazuje się, że chcąc się dostać do pojedynczych elementów kolekcji, najczęściej interesuje programistę właśnie pierwszy i ostatni z nich. Dlatego wybrane kontenery z C++ (w tym std::string) udostępniają dodatkowe, dedykowane metody do właśnie tych operacji:

#include <iostream>
#include <string>

auto main() -> int {
    auto text = std::string("Programming in C++");

    text.front() = 'p';
    text.back()  = '!';

    std::cout << text;
}

Wynikiem wykonania powyższego kodu również jest wyświetlenie tekstu programming in C+!.

Składnia z linii nr 7 oraz 8 może się wydawać dziwna — zupełnie jakbyśmy przypisywali coś do metody albo do jej wyniku. W rzeczywistości tak właśnie jest — drugie z tych skojarzeń jest prawdziwe. To dzięki referencjom, które zostaną dokładniej przedstawione w niedalekiej przyszłości.

Można oczywiście używać metod .front() oraz .back() nie tylko do nadpisywania elementów, ale również do ich zwykłego wyświetlenia.

Użycie metody .front() lub .back() na pustym kontenerze skutkuje Zachowaniem Niezdefiniowanym (UB).

Do std::string można dodawać znaki na wiele sposobów. Najczęściej wykorzystuje się do tego operator +=.

#include <iostream>
#include <string>

auto main() -> int {
    auto text = std::string();

    auto first  = std::string("Programming");
    auto second = std::string("in");
    auto third  = std::string("C++");

    for (auto chr : first) text += chr;
    text += ' ';
    for (auto chr : second) text += chr;
    text += ' ';
    for (auto chr : third) text += chr;

    std::cout << text;
}

Uruchomienie powyższego kodu wyświetli tekst Programming in C++. Warto zwrócić uwagę, że tak samo, jak w Javie, można pomijać klamry pod pętlami czy instrukcjami typu if (), o ile ma być wykonywana pojedyncza instrukcja w ramach ciała.

Ostatnią z podstawowych operacji (jak na razie) dotyczących std::string będzie konstruowanie fragmentów tekstu na podstawie oryginalnego obiektu. Rozważmy poniższy listing:

    std::cout << "kg stands for kilo" << text.substr(3, 4);

Metoda .substr() pozwala na skonstruowanie nowego obiektu std::string zawierającego sprecyzowany fragment oryginalnego tekstu. Pierwszy argument to indeks startowy, a drugi to liczba znaków do skopiowania.

Język C++ stawia wydajność aplikacji jako jeden z priorytetów. W związku z tym nietrudno się domyślić, że tworzenie zupełnie nowego obiektu (co często implikuje alokacje pamięci i kopiowanie) w momencie, gdy programistę interesuje praca jedynie na fragmencie oryginalnego std::stringa, wcale nie zawsze jest najlepszym pomysłem. Na ten moment w ramach PJC nie należy się tym przejmować, ale jeżeli ktoś chce poczytać o potencjalnie wydajniejszych alternatywach, warto zagłębić się w ten temat bardziej1.

Kontener std::vector

std::string to kontener przechowujący znaki. Nietrudno się domyślić, że istnieje bardziej generyczny, czyli ogólny, kontener, który może przechowywać cokolwiek. Nazywa się on std::vector.

std::vector i std::string to najczęściej używane kontenery w C++.

Deklarując zmienną typu std::vector2 należy sprecyzować, jakiego typu elementy będzie ona przechowywać. Obrazuje to poniższy listing:

    auto integers    = std::vector<int>();
    auto realNumbers = std::vector<double>();

Zwracamy uwagę na nowy nagłówek — #include <vector>.

Typ elementów wektora precyzujemy w nawiasach trójkątnych (<>).

Zamiast korzystać z konstruktora domyślnego, można stworzyć wektor od razu wypełniony elementami. Używamy do tego klamer ({}) zamiast nawiasów okrągłych (()).

    auto integers    = std::vector<int>{1, 2, 3};
    auto realNumbers = std::vector<double>{3.14, 2.71, 1.61};
    auto words       = std::vector<std::string>{"Hello", " ", "World"};

Jeżeli nie wiemy, jakie elementy będzie przechowywał wektor, można utworzyć go pustego, a następnie dodawać je metodą .push_back(). Dodaje ona do wektora do niego nowy element, ustawiając go na samym końcu kontenera (efektywnie zwiększając jego rozmiar o 1):

#include <iostream>
#include <string>
#include <vector>

auto main() -> int {
    auto integers = std::vector<int>();

    for (auto i = 0; i < 10; i++) {
        integers.push_back(i);
    }

    for (auto element : integers) {
        std::cout << element << ' ';
    }
}

Wektor, podobnie jak std::string, wspiera metody takie jak .size(), .front() czy indeksowanie.

Naturalnie dodawanie elementów to tylko połowa sukcesu. Czasem należy też niektóre usunąć. W tym celu możemy użyć metody .pop_back(), która usuwa element z końca wektora (efektywnie zmniejszając jego rozmiar o 1):

#include <iostream>
#include <vector>

auto main() -> int {
    auto integers = std::vector<int>{1, 2, 3, 4, 5};

    auto toRemove = 0;
    std::cin >> toRemove;

    if (toRemove > integers.size()) {
        toRemove = integers.size();
    }

    for (auto i = 0; i < toRemove; i++) {
        integers.pop_back();
    }

    std::cout << integers.size() << '\n';
    
    for (auto element : integers) {
        std::cout << element << ' ';
    }
}

Powyższy listing poprosi użytkownika o wprowadzenie liczby elementów do usunięcia z wektora. Jeżeli wprowadzona liczba będzie większa niż liczba elementów w wektorze, zostanie ona odpowiednio dopasowana. Na koniec wyświetlana jest liczba elementów, które w wektorze pozostały oraz sama zawartość tego wektora.

std::string również wspiera .push_back() oraz .pop_back(), choć w przypadku tej klasy raczej nie używa się metody .push_back(). Większość kontenerów współdzieli wiele metod, choć czasem niektórych z nich używa się bardzo rzadko.

Klasa std::string a C-napisy

Na pewno niektórzy zwrócili już uwagę na pierwsze przedstawienie typu tekstowego, a dokładniej na jawne precyzowanie typu std::string. Czym się zatem różni "Text" od std::string("Text")?

Bardzo małym błędem byłoby odpowiedzieć, że wszystkim.

1

auto string = std::string("Text");

1

auto rawText = "Text";

C-string, albo inaczej C-napis, to najbardziej surowa forma tekstu przechowywanego w komputerze. Nie reprezentuje on żadnego obiektu, w znanym nam znaczeniu tego terminu. Jest to nic innego jak tylko zapisana w pamięci komputera niemodyfikowalna tablica znaków, do której otrzymujemy dostęp przy pomocy jej adresu. Na takiej zmiennej rawText nie możemy wykonać żadnych ciekawych operacji.

Zmienne reprezentujące dostęp do C-napisów wspierają indeksowanie, ale przykładowo nie powiedzą nam, z ilu składają się znaków (nie mają metody .size()), bo nie wspierają żadnych metod. Efektywnie można ich użyć tylko do wyświetlania lub inicjalizacji obiektów typu std::string.

Jeżeli nie interesują nas żadne metody, a jedynie sprecyzowanie literału tekstowego, nie trzeba go umieszczać w obiekcie typu std::string — wystarczy skorzystać z literału C-napisu, jak to było wykorzystywane w przykładach wyżej, np. w std::cout << "kg stands for kilo".

Niemniej jednak, najczęściej przy przechowywaniu tekstu będziemy tworzyć obiektu typu std::string — dla wygody.
