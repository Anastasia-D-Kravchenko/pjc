Iteratory

Nie wszystkie kontenery wspierają indeksowanie.

Nie zawsze chcemy posortować (lub odwrócić) cały kontener. Czasem chcemy zaaplikować jakiś standardowy algorytm do fragmentu danych.

Jak zatem uzyskać dostęp do danych z kontenera, który nie wspiera indeksowania? Jak można zaaplikować standardowy algorytm do fragmentu kontenera?

Odpowiedzią na obydwa pytania jest: używając iteratorów.

Czym jest iterator?

Iterator to abstrakcja dostępu do danych. Do tej pory, chcąc w jakiś sposób wejść w interakcję z konkretnym elementem kontenera (lub tablicy w Javie) używaliśmy indeksowania.

Indeksowanie nie zawsze jest wystarczające. Niektóre kontenery (oraz kolekcje w innych językach, np. w Javie) nie wspierają indeksowania. Czasem dlatego, że nie precyzują one żadnej kolejności danych (więc co by oznaczało, że jakiś element jest pod indeksem 4, a inny pod indeksem 7?), a czasem dlatego, że indeksowanie implikuje szybki dostęp do danych (podajemy liczbę i oczekujemy, że pozycja elementu będzie natychmiast dostępna). Tak również czasem nie jest.

To nie są wyczerpujące przykłady, ale na ten moment powinny być wystarczające do zrozumienia, że indeksowanie nie jest uniwersalnym sposobem dostępu do danych.

Iteratory udostępniają uniwersalny sposób dostępu do danych. Kontenery nie zawsze wspierają indeksowanie.

O iteratorze można myśleć jak o strzałce wskazującej na jakieś dane lub jako o kartce z adresem oraz szczegółowymi danymi dotyczącymi tego, co znajduje się pod wspomnianym adresem.

Wszystkie kontenery w C++ udostępniają metody .begin() oraz .end()1, które zwracają iteratory na kolejno ich początek i koniec.

Używanie iteratorów

No dobrze, ale jak się korzysta z iteratorów?

Najczęściej wywołując metodę .begin() i zapisując zwrócony iterator. Przykład ukazuje poniższy listing:

#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2};

    auto iterator = vec.begin();
}

Linijka nr 6 zawiera deklarację zmiennej iterator. Jak sama nazwa wskazuje — jest to jakiś iterator. Typem tej zmiennej jest std::vector<int>::iterator. Nazwa tego typu nie mówi nam absolutnie nic. Tak naprawdę jest to alias2 na typ, którego prawdziwej nazwy nie znamy. Dlatego nie będziemy się interesować jego konkretną nazwą lub deklaracją. Jedyne, co nas interesuje, to co można z takim iteratorem zrobić.

Jak już zostało to kilkukrotnie zaznaczone, iteratory pozwalają na dostęp do danych. Aby dostać się do elementu wskazywanego przez iterator, należy użyć operatora dereferencji, czyli znaku *:

#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2};

    auto iterator = vec.begin();

    std::cout << *iterator;
}

Kod ten wyświetla 3. To dlatego, że .begin() zwraca iterator wskazujący na pierwszy element kontenera.

#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2};

    auto iterator = vec.begin();

    *iterator = 10;

    std::cout << vec.front();
}

Ukazaną operację można zapisać nieco zwięźlej (choć nie zawsze zwiększa to czytelność) w następujący sposób: *vec.begin() = 10.

Powyższy listing wyświetla liczbę 10, co nie powinno być zaskoczeniem. Uzyskujemy iterator na pierwszy element, później za jego pomocą (i dzięki *) dostajemy się do elementu wskazywanego przez niego i nadpisujemy ten element wartością 10. Wspomniany element jest wciąż w tym samym miejscu — na początku wektora. Dlatego wyświetlając go przy pomocy vec.front() widzimy wspomnianą liczbę 10.

Dostęp do danych (przy pomocy *) jest najważniejszą cechą iteratora. Na drugim miejscu stoi przesuwanie go (przy pomocy ++ i tym podobnych).

#include <iostream>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2};

    auto iterator = vec.begin();

    *iterator = 10;
    ++iterator;
    *iterator = 20;

    for (auto element : vec) {
        std::cout << element << ' ';
    }
}

W powyższym listingu metoda produkująca iterator została wywołana tylko raz. Stworzyliśmy tylko jedną zmienną będącą iteratorem. Niemniej jednak w wektorze vec zmianie podległy aż dwa elementy.

To dlatego, że pojedynczy iterator nie jest z reguły związany z pojedynczym elementem. To swojego rodzaju kartka papieru z adresem, której ten adres możemy zamazać i nadpisać. Alternatywnie można myśleć o iteratorze jako o strzałce, za pomocą której możemy się dostać do jakichś elementów. Strzałki można przesuwać. Gdy daną strzałkę przesuniemy, a następnie użyjemy jej jako dostępu do danych, to naturalnym będzie założyć, że dostaniemy się do jakiś zupełnie nowych danych.

Tak właśnie się stało w linijkach nr 9-11. Pierwotnie iterator wskazywał na liczbę 3 z wektora. Została ona potem zamieniona na liczbę 10. Następnie (linijka nr 10) iterator został przesunięty o jedno miejsce “w prawo” — na element zawierający liczbę 5. Powtórzenie operacji nadpisania zamieniło tę liczbę na liczbę 20.

Operacja inkrementacji na iteratorze skutkuje przesunięciem go na następny element. W przypadku iteratorów wskazujących na kontenery reprezentowane przez blok pamięci (np. std::string czy std::vector), tę operację można uznać jako “przesuwanie iteratora w prawo”.

Niektóre z iteratorów mogą być inkrementowane tylko przy pomocy ++. Niektóre wspierają też --. Jeszcze inne wspierają również += czy -=. Na ten moment ograniczamy się do analizy std::vector oraz std::string, których iteratory wspierają każdą z tych operacji. Przykładowo:

    *iterator = 10;

Jak widać wyżej, można praktycznie dowolnie “skakać” po elementach i je zmieniać dzięki iteratorom.

Wykonywanie standardowych algorytmów na fragmentach kontenerów

Jaki jest realny przykład operacji, które mogę chcieć wykonać teraz, do których będą mi potrzebne iteratory?

Wykonywania operacji na fragmentach kontenerów, a w niedalekiej przyszłości — dostęp do elementów z kontenerów, które nie wspierają indeksowania.

Posortujmy pierwszą połowę wektora i odwróćmy jego drugą połowę:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2, 0};

    std::ranges::sort(vec.begin(), vec.begin() + vec.size() / 2);
    std::ranges::reverse(vec.begin() + vec.size() / 2, vec.end());

    for (auto element : vec) {
        std::cout << element << ' ';
    }
}

1

1 3 5 0 2 4

Na pierwszy rzut oka nie ma nic podejrzanego w powyższym przykładzie. Ewidentnie widać, że zakres vec.begin(), vec.begin() + vec.size() / 2 to pierwsza połowa wektora vec, a vec.begin() + vec.size() / 2, vec.end() to druga połowa wektora vec.

A jeżeli tego nie widać, to można to relatywnie prosto wydedukować. Skoro .begin() to iterator na pierwszy element, a iteratory można przesuwać, to przesuwając otrzymany iterator “do przodu” (“w prawo”) o połowę elementów znajdujących się w całym kontenerze (vec.size() / 2), otrzymamy iterator na środkowy element.

Ten sam iterator jest używany do sprecyzowania początku zakresu, na którym pracuje algorytm std::ranges::reverse(). Warto to podkreślić refaktorując kod poprzez zapisanie powtarzających się wyrażeń do zmiennej:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2, 0};

    auto middle = vec.begin() + vec.size() / 2;
    
    std::ranges::sort(vec.begin(), middle);
    std::ranges::reverse(middle, vec.end());

    for (auto element : vec) {
        std::cout << element << ' ';
    }
}

“Na papierze” wszystko jest bardzo proste — definiujemy środek zakresu i za jego pomocą dzielimy wspomniany zakres na dwie części, na których operujemy osobnymi algorytmami.

Pojawia się jednak nieuniknione pytanie:

W wektorze vec jest 6 elementów. Na który z nich wskazuje middle? Dodatkowo skoro middle jest używane zarówno w std::ranges::sort() oraz std::ranges::reverse(), to który z algorytmów ma wpływ na element, na który pokazuje? Obydwa? Żaden? Jeden z nich? A jeżeli tak, to który?

middle oczywiście wskazuje na element z oryginalną wartością 4. Iterator na początek (.begin()) jest przesuwany o 3 elementy w prawo (vec.size() / 2) — tak otrzymaliśmy middle.

Jednak aby odpowiedzieć na resztę pytań, należy zgłębić temat zakresów prawostronnie otwartych oraz tego, jak zaskakującym iteratorem jest ten zwracany przez .end().

Zakresy prawostronnie otwarte

Z matematyki wiemy, co oznacza zakres prawostronnie otwarty. To jest to samo, co zakres lewostronnie zamknięty. Opisuje się go następującym wzorem: \([x, y)\).

Zakresy w C++ są prawostronnie otwarte. Oznacza to, że element wskazywany przez iterator reprezentujący początek zakresu będzie brany pod uwagę podczas wykonywania danego algorytmu, a element wskazywany przez iterator reprezentujący koniec zakresu nie będzie brany pod uwagę podczas wykonywania danego algorytmu.

Standardowo, najlepiej jest przyjrzeć się przykładowi ilustrującemu powyższy fakt. Stwórzmy zatem prosty wektor oraz dwa iteratory wskazujące na któreś z jego wewnętrznych elementów:

auto main() -> int {
    auto vec = std::vector<int>{11, 22, 33, 44, 55, 66};

    auto first = vec.begin() + 1;
    auto last  = vec.begin() + 4;

    std::cout << *first << ' ' << *last;
}

Prosta arytmetyka iteratorów jasno pokazuje, że first wskazuje na element przechowujący wartość 22, a last na element przechowujący 55.

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{11, 22, 33, 44, 55, 66};

    auto first = vec.begin() + 1;
    auto last  = vec.begin() + 4;

    std::ranges::reverse(first, last);
}

Początkujący programiści C++ często zakładają, że skoro first wskazuje na element 22, last na 55, to odwrócenie elementów między first i last poskutkuje uporządkowaniem wektora vec w następujący sposób: 11 55 44 33 22 66.

Tak jednak nie jest.

Faktycznym stanem vec po wykonaniu algorytmu odwracania z linii 11 jest: 11 44 33 22 55 66. Liczba 55 jak była, tak jest przedostatnia.

To dlatego, że element wskazywany przez last nie jest brany pod uwagę w ramach wykonywania std::ranges::reverse() z linijki 11.

W takim razie po co w ogóle się go przekazuje? Dlaczego jest to tak dziwnie zrobione?

Można godzinami czytać na temat plusów i minusów takich zakresów. Kilka ciekawych przykładów można znaleźć tutaj.

Nie zmienia to jednak faktu, że użytkownicy (czyli “normalni ludzie”) wcale nie myślą przy pomocy zakresów jednostronnie otwartych. Przykładowo, gdy mówi się “od poniedziałku do piątku”, to ma się na myśli pełne pięć dni — włącznie z poniedziałkiem i włącznie z piątkiem.

Dlatego musi minąć trochę czasu, zanim przyzwyczaimy się do tego, że algorytmy standardowe oczekują zakresów, których “końcowy iterator” wskazuje na element, którego algorytm nie bierze pod uwagę.

Na ten moment najistotniejszym argumentem ku akceptacji takiej notacji i praktyki reprezentowania zakresów jest fakt, że koniec jednego podzakresu jest automatycznie początkiem następnego.

Dzięki temu, że zakresy w C++ są prawostronnie otwarte, dzieląc jakiś zakres na podzakresy, iterator reprezentujący koniec któregoś z nich jest automatycznie początkiem następnego. Nie trzeba wtedy wykonywać selektywnych operacji typu + 1 chcąc obliczyć następny element.

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2, 0};

    auto middle = vec.begin() + vec.size() / 2;
    
    std::ranges::sort(vec.begin(), middle);
    std::ranges::reverse(middle, vec.end());

    for (auto element : vec) {
        std::cout << element << ' ';
    }
}

middle wskazuje na 4. std::ranges::sort() posortuje wszystko od 3 do 4 wyłącznie, czyli: 3, 5, 1. std::ranges::reverse() odwróci resztę elementów (włącznie z 4) czyli: 4, 2, 0.

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{11, 22, 33, 22, 33, 11};

    auto middle = vec.begin() + vec.size() / 2;

    std::ranges::sort(vec.begin(), middle);
    std::ranges::sort(middle, vec.end());

    auto bothHalvesEqual = std::ranges::equal(
            vec.begin(), middle,
            middle, vec.end()
    );

    std::cout << bothHalvesEqual;
}

Algorytm jest bardzo prosty. Ponownie otrzymujemy iterator na “środek”, sortujemy obydwie połówki i za pomocą std::ranges::equal() sprawdzamy, czy są takie same.

Algorytm std::ranges::equal() sprawdza, czy dwa dowolne zakresy są identyczne. Można dzięki niemu przykładowo porównywać między sobą std::vector<char> oraz std::string.

Czym jest .end()?

.begin() oraz .end() zwracają iteratory na początek i koniec. Algorytmy standardowe pracują na zakresach prawostronnie otwartych, czyli “nie dotykają” elementu wskazywanego przez iterator reprezentujący koniec. .begin() zwraca iterator na pierwszy element zakresu.

To wszystko są fakty, które poznaliśmy wcześniej. To, czego jeszcze jednak nie wiemy, to co konkretnie zwraca .end().

Spójrzmy na poniższy fragment kodu, który odwraca cały wektor, ale zamiast przekazywać do algorytmu jego nazwę, przekazujemy iteratory na jego początek i koniec:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{1, 2, 3};

    std::ranges::reverse(vec.begin(), vec.end());

    for (auto element : vec) {
        std::cout << element << ' ';
    }
}

Efektem jest wyświetlenie 3 2 1. To samo, co gdybyśmy zamiast std::ranges::reverse(vec.begin(), vec.end()) wykonali std::ranges::reverse(vec).

Zakres od range.begin() do range.end() reprezentuje wszystkie elementy z range.

Jak to można pogodzić? Jak to jest, że algorytmy ignorują element pod iteratorem reprezentującym koniec zakresu, a para .begin()-.end() reprezentuje wszystkie elementy?

Iterator zwracany przez .end() wskazuje na element za ostatnim.

To tyle. Cała filozofia. Jest to zbiór często mało intuicyjnych faktów, które mimo wszystko współpracują ze sobą, aby stworzyć relatywnie wygodne narzędzie w postaci algorytmów i struktur danych z biblioteki standardowej języka C++.

W przyszłości pojawi się więcej przykładów, które będą wykorzystywały te osobliwe cechy zakresów i iteratorów. Na koniec warto jeszcze przyjrzeć się przykładowi, który za pomocą iteratorów wyświetla wszystkie elementy wektora. Do mniej więcej takiej formy jest kompilowana pętla zakresowa for ():

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{1, 2, 3};

    for (auto iter = vec.begin(); iter != vec.end(); ++iter) {
        std::cout << *iter << ' ';
    }
}

Jak widać, dotarcie do końca zakresu (.end()) reprezentuje koniec danych, na których jakiś algorytm (w tym przypadku — surowa pętla for ()) miał pracować. Jest to swojego rodzaju “strażnik”, do którego dotarcie oznacza koniec pracy.
