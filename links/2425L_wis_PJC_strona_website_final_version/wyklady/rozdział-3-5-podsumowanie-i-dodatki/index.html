Rozdział 3.5 - Podsumowanie i dodatki

Opublikowano Mar 16, 2025
Autor Filip Kwiatkowski
7 min czytania

Nowe standardowe algorytmy i elementy nimi sterujące

Poznaliśmy:

  • std::ranges::find(), które zwraca iterator na szukany element.
  • std::ranges::max(), std::ranges::min() oraz ich wersje z sufiksem _element():
    • wersje “podstawowe” zwracają największy lub najmniejszy obiekt z zakresu;
    • wersje z sufiksem _element() zwracają iterator na największy lub najmniejszy element.
  • std::ranges::less oraz std::ranges::greater, które są typami reprezentującymi logikę komparatorów.
  • std::ranges::size, czyli obiekt-funkcja, który zwraca wielkość przekazanego argumentu — bardzo przydatny w projekcjach.
  • std::ranges::find_if(), który jest bliźniaczym algorytmem do std::ranges::find(). Różnica między nimi jest taka, że “podstawowa” wersja szuka identycznego elementu do przekazanego, a wersja z sufiksem _if() przyjmuje predykat i szuka pierwszego elementu, który ten predykat spełni.
  • std::ranges::transform(), który pozwala na zamianę jednego zakresu w drugi.

Intuicyjne zrozumienie zasady działania komparatorów, projekcji czy predykatów może być nieco trudne, dlatego warto spróbować zadziałać na zasadzie skojarzenia. Przykładowo, można powiedzieć, że algorytm sortujący działa tak:

std::ranges::sort(CoSortować, JakSortować, WedługCzego)

A algorytm transformujący działa tak:

std::ranges::transform(Co, GdzieWpisać, JakZmienić) 1

Lambdy

Lambdy rozwiązują problem braku możliwości definiowania lokalnych funkcji. Są to obiekty-funkcje.

Unikalny i ukryty typ lambdy

Widząc pierwszy raz taki kod:

1
2
3
4
5
6
7
8
9

#include <fmt/base.h>

auto main() -> int {
    auto useless = []() -> void { };

    auto greeter = []() -> void {
        fmt::println("Hello World!");
    };
}

Można się zastanawiać, jakiego typu są obiekty useless i greeter. W końcu auto pozwala nam na pomijanie typu — możemy zrobić auto x = int(), ale jednocześnie możemy od razu zainicjalizować tę zmienną jakimś literałem, np. auto x = 0;.

Jak by wyglądało stworzenie zmiennej useless czy greeter bez użycia auto?

Nie wyglądałoby. Nie da się “ręcznie” sprecyzować typu takiej zmiennej. Literał lambdy (czyli []() {} z dekoracjami typu typ zwracany lub argumenty) ma unikalny typ wygenerowany przez kompilator. Nie jesteśmy w stanie go ręcznie wprowadzić.

Istnieją alternatywy stosujące mechanizm wymazania typu (ang. type erasure), ale cechują się one gorszą wydajnością. Warto zatem zapamiętać jedno:

Przy tworzeniu zmiennych, które są lambdami, należy używać auto.

Co więcej, dwie, identyczne lambdy mają różne typy!

Przykładowo, gdy stworzymy lambdę, to nic nie stoi na przeszkodzie, żeby ją skopiować:

1
2
3
4

auto main() -> int {
    auto lambda = []() { };
    auto copy   = lambda;
}

Zarówno lambda jak i copy mają ten sam typ — auto potrafi go wydedukować i odpowiednio podstawić. Natomiast gdy spróbujemy zainicjalizować copy identyczną lambdą, a potem nadpisać jedną przy pomocy drugiej, kod się nie skompiluje:

1
2
3
4
5
6

auto main() -> int {
    auto lambda  = []() { };
    auto another = []() { };

    lambda = another;
}

      |                     ^

To dlatego, że mimo iż literały lambd mogą wyglądać tak samo, każdy literał lambdy reprezentuje unikalny typ.

Alternatywa do wczytywania elementów wektora

We wcześniejszej części rozdziału został zaprezentowany fragment kodu, który wczytywał elementy od użytkownika do wektora:

1
2
3
4
5

auto numbers = std::vector<int>(21);

for (auto i = 0; i < numbers.size(); i++) {
    std::cin >> numbers[i];
}

Alternatywnie można to samo osiągnąć używając pętli zakresowej, która by wykorzystywała referencje do elementów:

1
2
3
4
5

auto numbers = std::vector<int>(21);

for (auto& number : numbers) {
    std::cin >> number;
}

Jak widać, referencji możemy używać nie tylko jako zmienne lokalne czy parametry, ale też i w zmiennych pętli. number referuje tutaj do każdego elementu z numbers. Bez ampersanda (czyli referencji — &), number byłoby kopią każdego kolejnego elementu.

Bezpieczne przesuwanie iteratorów

W jednym z omawianych w tym rozdziale zadań pojawił się fragment, gdzie przesuwaliśmy dany iterator o trzy miejsca w prawo. Odpowiadał za to następujący kod:

1

start += 3

Była to część pętli, która wykonywała się dopóki start != numbers.end(). Co, gdyby jednak numbers nie miało liczby elementów podzielnych przez 3? Taka inkrementacja iteratora uciekłaby poza zakres i wywołalibyśmy UB. Warto jest rozważyć bezpieczniejszą alternatywę:

1

std::ranges::advance(start, 3, numbers.end())

Algorytm std::ranges::advance() przesuwa przekazany w pierwszym argumencie iterator o odpowiednią, sprecyzowaną w drugim argumencie liczbę miejsc, ale nie pozwala, żeby to przesunięcie przeszło “dalej” niż trzeci argument. Efektywnie jest to bezpieczniejsza alternatywa dla przykładów, gdzie nie jesteśmy pewni, czy przesunięcie nie wyjdzie poza zakres.

Odwrotności algorytmów i komparatorów

Odwracając algorytm oraz komparator, otrzymamy identyczny wynik.

Oznacza to, że poniższe dwa listingi kodu zrobią efektywnie to samo:

1

std::ranges::max(someRange);

1

std::ranges::min(someRange, std::ranges::greater());

To dlatego, że std::ranges::min() szukając “najmniejszego” elementu będzie szukało efektywnie takiego, który będzie “najmniejszy” dla przekazanego komparatora. std::ranges::greater() “ustawia” najpierw największe elementy, ale std::ranges::min() o tym nie wie. Stąd wywodzi się powyższa równoważność operacji.

Algorytm std::ranges::minmax_element()

W tym rozdziale pojawił się przykład zamiany miejscami najmniejszej i największej wartości z danego kontenera. Wyglądał on mniej więcej tak:

1
2
3
4

auto maxIter = std::ranges::max_element(numbers);
auto minIter = std::ranges::min_element(numbers);

std::ranges::iter_swap(maxIter, minIter);

Kod ten można nieco uprościć. Istnieje algorytm std::ranges::minmax_element(), który zwraca parę iteratorów — jeden wskazujący na najmniejszy i jeden wskazujący na największy element.

Algorytm ten istnieje dlatego, że istnieje szybszy sposób znalezienia takiej pary “na raz” niż osobne szukanie wpierw jednego, a potem drugiego.

Można go wykorzystać w następujący sposób:

1
2

auto elements = std::ranges::minmax_element(numbers);
std::ranges::iter_swap(elements.min, elements.max);

Zaprezentowany kod można jeszcze inaczej zmodyfikować — wykorzystując tak zwane wiązania strukturalne (ang. structured bindings). Nie trzeba o nich wiedzieć, bo będą dokładniej wyjaśnione w rozdziale traktującym o mapach:

1
2

auto [min, max] = std::ranges::minmax_element(numbers);
std::ranges::iter_swap(min, max);

Efektywnie “rozbija” to obiekt na dwie lokalne zmienne.

Literał domyślnych wartości — {}

Puste klamry mogą nie tylko oznaczać pusty kontener, jak w przypadku std::vector<int>{}, std::string{} czy std::set<float>{}. Mogą one reprezentować też domyślnie stworzoną wartość, gdy typ tej wartości jest oczywisty. Przyjrzyjmy się kilku przykładom:

Jawny typ zwracany

Poniższe dwie funkcje robią dokładnie to samo:

1
2
3

auto makeInt() -> int {
    return 0;
}

1
2
3

auto makeInt() -> int {
    return {};
}

Kompilator wie, że makeInt() ma zwrócić inta — w końcu napisaliśmy -> int. Dlatego wie, że {} będzie użyte do stworzenia domyślnej wartości — 02.

Argument

Gdy argument w funkcji jest znany i można go “domyślnie stworzyć”, można użyć {}, aby stworzyć tymczasową wartość. Zakładając następującą funkcję:

1

auto acceptInt(int n) -> void { }

Można wywołać ją z argumentem 0 na dwa sposoby:

1

acceptInt(0);

1

acceptInt({});

Nie jest zbytnio przydatne dla intów, ale gdy typ jest długi, może się okazać, że taki skrócony zapis bardzo upraszcza pisanie kodu. Przykładowo:

auto acceptVector(std::vector<int> vec) -> void { }

auto main() -> int {
    acceptVector({});

#include <algorithm>
#include <functional>   // std::ranges::less
#include <ranges>       // std::ranges::size
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "those", "are", "extremely",
            "random", "words", "in",
            "this", "particular", "example"
    };

    std::ranges::sort(words, {}, std::ranges::size);

    fmt::println("{}", words);
}

Wiemy, że drugim argumentem dla std::ranges::sort() jest komparator, którego domyślnym typem jest std::ranges::less. Skoro tak, to wystarczy użyć {} do stworzenia tymczasowego obiektu tego typu — nie trzeba pisać std::ranges::less().

Lambdy mogą być const

W poprzedniej części rozdziału (przy wprowadzeniu lambd na przykładzie funkcjonalności isEven()) pojawiło się następujące stwierdzenie:

Przede wszystkim isEven nie jest już funkcją. isEven jest zmienną. Zmienną, która została zainicjalizowana lambdą.

Zmienne (obiekty) mogą być const. Czy powinniśmy deklarować lokalne lambdy jako const?

Z reguły tak. Bardzo rzadko jest powód, żeby tego nie robić. Wyjątkiem stanowi sytuacja, gdy chcemy oznaczyć naszą lambdę jako mutable, ale o tym będziemy mówić dopiero w przyszłości.
