Rozdział 4.4 - Podsumowanie i dodatki

Opublikowano Mar 24, 2025
Autor Filip Kwiatkowski
3 min czytania

Szablony stosuje się wtedy, gdy jakaś implementacja jest identyczna dla dużego zestawu typów

Zamiast tworzyć absurdalne liczby przeciążeń funkcji, warto zastosować szablon. Co więcej, pozwala on na stworzenie narzędzi (np. funkcji), które będą działały z typami, które jeszcze nie istnieją. Przykładowo, gdy będziemy uczyć się o typach stworzonych przez użytkownika (klasach), to nic nie będzie stało na przeszkodzie stworzyć wektor naszych obiektów. O ile nasz typ będzie spełniał określone warunki, szablony z biblioteki standardowej (np. te z std::ranges) będą poprawnie obsługiwały kontenery przechowujące nasze obiekty.

Wprowadzone placeholdery tyczą się tylko jednej nazwy następującej po słowie template

Przykładowo, patrząc na taki kod:

1
2
3
4

template <typename T>
auto accept1(T t) -> void { }

auto accept2(T t) -> void { }

Szablon accept1() jest całkowicie poprawny, ale accept2() nie przejdzie procesu kompilacji. Linijka template <typename T> wprowadza placeholder T tylko dla accept1(). Jednocześnie tylko accept1() jest szablonem. accept2() to zwykła funkcja, która próbuje przyjąć jakiś typ T, o którym C++ nie słyszał.

Gdybyśmy chcieli stworzyć dwa takie szablony, musielibyśmy powtórzyć deklarację template <typename T>:

template <typename T>
auto accept1(T t) -> void { }

template <typename T>
auto accept2(T t) -> void { }

W prostych szablonach warto rozważyć użycie skrótowego zapisu

Listing z poprzedniego podrozdziału można zastąpić następującym:

2
3

auto accept1(auto t) -> void { }

auto accept2(auto t) -> void { }

Nie zawsze jest to jednak możliwe wygodne.

Lambdy

Aby przyjąć lambdę jako argument, jedynym sposobem jest użycie szablonu1. Lambdy mają unikalny, nieznany nam typ, a zatem musimy wykorzystać szablon.

Koncepty pozwalają ograniczać typ, który można dopasować do szablonu

Dzięki Konceptom jesteśmy w stanie ograniczyć zbiór typów, które nasz szablon może przyjąć. Dzięki temu możemy tworzyć osobne szablony, które działają z potencjalnie nieskończoną liczbą typów, ale w zależności od tego, jakie zachowanie dane typy wspierają, różne implementacje zostaną wybrane.

Czasami możliwym jest nawet zaimplementować różne zachowanie dla różnych typów w ramach jednego szablonu! Można to uzyskać stosując dosyć zaawansowaną konstrukcję if constexpr ():

#include <iostream>
#include <ranges>
#include <vector>

template <typename T>
auto print(T const& t) -> void {
    if constexpr (std::ranges::range<T>) {
        for (auto const& element : t) {
            std::cout << element << ' ';
        }
        std::cout << '\n';
    } else {
        std::cout << t << '\n';
    }
}

auto main() -> int {
    auto const vec = std::vector<int>{2, 1};
    auto const num = 37;

    print(vec);
    print(num);
}

Instrukcja if constexpr () w tym kontekście pozwala nam skompilować tylko fragment kodu — w zależności od wartości logicznej w nawiasach. W końcu szablonu generują kod — inny kod się wygeneruje przy wywołaniu print(vec) a inny przy wywołaniu print(num). if constexpr () pozwala nam skompilować jeden lub drugi blok (np. ten po else) w zależności od tego, czy dany typ spełnia w danej generacji kodu dany Koncept.

  1. W teorii niektóre lambdy mogą być konwertowane do czegoś, co się nazywa wskaźnik na funkcję. Użycie tego wskaźnika nie wymaga użycia szablonu. Przy okazji używając std::function można przyjąć przez argument lambdę bez używania szablonów własnoręcznie. Nie sprawia to jednak, że teza z referowanego paragrafu jest niepoprawna. Wskaźniki na funkcję nie zawsze zadziałają (oraz mogą czasami negatywnie wpływać na wydajność), a std::function jest szablonem. ↩
