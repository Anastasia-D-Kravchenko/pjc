Zmiana zasady porządkującej liczby w algorytmie sortowania

Chciałbym użyć algorytmu std::ranges::sort() do posortowania wektora malejąco. Czy da się to zrobić, czy jednak jedyną możliwością jest posortowanie i późniejsze użycie std::ranges::reverse()?

Jak najbardziej istnieje sposób, aby od razu posortować liczby (lub elemnety innego typu) malejąco. Odpowiada za to drugi argument algorytmu std::ranges::sort(). Nazywa się on komparator (ang. comparator).

Komparator to narzędzie, które pozwala sterować zasadą porządkowania elementów w algorytmach.

“Standardowe” wywołanie std::ranges::sort() wyglądało dotychczas tak:

#include <algorithm>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto numbers = std::vector<int>{3, 5, 1, 4, 2};
    std::ranges::sort(numbers);
    fmt::println("{}", numbers);
}

1

[1, 2, 3, 4, 5]

Przyjrzyjmy mu się bliżej:

1

std::ranges::sort(numbers);

Na pierwszy rzut oka wszystko wygląda prosto — wywołujemy algorytm z jednym argumentem — z wektorem numbers.

Nie jest to do końca prawda. Algorytm ten przyjmuje więcej niż jeden argument. Na ten moment załóżmy, że tak naprawdę przyjmuje on dwa argumenty, gdzie drugi jest domyślny. W takim wypadku “pełne” wywołanie wyglądałoby tak:

1

std::ranges::sort(numbers, std::ranges::less());

std::ranges::less to typ, którego zmienne są komparatorami. W powyższym wywołaniu przekazujemy przez argumenty:

  1. Wektor numbers.
  2. Tymczasowy obiekt typu std::ranges::less. Puste nawiasy są wywołaniem konstruktora domyślnego. Np. jak przy auto text = std::string().

std::ranges::less reprezentuje logikę, która odpowiada relacji mniejszości (stąd nazwa), czyli operatorowi <. Jest to domyślny komparator używany w standardowych algorytmach.

Dla ułatwienia można mówić, że std::ranges::sort() grupuje elementy w taki sposób, że ustawia na początek te, które odpowiadają nazwie komparatora. Przykładowo, użycie sortowania z std::ranges::less ustawia na początek mniejsze elementy.

Odwrotnością less jest greater. Poniższy kod posortuje elementy wektora malejąco (bo najpierw będą większe (ang. greater)):

#include <algorithm>
#include <functional>   // std::ranges::less 
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto numbers = std::vector<int>{3, 5, 1, 4, 2};
    std::ranges::sort(numbers, std::ranges::greater());
    fmt::println("{}", numbers);
}

1

[5, 4, 3, 2, 1]

Zmiana zasady porządkującej tekst w algorytmie sortowania

Wiemy już, że std::ranges::less i std::ranges::greater pozwalają nam na jawne definiowane interesującej nas kolejności elementów przy algorytmach sortowania. Co jednak w przypadku, gdy sortujemy nie std::vector<int>, a — przykładowo — std::vector<std::string>?

Tak naprawdę to nic nowego. Wciąż możemy użyć tego samego:

#include <algorithm>
#include <functional>   // std::ranges::less 
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "hello", "there", "and", "welcome"
    };

    std::ranges::sort(words, std::ranges::greater());

    fmt::println("{}", words);
}

["welcome", "there", "hello", "and"]

Jak widać, przechowywane stringi zostały posortowane leksykograficznie malejąco, czyli “odwrotnie niż alfabetycznie”.

Sortowanie tekstu na bazie innej cechy

Teraz chciałbym posortować stringi rosnąco, ale z uwagi na ich długość, a nie pozycję alfabetyczną. Czy tak się da?

Oczywiście! Można to osiągnąć precyzując troszkę bardziej skomplikowany komparator, ale o tym będzie dopiero później. Na ten moment osiągniemy ten cel prościej. Dodatkowo odkryjemy całą prawdę o std::ranges::sort(), a mianowicie fakt, że przyjmuje on nie dwa, a trzy argumenty.

Pierwszym argumentem algorytmu sortowania jest zakres do posortowania. Może to być pojedynczy obiekt lub para iteratorów (wtedy jest to pierwszy i drugi argument). Kolejnym argumentem jest komparator, służący do precyzowania, który obiekt powinien być “ustawiony” przed którym. Trzecim jest projekcja (ang. projection) pozwalająca na patrzenie na obiekt przez inny pryzmat — przez inną cechę.

Co to znaczy, że “patrzymy na obiekt przez inny pryzmat”?

Na to pytanie najłatwiej jest odpowiedzieć przykładem. Pierwszą projekcją, którą poznamy, będzie std::ranges::size. Jest to specjalny obiekt-funkcja, która przyjmuje dowolny argument i zwraca jego wielkość:

#include <ranges>   // std::ranges::size
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto const words    = std::vector<std::string>{"hey", "there"};
    auto const word     = std::string("Hello");
    auto const sentence = std::string("Hello There");

    fmt::println(
            "size of {} is {}\n"
            "size of \"{}\" is {}\n"
            "size of \"{}\" is {}\n"
            "size of \"{}\" is {}",
            words,          std::ranges::size(words),
            words.front(),  std::ranges::size(words.front()),
            word,           std::ranges::size(word),
            sentence,       std::ranges::size(sentence)
    );
}

Skoro std::ranges::size() mówi nam, ile elementów ma dany obiekt / jakiej jest wielkości, to możemy go użyć jako projekcji w algorytmie sortowania, aby posortować stringi od najkrótszego do najdłuższego:

#include <algorithm>
#include <functional>   // std::ranges::less
#include <ranges>       // std::ranges::size
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "those", "are", "extremely",
            "random", "words", "in",
            "this", "particular", "example"
    };

    std::ranges::sort(words, std::ranges::less(), std::ranges::size);

    fmt::println("{}", words);
}

1

["in", "are", "this", "those", "words", "random", "example", "extremely", "particular"]

Dla dokładniejszego zrozumienia spróbujmy wyjaśnić wszystkie fragmenty tego wywołania:

1

std::ranges::sort(words, std::ranges::less(), std::ranges::size);

A zatem:

  • std::ranges::sort — posortuj…
  • words — …elementy wektora words…
  • std::ranges::less() — …ustawiając najpierw najmniejsze elementy…
  • std::ranges::size — …ale bierz pod uwagę tylko ich wielkości — nic innego.

W praktyce wygląda to tak, że algorytm std::ranges::sort(), podczas sortowania, pobiera dwa elementy, które musi w jakiś sposób ustawić. Przepuszcza je przez projekcję, czyli w naszym przypadku otrzymuje ich wielkości. Następnie przekazuje je do komparatora, który (w tym momencie otrzymując tylko liczby — wielkości sortowanych std::stringów otrzymane dzięki projekcji) powie, że na początek ma zostać ustawiona ta mniejsza liczba. Algorytm w ten sposób określi, że krótszy ze stringów musi zostać ustawiony na początek.

Brzmi skomplikowanie.

Ale takie nie jest — naprawdę wystarczy trochę to przećwiczyć i intuicyjnie wszystko “wejdzie w krew”.

Dlaczego przy std::ranges::less używamy (), czyli tworzymy tymczasowy obiekt, a przy std::ranges::size już nie?

…Trudne pytanie.

Formalnie odpowiedź brzmi tak:

std::ranges::less jest typem (klasą), więc aby algorytm mógł go użyć, trzeba stworzyć obiekt tego typu. std::ranges::size jest już (globalnym) obiektem (tak jak np. std::cout czy std::cin), więc używamy go bezpośrednio.

Mimo wszystko jest to temat dużo trudniejszy niż się wydaje. Jeżeli ktoś bardzo chce poczytać dalej (a jest to odradzane, chyba że komuś już coś mówi termin CPO (ang. customization point object) czy niebloid, bo wiedza ta wykracza poza zakres PJC), to może zacząć tutaj.

Dlatego na ten moment trzeba po prostu zaakceptować, że niektóre “algorytmy” czy “funkcje” czasem są wykorzystywane jako typy, których obiekty trzeba tworzyć, a czasem jako już predefiniowane obiekty. Nieco więcej wyjaśni się w następnym rozdziale, gdzie będzie mowa o lambdach.

Wyszukiwanie tekstu na bazie innej cechy

Tak samo jak std::ranges::sort(), wiele innych, poznanych wcześniej algorytmów wspiera precyzowanie komparatora i projekcji. Przykładowo, możemy użyć std::ranges::max_element() aby usunąć z wektora największy element:

#include <algorithm>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto numbers = std::vector<int>{3, 5, 2, 4, 1};
    numbers.erase(std::ranges::max_element(numbers));
    fmt::println("{}", numbers);
}

1

[3, 2, 4, 1]

#include <algorithm>
#include <functional>
#include <ranges>
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "short", "loooooooong", "medium"
    };


    auto const longestWordPosition = std::ranges::max_element(
            words, std::ranges::less(), std::ranges::size
    );
    words.erase(longestWordPosition);
    fmt::println("{}", words);
}

1

["short", "medium"]

Zaskakującym może być tutaj użycie std::ranges::less(). Co ma std::ranges::max_element() do std::ranges::less()?

Omawiany algorytm akceptuje dowolny komparator. Może chcemy porównywać std::stringi na podstawie tego, który z nich ma więcej samogłosek? Może chcemy skorzystać z jeszcze bardziej skomplikowanego porównywania?

Dlatego właśnie algorytm ten akceptuje zarówno komparator jak i projekcję. Wszystkie algorytmy, które w jakiś sposób muszą porównywać elementy, domyślnie korzystają z std::ranges::less2. std::ranges::max_element() o tym wie — po prostu zapamiętuje element, który std::ranges::less wskaże jako niemniejszy.
