Przechowywanie unikalnych wartości

Zdarza się, że interesuje nas funkcjonalność przechowywania danych bez duplikatów. Na przykład przechowujemy dane dotyczące imion studentów i chcemy zobaczyć, ile mamy różnych imion. Naturalnie istnieje wysoka szansa, że niektórzy studenci mają tak samo na imię, dlatego trzeba w jakiś sposób przefiltrować duplikaty.

Jednym ze sposobów na osiągnięcie tego celu jest użycie kontenera std::set.

std::set to kontener, który nie pozwala na dodanie do niego duplikatu.

Przykładem użycia std::set jest stworzenie kontenera i dodawanie do niego elementów, a później wyświetlenie jego zawartości:

#include <algorithm>
#include <iostream>
#include <set>

auto main() -> int {
    auto set = std::set<int>();

    for (auto newItem : {3, 2, 1, 1, 2, 3, 5, 4, 3, 2, 1}) {
        set.insert(newItem);
    }

    for (auto element : set) {
        std::cout << element << ' ';
    }
}

Jak widać, nawet dodając wiele identycznych elementów do std::set, kontener ten nie dopuści do sytuacji, w której przechowywałby duplikaty.

Co więcej, warto zauważyć, że kolejność elementów została zmieniona — nie jest zgodna z tą, w której dodawaliśmy liczby do zbioru.

std::set przechowuje swoje elementy w posortowanej kolejności oraz nie dopuszcza do dodania duplikatów.

Są jeszcze dwie rzeczy w omawianym listingu kodu, na które warto zwrócić uwagę:

  1. Aby korzystać z std::set, należy dołączyć odpowiedni nagłówek, tj. #include <set>.
  2. Dodawanie nowych elementów do tworzonego obiektu jest wykonywane w dosyć ciekawy sposób — pętla zakresowa for () iteruje po elementach w nawiasach klamrowych (linijka nr 8). Nazywa się to lista inicjalizacyjna (std::initializer_list), ale nie trzeba się na tym szczególnie koncentrować. To po prostu jeden ze sposobów na wygodną konstrukcję elementów. Co jednak warto wiedzieć, to fakt, że gdy umieszczamy elementy od razu w kontenerze przy pomocy nawiasów klamrowych, jak to było prezentowane przy std::vector, to również używamy właśnie tego elementu języka.

Zamiast używać pętli z listą inicjalizacyjną, można od razu użyć jej bezpośrednio przy inicjalizacji kontenera:

Otrzymywanie unikalnych elementów ze zbioru danych z duplikatami

std::set nie przechowuje duplikatów. Ale co jeżeli mamy jakiś inny zbiór danych (np. std::vector) z duplikatami i chcemy się dowiedziec, ile jest w nim unikalnych wartości?

Efektywnie istnieją dwa proste sposoby na osiągnięcie tego celu — usunięcie duplikatów z oryginalnego zbioru lub utworzenie osobnego kontenera, których ich nie będzie zawierał.

Drugi sposób będzie prostszy (choć nieoptymalny), a zatem zacznijmy od niego.

            "Josuke", "Giorno", "Jolyne",

    auto uniqueNames = std::set<std::string>();

    }
}

Konstruktor zakresowy

Istnieje jednak zwięźlejsza forma kodu zaprezentowanego w poprzednim listingu. Można wykorzystać konstruktor zakresowy, czyli taki, który przyjmuje parę iteratorów do zakresu, z którego będą kopiowane elementy. Dzięki temu można stworzyć std::set na podstawie std::vector bez jawnego korzystania z pętli:

#include <algorithm>
#include <iostream>
#include <set>
#include <string>
#include <vector>

auto main() -> int {
    auto names = std::vector<std::string>{
            "Jonathan", "Joseph", "Jotaro",
            "Josuke", "Giorno", "Jolyne",
            "Jonathan", "Josuke"
    };

    auto uniqueNames = std::set<std::string>(names.begin(), names.end());

    for (auto name : uniqueNames) {
        std::cout << name << ' ';
    }
}

Wynik tego kodu jest identyczny (czyli wyświetlenie tekstu Giorno Jolyne Jonathan Joseph Josuke Jotaro).

Każdy kontener udostępnia konstruktor zakresowy, dzięki któremu można stworzyć zakres danych na podstawie innego.

Przykładowo, można taki wektor przechowujący duplikaty nadpisać nowym wektorem, który będzie stworzony na podstawie zbioru bez duplikatów:

#include <algorithm>
#include <set>
#include <string>
#include <vector>

auto main() -> int {
    auto names = std::vector<std::string>{
            "Jonathan", "Joseph", "Jotaro",
            "Josuke", "Giorno", "Jolyne",
            "Jonathan", "Josuke"
    };

    auto uniqueNames = std::set<std::string>(
            names.begin(), names.end()
    );

    names = std::vector<std::string>(
            uniqueNames.begin(), uniqueNames.end()
    );
}

W taki sposób w oryginalnym wektorze pozostały tylko unikalne imiona. Nie ma w nim żadnych duplikatów.

Jednak z perspektywy wydajności, to rozwiązanie jest średniej jakości. Jest z pewnością relatywnie proste, ale warto przyjrzeć się, co konkretnie robimy, chcąc jedynie usunąć duplikaty ze zbioru:

  1. Tworzymy nowy kontener (uniqueNames typu std::set).
  2. Kopiujemy do niego elementy z oryginalnego wektora (czyli znames, które przechowuje obiekty typu std::string, które z kolei mogą być bardzo długie, przez co ich kopiowanie może zająć dużo czasu oraz wymagać alokacji dużej ilości dodatkowej pamięci).
  3. Tworzymy nowy wektor, do którego znowu kopiujemy elementy (z uniqueNames).
  4. Nadpisujemy oryginalny wektor nowym.

To… zdecydowanie dużo pracy jak na chęć usunięcia duplikatów z oryginalnego kontenera. Na pewno musi istnieć jakiś alternatywny, wydajniejszy sposób.

Na szczęście istnieje — wykorzystuje on algorytm std::ranges::unique().

Usuwanie duplikatów z oryginalnego zbioru przy pomocy std::ranges::unique()

W idealnym świecie std::ranges::unique() mogłoby w optymalny sposób zwyczajnie usunąć duplikaty z przekazanego zakresu. Jest to jednak niemożliwe1.

Jednak dywagacje na temat tego, dlaczego ten algorytm został zaprojektowany tak, a nie inaczej, mogłyby zająć nawet ćwierć wykładu z ASD2. Dlatego nie będziemy się koncentrować na powodach, a jedynie na działaniu.

Podsumowując działanie algorytmu:

Algorytm std::ranges::unique() przesuwa duplikaty z grup sąsiadujących, identycznych elementów na koniec sprecyzowanego zakresu.

Powyższa informacja niewiele daje w kwestii intuicyjnego zrozumienia działania tego algorytmu, więc przejdźmy od razu do praktycznych przykładów. Najprostszym z nich będzie wykonanie tego algorytmu na wektorze przechowującym kilka identycznych elementów:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>(5, 1);

    std::ranges::unique(numbers);

    for (auto element : numbers) {
        std::cout << element << ' ';
    }
}

Uruchamiając powyższy kod, zorientujemy się, że coś jest zdecydowanie nie tak. Efekt nie jest gwarantowany (choć nigdzie nie ma UB), ale przeważnie powyższy kod wyświetla 1 1 1 1 1.

Zanim jednak dowiemy się, dlaczego std::ranges::unique() nie zadziałało nie zrobiło tego, czego oczekiwaliśmy, przyjrzymy się linijce nr 6 z listingu wyżej. Warto zwrócić uwagę, że konstrukcja wektora wykorzystuje składnię (5, 1), a nie {5, 1} (czyli używamy nawiasów okrągłych, a nie klamrowych). Zachowanie {5, 1} jest nam znane — zostałby stworzony wektor z dwoma elementami — piątką oraz jedynką. Zachowanie (5, 1) jest jednak inne (dlatego trzeba zwracać uwagę na nawiasy). Jest to wywołanie dwuargumentowego konstruktora, który zainicjalizuje wektor pięcioma jedynkami.

Chcąc zainicjalizować wektor kilkoma identycznymi elementami, warto rozważyć użycie alternatywnego konstruktora. Zamiast używać std::vector<int>{1, 1, 1, 1, 1} można użyć std::vector<int>(5, 1). Niektóre wybrane kontenery również udostępniają taką funkcjonalność (jak np. std::string, ale już nie std::set).

Wróćmy jednak do algorytmu std::ranges::unique(). Co on zrobił? Dlaczego nie usunął duplikatów?

Przede wszystkim należy pamiętać, że algorytm ten nie usuwa duplikatów. On przenosi je na koniec sprecyzowanego zakresu. Zatem przy wektorze {1, 1, 1, 1, 1}, algorytm “zobaczył” pierwszą jedynkę oraz pozostałe cztery z nich, a następnie te cztery jedynki przesunął na koniec — czyli na ich pierwotne miejsce. Nie zrobił nic.

Brzmi kompletnie bezsensownie. Jak zatem użyć tego algorytmu poprawnie?

Usunąć wszystkie elementy, które oznaczył on jako duplikaty.

Okej, ale jak wiedzieć, które elementy są oznaczone jako duplikaty? Jak je potem usunąć?

Zapisując wartość zwracaną przez algorytm. Zwraca on podzakres — obiekt, który reprezentuje jakiś widok na fragment oryginalnie przekazanego zakresu. Jest to fragment z duplikatami, które należy usunąć.

#include <algorithm>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>(5, 1);

    auto duplicates = std::ranges::unique(numbers);
}

duplicates jest widokiem na cztery ostatnie elementy z numbers3. To dlatego, ze numbers zawiera pięć identycznych elementów. Zatem ma cztery duplikaty do usunięcia.

Fantastycznie. Jak zatem usunąć elementy z numbers, do których referuje duplicates?

Za pomocą metody .erase(). Metoda ta przyjmuje iterator (lub parę iteratorów) do elementów, które chcemy usunąć. Dobrze obrazuje to poniższy listing:

#include <iostream>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>{1, 2, 3, 4, 5, 6, 7};

    for (auto element : numbers) std::cout << element << ' ';
    std::cout << '\n';

    numbers.erase(numbers.begin()); // usuwamy pierwszy element

    for (auto element : numbers) std::cout << element << ' ';
    std::cout << '\n';

    numbers.erase(numbers.end() - 1); // usuwamy ostatni element

    for (auto element : numbers) std::cout << element << ' ';
    std::cout << '\n';

    numbers.erase(numbers.begin() + 1, numbers.begin() + 3);
    
    for (auto element : numbers) std::cout << element << ' ';
}

Najciekawszym fragmentem jest wywołanie metody .erase() z linijki 20. Reszta wywołań powinna zachowywać się intuicyjnie.

Wspomniane wywołanie pracuje na wektorze przechowującym następujące elementy: 2 3 4 5 6. numbers.begin() + 1 wskazuje zatem na liczbę 3 z wektora. numbers.begin() + 3 wskazuje na liczbę 5. .erase(), jak każdy algorytm w C++, pracuje na zakresie prawostronnie otwartym, zatem usunie wszystkie elementy od 3 do 5 (włącznie z 3, ale już nie dotykając 5).

Jak widać, metoda .erase() pozwala na usuwanie elementów z dowolnego miejsca w wektorze (w przeciwieństwie do poznanego wcześniej .pop_back(), która usuwa tylko ostatni). Jej przeciwieństwem jest metoda .insert(), która pozwala na dodawanie elementów w dowolnym miejscu w kontenerze.

Uzbrojeni w te wiedzę wiemy już, jak można usunąć wiele elementów na raz z wektora. Wystarczy teraz uzyskać iteratory na elementy, które obejmuje widok duplicates. Jest to bardzo proste, ponieważ obiekt zwracany przez algorytm std::ranges::unique() posiada metody .begin() oraz .end(), które zwracają iteratory wskazujące na elementy oryginalnego zakresu, którego dotyczyło wywołanie omawianego algorytmu:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>(5, 1);

    auto duplicates = std::ranges::unique(numbers);

    numbers.erase(duplicates.begin(), duplicates.end());

    for (auto element : numbers) {
        std::cout << element << ' ';
    }
}

Wygląda na to, że algorytm nie zrobił nic. Efektywnie to prawda. Zobaczył, że nie ma żadnych duplikatów, które ze sobą sąsiadują, więc nie przesunął nic na koniec. Zwrócony obiekt duplicates składa się z dwóch, identycznych iteratorów, które wskazują na numbers.end(). Wywołanie numbers.erase(numbers.end(), numbers.end()) (albo numbers.erase(x, y), gdzie x i y to iteratory na ten sam element) nie zrobi nic (bo algorytm nie dotyka elementu wskazywanego przez drugi iterator — nieważne, że pierwszy też na niego wskazuje).

Dla ułatwienia przypomnijmy opis algorytmu:

Algorytm std::ranges::unique() przesuwa duplikaty z grup sąsiadujących, identycznych elementów na koniec sprecyzowanego zakresu.

Co teraz? Jak zmusić algorytm do robienia tego, czego intuicyjnie oczekujemy, czyli usunięcia duplikatów niezależnie od tego, gdzie są?

Odpowiadając na to pytanie dosłownie — nie da się.

Nie warto jednak tracić nadziei. To nie tak, że std::ranges::unique() nam nie pomoże. Pomoże, tylko trzeba odpowiednio przygotować dane. Trzeba je przygotować tak, żeby wszystkie identyczne elementy znajdywały się obok siebie. W przypadku wektora numbers z listingu wyżej, trzeba zrobić tak, żeby wszystkie jedynki były obok siebie, wszystkie dwójki były obok siebie i aby wszystkie trójki były obok siebie.

Okazuje się, że najprostszym sposobem na osiągnięcie tego efektu będzie posortowanie danych4:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>{1, 2, 3, 1, 2, 3, 1, 2, 3};

    std::ranges::sort(numbers);
    auto duplicates = std::ranges::unique(numbers);

    numbers.erase(duplicates.begin(), duplicates.end());

    for (auto element : numbers) {
        std::cout << element << ' ';
    }
}

Sukces! W dodatku pełen sukces. Sortowanie danych przed użyciem algorytmu std::ranges::unique() jest bardzo popularną operacją. Zwykle należy dane posortować, użyć algorytmu std::ranges::unique(), a na koniec użyć metody .erase() do faktycznego usunięcia duplikatów.

Jak widać, sortowanie danych i używanie algorytmu std::ranges::unique() jest niewątpliwie bardziej skomplikowane niż użycie kontenera std::set. Niemniej jednak z reguły podejście używające kontenera będzie gorsze pod względem wydajności. Dlatego warto znać obydwa sposoby na osiągnięcie zamierzonego celu.
