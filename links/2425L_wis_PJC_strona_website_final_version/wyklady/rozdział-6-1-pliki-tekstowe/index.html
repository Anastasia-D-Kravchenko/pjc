Opublikowano Apr 7, 2025

Klasa std::fstream

W języku C++ standardowym sposobem na interakcję z plikami jest wykorzystywanie klasy std::fstream. Pozwala ona na czytanie i zapisywanie do pliku tekstowego oraz binarnego. Na ten moment skoncentrujemy się wyłącznie na plikach tekstowych.

Aby czytać z lub zapisywać do pliku tekstowego, należy stworzyć obiekty klasy std::fstream i przekazać mu odpowiednią ścieżkę.

Obiekty tej klasy pozwalają na swojego rodzaju “połączenie” z plikiem. Przykładowo, jeżeli obok pliku wykonywalnego aplikacji będziemy mieli plik data.txt, to stworzenie obiektu std::fstream, który się z nim połączy, może wyglądać następująco:

1
2
3
4
5

#include <fstream>  // std::fstream

auto main() -> int {
    auto file = std::fstream("data.txt");
}

Przejdźmy teraz do wczytywania z i zapisu do takiego pliku.

Czytanie słów z pliku

Aby wczytać dane z pliku, należy mieć je gdzieś zapisać. Dane zapisujemy w obiektach, które zwykle są reprezentowane jako zmienne (lub jako część jakiejś kolekcji).

Z pliku tekstowego zawsze da się wczytać std::string — w końcu pliki tekstowe to nic innego jak jeden wielki zbitek tekstu. Oczywiście ignorujemy tutaj przypadki, gdy plik jest uszkodzony lub pusty.

Aby wczytać std::string z pliku należy wpierw stworzyć odpowiednią zmienną, a później skorzystać z tych samych operacji, co w przypadku input-output streamów, czyli << oraz >>. W tym przypadku interesuje nas >>:

#include <fstream>
#include <string>

#include <fmt/base.h>

auto main() -> int {
    auto file = std::fstream("data.txt");
    auto word = std::string();
    file >> word;

    fmt::println("{}", word);
}

Zakładając, że plik data.txt wygląda następująco:

1

Hello!

To powyższy kod wyświetli następujący output:

1

Hello!

Nic dziwnego — w pliku znajduje się pojedynczy fragment tekstu, który wczytaliśmy przy pomocy operacji file >> word (zupełnie jakbyśmy czytali z std::cin), a następnie go wyświetliliśmy.

Aby wczytać drugie słowo, wystarczy powtórzyć operację czytania. Zakładając taką samą zawartość pliku tekstowego co wcześniej, następujący kod:

#include <string>

#include <fmt/base.h>

auto main() -> int {
    auto file = std::fstream("data.txt");
    auto word = std::string();
    file >> word;
    fmt::println("{}", word);
    file >> word;
    fmt::println("{}", word);

Jak widać, każda kolejna operacja >> wczytuje każde kolejne słowo. Popularnym pytaniem w takich przypadkach jest:

Skąd file wie, że akurat to wywołanie >> powinno wczytać dane (kolejne) słowo?

Obiekty typu std::fstream “pamiętają”, gdzie skończyły ostatnią operację. W środku obiektu file przechowywana jest informacja, gdzie poprzednie operacje (w tym przypadku pierwszy file >> word) zakończyły swe działanie.

auto main() -> int {

W porządku, ale co gdy nie wiemy, ile jest słów w pliku?

Bardzo dobre pytanie. Wtedy też możemy użyć pętli, ale ze zmodyfikowanym warunkiem. Zamiast iterować konkretną liczbę razy, chcemy iterować, dopóki z danego pliku da się wczytać słowo:

Najistotniejszym elementem tego kodu jest umieszczenie operacji wczytywania w warunku pętli. file >> word spróbuje wczytać słowo. Gdy się to uda, file będzie zadowolony. Jeżeli nie (bo np. już wszystkie słowa zostały wczytane), file to zapamięta i będzie informowało, że nie można z niego nic więcej wyczytać.

Operacja file >> word formalnie zwraca referencję do lewego argumentu. Stąd widać, że po wykonaniu operacji czytania (>>), pętla while () otrzymuje w warunku referencję do file. Gdy obiekt typu std::fstream zostanie użyty w kontekście, gdzie oczekujemy wartości logicznej bool, to wygeneruje wartość true, jeżeli wszystko jest w porządku (ostatnia operacja (np. wczytanie słowa) się powiodła). Jeżeli jednak coś poszło nie tak (np. ostatnia operacja (np. wczytanie słowa) nic nie wczytało, bo, przykładowo, nie ma już kolejnych słów w pliku), to wygeneruje wartość false.

Powyższy akapit jest formalnym i nieco skomplikowanym wyjaśnieniem następującego uproszczenia:

while (file >> word) { } oznacza wykonuj ciało pętli, dopóki z file da się wczytać word.

Warto zwrócić uwagę, że gdy zastąpimy file obiektem std::cin, to będziemy wczytywać słowa od użytkownika aż do momentu, gdy nie wprowadzi znaku końca pliku.

Zapis tekstu do pliku

Czytanie zawartości pliku tekstowego niewątpliwie przypomina czytanie danych od użytkownika. W obydwu przypadkach używamy operatora >>. Taką samą analogię możemy zastosować przy zapisywaniu tekstu do pliku oraz wyświetlaniu (przy pomocy std::cout <<).

Poniższy kod, zamiast czytać z pliku, zapisze do niego kilka słów. Wpierw załóżmy, że plik jest pusty:

Nie trzeba się jednak tym martwić. Rozwiążemy ten problem w identyczny sposób, jak to zrobiliśmy z std::cout — użyjemy {fmt}.
Użycie {fmt} wraz z std::fstream
Wyświetlenie wektora na standardowe wyjście z użyciem {fmt} jest bardzo proste:
  
1

fmt::println("{}", std::vector<int>{1, 2, 3});

Zapisanie tekstowej reprezentacji takiego samego wektora (czyli tego, co by wyświetliła powyższa instrukcja, tj. [1, 2, 3]) do pliku, z którym jesteśmy połączeni dzięki std::fstream, jest praktycznie tak samo proste:
  
1

fmt::println(file, "{}", std::vector<int>{1, 2, 3});

Jak widać, wystarczy sprecyzować dodatkowy argument na samym początku — reprezentuje on strumień wyjścia, do którego {fmt} ma wysłać sformatowany tekst.

#include <fstream>
#include <vector>

#include <fmt/ostream.h>    // fmt::print() for std::fstream
#include <fmt/ranges.h>     // formatting ranges

auto main() -> int {
    auto file = std::fstream("data.txt");

    auto numbers = std::vector<int>{1, 2, 3};

    fmt::println(file, "{}", numbers);
}

Poskutkuje on zapisaniem pliku w następującym stanie:

[1, 2, 3]


Warto zwrócić uwagę na dwa istotne fakty:
  1. Na końcu pliku znajduje się pusta linia. To dlatego, że fmt::println() zapisał [1, 2, 3] do pliku, a następnie “dodał” znak nowej linii. Pojawiła się linia nr 2, która jest pusta.
  2. W żadnym z listingów przedstawionych w tym rozdziale nie zamknęliśmy pliku. To dlatego, że o ile std::fstream oferuje metodę .close(), to nie trzeba jej używać, chyba że z jakiegoś powodu chcemy zamknąć plik wcześniej niż moment, gdy obiekt zakończy swoje życie. Dzieje się tak dzięki destruktorom, które będą omówione w dalszej części przedmiotu. Na ten moment wystarczy zapamiętać, że nie trzeba ręcznie zamykać plików w C++.
Nie powinniśmy ręcznie zamykać plików (obiektów typu std::fstream) w C++, chyba że mamy bardzo dobry powód, żeby to zrobić (np. chęć użycia tego samego obiektu do otworzenia innego pliku).
Kolejnym tematem, który należy omówić, jest wielokrotne zapisywanie do pliku. Rozumiemy przez to odwrotną sytuację niż ta, w której czytaliśmy z pliku kilka razy. W tym drugim przypadku std::fstream “zapamiętywał”, gdzie skończyliśmy czytać. Jak to wygląda w kwestii zapisywania do pliku? Przyjrzyjmy się kilku przykładom.

Co się stanie, gdy uruchomimy taki kod?
Zaskakująco, plik będzie wyglądał tak:
  
1

Hello Therext in this file.

Zapisany tekst Hello There zastąpił pierwsze znaki w pliku. Najpewniej spodziewaliśmy się czegoś innego, jak choćby:
  • Dopisania tekstu na koniec pliku.
  • Zastąpienia całej zawartości pliku nowym tekstem, tj. wyczyszczenie jego zawartości i zaczęcie zapisywania elementów poprzez fmt::print().
Ale tak nie było. Domyślnie, std::fstream zaczyna odczytywanie i zapisywanie w tym samym miejscu — na początku pliku.
Możemy to zmienić za pomocą sprecyzowania innych argumentów konstruktora. Precyzuje się je przy pomocy wartości std::ios::openmode
Flagi std::ios::openmode
Gdy stworzymy obiekt std::fstream w następujący sposób:
  
1

auto file = std::fstream("data.txt");

To jest to jednoznaczne ze stworzeniem go w taki sposób:
  
1

auto file = std::fstream("data.txt", std::ios::in | std::ios::out);

To dlatego, że konstruktor std::fstream korzysta z domyślnego argumentu wyglądającego tak, jak zaprezentowano wyżej.
std::ios::in oraz std::ios::out mówią same za siebie — pierwszy reprezentuje sposób działania wspierający czytanie z pliku (input), a drugi zapisywanie do pliku (output). Łącząc je przy pomocy bitowej alternatywy (czyli swojego rodzaju konkatenacji flag bitowych — |) otrzymujemy obiekt, który pozwala na jednoczesne czytanie oraz zapisywanie.
Aby osiągnąć dowolne z alternatywnych zachowań zapisywania do pliku, które zostały wspomniane wyżej, wystarczy podać odpowiednią kombinację flag:

#include <fstream>

#include <fmt/ostream.h>

auto main() -> int {
    auto file = std::fstream("data.txt", std::ios::out | std::ios::trunc);

    fmt::print(file, "{}", "Hello ");
    fmt::print(file, "{}", "There");
