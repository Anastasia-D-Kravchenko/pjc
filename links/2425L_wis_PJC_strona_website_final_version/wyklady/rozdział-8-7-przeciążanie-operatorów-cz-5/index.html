Operatory konwertujące

Ostatnim rodzajem operatorów, którymi się zajmiemy, są operatory konwersji. Jak z większością operatorów, mieliśmy już z nimi do czynienia, tylko tego nie wiedzieliśmy. Konkretnie, przy pracy z plikami tekstowymi, a konkretniej, przy automatyzowaniu wczytywania.

No bo jak to się dzieje, że ten kod wyświetli wszystkie słowa z pliku?

#include <fstream>
#include <string>

#include <fmt/base.h>

auto main() -> int {
    auto file = std::fstream("../data.txt");

    for (auto word = std::string(); file >> word; ) {
        fmt::println("{}", word);
    }
}

Przecież w drugim fragmencie pętli for() (czyli w miejscu, gdzie jest file >> word) musi być wartość logiczna. Jakiś bool, albo chociaż wyrażenie, które zwraca bool.

To dlatego, że wyrażenie file >> word zwraca referencję do file, a file jest typu std::fstream, a z kolei std::fstream (a właściwie klasa bazowa, z której dziedziczy) ma zdefiniowany operator bool. Dzięki temu, gdy coś oczekuje boola, a dostanie std::fstream, to użyje tego operatora, aby — zgodnie z jakąś logiką — sprawdzić, czy ten typ jest w poprawnym stanie.

Taki operator bool zwyczajnie sprawdza, czy stan obiektu jest “poprawny” i jeżeli tak, to zwraca true.

Operatory konwersji potrafią pomagać programiście tworzyć jedne typy z innych. Na przykład:

#include <string>

#include <fmt/base.h>

struct Person {
    std::string name;
    std::string surname;

    operator std::string() const {
        return name + " " + surname;
    }
};

auto main() -> int {
    auto p = Person("Dio", "Brando");
    auto text = std::string(p);
    fmt::println("{}", text);
}

1

Dio Brando

Normalnie nie można stworzyć std::string z obiektu typu Person. No bo jak? std::string nie ma takiego konstruktora.

Ale jednak gdy nasz obiekt wie, jak zmienić się w std::string, to przestaje być to problemem!

W podobny sposób std::fstream umie zamienić się w boola.

Praktycznym przykładem może być abstrakcje reprezentująca piksel składający się z trzech barw — czerwonej, zielonej i niebieskiej:

#include <array>

#include <fmt/ranges.h>

struct Pixel {
    int red;
    int green;
    int blue;

    operator std::array<int, 3>() const {
        return {red, green, blue};
    }
};

auto drawPixel(std::array<int, 3> pixel) -> void {
    fmt::println("drawing: {}", pixel);
}

auto main() -> int {
    auto pixel = Pixel(1, 33, 7);
    drawPixel(pixel);
}

1

drawing: [1, 33, 7]

Można myśleć, że konstruktor mówi o tym, jak dany obiekt ma być tworzony, a operator konwersji mówi, w co obiekt może się zmienić. Koniec końców obydwa te elementy w pewien sposób sterują tworzeniem czegoś na podstawie czegoś innego, ale w pewnym sensie “z różnych stron”.
