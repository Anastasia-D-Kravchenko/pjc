Znajdywanie elementów w kontenerach

Gdy chcemy sprawdzić, czy dany element znajduje się w jakimś kontenerze, mamy dwie opcje do wyboru:

  1. Być smutnym, że używamy C++20, a nie C++23, które dodało std::ranges::contains().
  2. Użyć std::ranges::find().

Skorzystajmy z tej drugiej opcji.

Algorytm std::ranges::find() szuka danego elementu w danym zakresie. Nie zwraca boola, tylko iterator do znalezionego obiektu.

Przykładowe użycie wygląda następująco:

#include <algorithm>
#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto const numbers = std::vector<int>{3, 5, 1, 4, 2};

    auto const iter = std::ranges::find(numbers, 1);

    fmt::println("{}", *iter);
}

Jak się uchronić przed takimi błędami? W jaki sposób można upewnić się, że std::ranges::find() znalazło element?

Należy porównać zwrócony iterator z końcem przekazanego zakresu:

#include <algorithm>
#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto const numbers = std::vector<int>{3, 5, 1, 4, 2};

    auto const iter = std::ranges::find(numbers, 9);

    auto const present = iter != numbers.end();

    if (present) {
        fmt::println("{}", *iter);
    } else {
        fmt::println("No such element");
    }
}

1

No such element

Wyrażenie iter != numbers.end() sprawdza, czy znaleziono jakiś element. Przyjrzyjmy się dokładniej temu, dlaczego tak zostało to zaprojektowane.

Iterator .end()

Jak już wcześniej się dowiedzieliśmy, standardowe algorytmy pracują na zakresach prawostronnie otwartych. Niesie to za sobą kilka korzyści. Aby kontenery poprawnie współpracowały z algorytmami, ich .end() musi zwracać iterator wskazujący na element za ostatnim. Pod .end() nie ma żadnego elementu. Wskazuje on na nieistniejący element. Dlatego jest idealnym kandydatem na wartość sygnalizującą brak jakiegoś elementu.

Szukanie elementów w podzakresach

Co gdy szukamy elementów nie w całym kontenerze, ale w jego fragmentach? Przykładowo wyobraźmy sobie, że użytkownik chce wprowadzić 21 liczb i dowiedzieć się, w ilu kolejno wprowadzonych trójkach znajduje się liczba 0.

Innymi słowy, trzeba wczytać 21 wartości, podzielić je na trzyelementowe grupy i sprawdzić, w ilu takich grupach znajduje się liczba 0.

Najwygodniej byłoby podzielić kontener, od którego wczytamy wszystkie liczby (np. jakiś std::vector) na wspomniane grupy i na każdej z nich wywołać std::ranges::find(), ale przed C++23 nie istnieje wygodny, gotowy sposób na rozwiązanie problemu w ten sposób. Jednak zamiast tego możemy korzystać z iteratorów reprezentujących wspomniane, trzyelementowe grupy jako podzakresy. Przykładowo:

#include <algorithm>
#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto const numbers = std::vector<int>{1, 2, 3, 4, 5, 6, 7};

    auto const iter = std::ranges::find(
            numbers.begin(), numbers.begin() + 3,
            5
    );
}

iter reprezentuje wynik szukania liczby 5 w pierwszych trzech elementach wektora numbers (numbers.begin(), numbers.begin() + 3). Jeżeli takiego elementu nie ma, to std::ranges::find() zwróci koniec zakresu, na którym miał pracować.

Tylko że koniec, w tym przypadku, to nie numbers.end(). To numbers.begin() + 3. To był iterator na koniec (pod)zakresu, na którym miał pracować wywoływany algorytm. Zatem aby sprawdzić, czy w pierwszych trzech elementach znajduje się liczba 5, należy iter porównać z numbers.begin() + 3:

#include <algorithm>
#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto const numbers = std::vector<int>{1, 2, 3, 4, 5, 6, 7};

    auto const iter = std::ranges::find(
            numbers.begin(), numbers.begin() + 3,
            5
    );

    if (iter == numbers.begin() + 3) {
        fmt::println("5 not found in the first three elements!");
    }
}

#include <algorithm>
#include <iostream>
#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto numbers = std::vector<int>(21);

    for (auto i = 0; i < numbers.size(); i++) {
        std::cin >> numbers[i];
    }

    auto zeroCounter = 0;

    for (auto start = numbers.begin(); start != numbers.end(); start += 3) {
        auto end = start + 3;

        auto const iterToZero = std::ranges::find(start, end, 0);

        if (iterToZero != end) {
            zeroCounter += 1;
        }
    }

    fmt::println("There were {} groups with zeros", zeroCounter);
}

Pętla opiera się o zmienną start będącą iteratorem do początku danej trójki elementów, w której szukamy liczby 0. Na razie nieistotne, co się dzieje w ciele samej pętli. Ważne jest, że po tym, jak już sprawdzimy, czy w danej trójce jest liczba 0, to przechodzimy do następnej trójki. Realizujemy to za pomocą przesunięcia iteratora start o trzy miejsca w prawo — przy pomocy start += 3.

Gdy tak “skacząc” dojdziemy do numbers.end(), to wiemy, że skończyły nam się elementy i czas zakończyć pętlę.

Wyszukiwanie najmniejszego i największego elementu w kontenerze

Zdarza się, że interesuje nas, jaka jest najmniejsza liczba w danym wektorze lub jaki jest “największy” znak w danym stringu (czyli najdalsza alfabetycznie litera). Naturalnie trywialnym byłoby znaleźć taki element przy pomocy pętli, ale zdecydowanie lepiej jest skorzystać ze standardowego algorytmu. W tym podrozdziale poznamy cztery z nich:

  • std::ranges::max()
  • std::ranges::max_element()
  • std::ranges::min()
  • std::ranges::min_element()

std::ranges::max() oraz std::ranges::min() zwracają kopię największego lub najmniejszego elementu. Wersje z sufiksem _element() zwracają iteratory.

#include <algorithm>
#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto numbers = std::vector<int>{11, 1, 1111, 111};

    auto const maxNumber = std::ranges::max(numbers);
    auto const maxIter   = std::ranges::max_element(numbers);

    auto const minNumber = std::ranges::min(numbers);
    auto const minIter   = std::ranges::min_element(numbers);

    fmt::println(
            "min: {}\nmax: {}\nminElement: {}\nmaxElement: {}",
            minNumber, maxNumber,
            *minIter, *maxIter
    );
}

Jak widać, przy pomocy zarówno wersji “podstawowej” jak i tej z sufiksem _element() możemy uzyskać najmniejszą czy największą liczbę. Należy jednak zwrócić uwagę, że przy precyzowaniu argumentów, które wyświetlamy, należało użyć dereferencji przy zwróconych iteratorach (linijka nr 18).

Algorytmy z sufiksem _element() brzmią jak niepotrzebne dodatki. Nie dość, że ich nazwa jest dłuższa, to jeszcze trzeba pamiętać o * przy ich użyciu. Po co się je wykorzystuje?

Przede wszystkim trzeba zapamiętać, że dzięki iteratorom unikamy kopiowania potencjalnie dużych elementów. Dają nam one bezpośredni dostęp do znalezionego elementu. Przykładowo, gdybyśmy chcieli zamienić miejscami największy i najmniejszy element, na nic nie zdałby się nam std::ranges::min() czy std::ranges::max():

#include <algorithm>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto numbers = std::vector<int>{11, 1, 1111, 111};

    auto const maxIter = std::ranges::max_element(numbers);
    auto const minIter = std::ranges::min_element(numbers);

    fmt::println("{}", numbers);
    std::ranges::swap(*maxIter, *minIter);
    fmt::println("{}", numbers);
}

2

[11, 1111, 1, 111]

Jak widać, dzięki temu, że iteratory dają nam bezpośredni dostęp do elementów, możemy ich użyć do nadpisania elementów z kontenera. W tym przypadku użyliśmy algorytmu std::ranges::swap(), który zamienia wartości dwóch obiektów.

Gdy mamy do czynienia z iteratorami, to warto rozważyć użycie std::ranges::iter_swap() zamiast std::ranges::swap() wraz z dereferencjami:

1

std::ranges::iter_swap(maxIter, minIter);

Powyższy fragment robi dokładnie to samo, co zaprezentowany wcześniej fragment z “klasyczną” zamianą:

1

std::ranges::swap(*maxIter, *minIter);

Warto jest stosować wersję przeznaczoną dla iteratorów. To dlatego, że trudniej jest się w niej pomylić. Przykładowo, gdybyśmy pominęli dereferencję w oryginalnym przykładzie, czyli zrobili tak:

1

std::ranges::swap(maxIter, minIter);

To nie zmieniłoby to jakkolwiek naszego wektora. Teraz maxIter wskazywałby na najmniejszy element, a minIter na największy. Taki błąd nie jest możliwy przy użyciu std::ranges::iter_swap(), ponieważ jest on przeznaczony tylko do użytku z iteratorami. Próba użycia go z obiektami niebędącymi iteratorami się nie powiedzie:

1

std::ranges::iter_swap(*maxIter, *minIter); // compilation error!

Podsumowując, gdy chcemy zamienić wartościami dwa dowolne obiekty, używamy std::ranges::swap(), ale gdy mamy dwa iteratory i chcemy zamienić wartościami obiekty, na które wskazują, najlepiej jest użyć std::ranges::iter_swap().
