Ogólne problemy z przeciążaniem operatorów

Dotychczas mówiliśmy głównie o plusach przeciążania operatorów. Łatwiejszy do czytania i interpretacji kod, bardziej zwięzłe instrukcje, większa spójność itd.

Przeciążanie operatorów nie jest jednak zbiorem samych plusów. Poza relatywnie dziwną składnią jego używania, mamy również do czynienia z problemami architekturalnymi. Przyjrzyjmy się jednemu z przykładów, który w ramach tego rozdziału stworzyliśmy:

#include <vector>

#include <fmt/ranges.h>

auto operator+(
        std::vector<int> left, std::vector<int> const& right
) -> std::vector<int> {
    left.insert(left.end(), right.begin(), right.end());
    return left;

auto main() -> int {
    auto v1 = std::vector<int>{1, 2, 3};
    auto v2 = std::vector<int>{4, 5};

    fmt::println("{} + {} = {}", v1, v2, v1 + v2);

A konkretniej temu fragmentowi: v1 + v2.

Co tak naprawdę oznacza dodanie dwóch wektorów? Na ten moment może się nam to wydać oczywiste. Jest to konkatenacja (łączenie) — tak samo, jak w przypadku dwóch std::stringów.

Jeżeli jednak spytalibyśmy kogoś wykształconego wyłącznie w dziedzinie matematyki, co oznacza operacja v1 + v2, gdzie v1 i v2 to wektory liczb całkowitych, otrzymalibyśmy (bardzo szybko) zupełnie inną odpowiedź:

Dostajemy nowy wektor, którego elementy są sumą elementów oryginalnych wektorów na korespondujących pozycjach. ~ Kolega matematyk (fizyk).

Oznacza to, że w pewnych dziedzinach dodawanie dwóch wektorów to nie:

1

[1, 2, 3] + [4, 5, 6] = [1, 2, 3, 4, 5, 6]

Tylko:

1

[1, 2, 3] + [4, 5, 6] = [5, 7, 9]

Zwróćmy uwagę, że teraz operacja wymaga, aby obydwa wektory były identycznej długości!

No dobrze, ale to jest troszkę udawany przypadek. Obydwa plusy mają jakiś sens. Wystarczy zobaczyć, których z nich został “wybrany” i to zapamiętać.

No niby tak. Ale co z mnożeniem wektorów? Dot product? Cross product?

#include <compare>

struct Person {

    std::string name;

    auto first  = Person("Joestar", "Jonathan");

    auto compared1 = first < second;
    auto compared2 = (first <=> second) < 0;

Co wyświetla true true.

Cała magia tkwi oczywiście w tym, co zwraca <=> i dlaczego porównujemy to z zerem. W tym momencie warto przypomnieć sobie interface‘y Comparable i Comparator z Javy. Zwracały one int. Jakąś dodatnią wartość, gdy lewy argument miał być uznawany za “większy” od prawego. Jakąś ujemną wartość, gdy lewy argument miał być uznawany za “mniejszy” od prawego. Zwracały one 0, jeżeli obydwa argumenty miały być uznawane za “równe” (ich .equals() dla siebie nawzajem powinien zwracać true).

Uzbrojeni w tę wiedzę, możemy teraz podsumować to, co robi linijka auto operator<=>(Person const& other) const = default;:

Poinstruowanie C++, aby stworzył domyślną implementację operatora <=> (przy pomocy = default), skutkuje stworzeniem takiej implementacji, która wywołuje <=> dla każdego kolejnego pola klasy. W momencie, gdy wynikiem takiej operacji jest coś różnego od 0, ten wynik jest zwracany. W innym przypadku łańcuch takich operacji jest kontynuowany, aż nie skończą się pola. W takiej sytuacji zwracany jest wynik, który porównany do 0 da true.

Podsumowanie nieco zawiłe, więc zaimplementujmy operator<=> ręcznie:

struct Person {
    std::string surname;
    std::string name;

    auto operator<=>(Person const& other) const -> auto {
        auto surnamesCompared = surname <=> other.surname;
        if (surnamesCompared != 0) return surnamesCompared;
        return name <=> other.name;
    }
};

Logika jest dosyć prosta. Sprawdzamy, czy nazwiska są różne. Otrzymujemy “ich różnicę” i zapisujemy w zmiennej surnamesCompared. Gdy jest ona różna od zera, to zwracamy tę informację. Jeżeli jednak one się nie różnią, to zwracamy różnicę imion.

Przypomnijmy sobie pewien problem, na który trafiliśmy wcześniej — domyślnie (= default) wygenerowany operator<=> psuł nam kolejność, bo wpierw porównywał imiona, a potem nazwiska (bo imię było zadeklarowane jako pierwsze w klasie). Implementując ten operator ręcznie, nie musimy się przejmować takimi rzeczami — to my ustalamy logikę porównywania.

Jest tylko… jeden problem. Niezwiązany z kolejnością pól. Jeżeli zaimplementujemy operator<=> ręcznie, to ten kod nie zadziała:

#include <algorithm>
#include <compare>
#include <string>
#include <vector>

#include <fmt/base.h>

struct Person {
    std::string name;
    std::string surname;

    auto operator<=>(Person const& other) const -> auto {
        auto surnamesCompared = surname <=> other.surname;
        if (surnamesCompared != 0) return surnamesCompared;
        return name <=> other.name;
    }
};

auto main() -> int {
    auto people = std::vector<Person>{
            {"Jonathan", "Joestar"},
            {"Joseph", "Joestar"},
            {"Jotaro", "Kujo"},
            {"Josuke", "Higashikata"},
            {"Giorno", "Giovanna"},
            {"Jolyne", "Cujoh"},
            {"Johnny", "Joestar"},
            {"Josuke", "Higashikata"},
            {"Jodio", "Joestar"}
    };

    std::ranges::sort(people);

    for (auto const& person : people) {
        fmt::println("{} {}", person.surname, person.name);
    }
}

Problemem znowu jest std::ranges::sort() i nieusatysfakcjonowany std::totally_ordered_with. Powód?

Jeżeli ręcznie zdefiniujemy operator<=>, to nie wspiera on automatycznego zastępowania ==. Serio…

Czemu?

Bo są przypadki, gdzie byłoby to nieoptymalne. Na przykład <=> dla std::string czy std::vector porównuje element po elemencie, ale == czy != mogą wprowadzić optymalizację i wpierw sprawdzić .size(). Jeżeli się różnią, to na pewno nie są takie same. Operatora <=> nie interesuje .size(), bo wciąż można porównywać leksykograficznie (w std::string oznacza to alfabetycznie) obiekty o różnych wielkościach.

Dodajmy zatem operator==, który też możemy oznaczyć jako = default:

#include <algorithm>
#include <compare>
#include <string>
#include <vector>

#include <fmt/base.h>

struct Person {
    std::string name;
    std::string surname;

    auto operator<=>(Person const& other) const -> auto {
        auto surnamesCompared = surname <=> other.surname;
        if (surnamesCompared != 0) return surnamesCompared;
        return name <=> other.name;
    }

    auto operator==(Person const& other) const -> bool = default;
};

auto main() -> int {
    auto people = std::vector<Person>{
            {"Jonathan", "Joestar"},
            {"Joseph", "Joestar"},
            {"Jotaro", "Kujo"},
            {"Josuke", "Higashikata"},
            {"Giorno", "Giovanna"},
            {"Jolyne", "Cujoh"},
            {"Johnny", "Joestar"},
            {"Josuke", "Higashikata"},
            {"Jodio", "Joestar"}
    };

    std::ranges::sort(people);

    for (auto const& person : people) {
        fmt::println("{} {}", person.surname, person.name);
    }
}
