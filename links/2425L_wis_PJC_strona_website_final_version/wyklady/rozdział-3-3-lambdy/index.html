Znajdywanie elementu na podstawie dowolnego kryterium

W przeszłości poznaliśmy algorytm std::ranges::find(). Przy jego pomocy jesteśmy w stanie znaleźć jakiś element w sprecyzowanym zakresie. Element, który jest równy temu, który podamy w argumencie wspomnianego algorytmu. Bardzo przydatne w momentach, gdy chcemy sprawdzić, czy taki element znajduje się w kontenerze — zwłaszcza jeżeli później chcemy jakoś wpłynąć na ten element. Przykładowo, możemy chcieć usunąć wszystkie liczby o danej wartości z wektora.

Przypomnijmy sobie sposób wykorzystania std::ranges::find() na przykładzie sprawdzenia, czy w danym wektorze znajdują się liczby: 2, 4 lub 6:

#include <algorithm>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto numbers = std::vector<int>{1, 2, 3, 4, 5, 6, 7, 8};

    auto const posOf2 = std::ranges::find(numbers, 2);
    auto const posOf4 = std::ranges::find(numbers, 4);
    auto const posOf6 = std::ranges::find(numbers, 6);

    auto const twoPresent  = posOf2 != numbers.end();
    auto const fourPresent = posOf4 != numbers.end();
    auto const sixPresent  = posOf6 != numbers.end();

    if (twoPresent or fourPresent or sixPresent) {
        fmt::println("2, 4, or 6 is / are present");
    }
}

Kod ten oczywiście wyświetla komunikat z linijki nr 18.

Nie sposób jednak nie zauważyć pewnej wspólnej cechy tych trzech, zaprezentowanych liczb. Są to liczby parzyste.

Załóżmy, że mamy inne zadanie — takie, które nie koncentruje się na liczbie 2, 4 lub 6, tylko na bardziej ogólnym przedstawieniu omawianego problemu:

Jak znaleźć w danym kontenerze liczbę parzystą?

Bardzo prosto. Używając operatora modulo (%):

#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto const numbers = std::vector<int>{1, 3, 5, 6, 7, 8};

    for (auto number : numbers) {
        if (number % 2 == 0) {
            fmt::println("found an even number: {}", number);
            break;
        }
    }
}

found an even number: 6

Wszystko fajnie, ale:

  • Używamy surowej pętli, która wymaga od nas analizy całego jej ciała, żeby być pewnym, co ona tak naprawdę robi.
  • Używamy instrukcji break, którą — o ile można — powinniśmy ograniczać, ponieważ może wprowadzać trudne do analizy przebiegi logiki działania programu. Może nie w tym przykładzie, ale wciąż niektórzy twierdzą, że powinno się jej unikać jak ognia.

Skorzystajmy zatem ze standardowego algorytmu, który jasno zasugeruje, że szukamy liczby, która jest parzysta. Algorytm będzie bliźniaczy do już wspominanego std::ranges::find(). Nazywa się std::ranges::find_if(). Wpierw jednak musimy zrozumieć, co to jest predykat.

Predykaty

Poznaliśmy już komparatory i projekcje. W dalszej części tego rozdziału dokładnie nauczymy się je implementować, choć zaczniemy od innego rodzaju funkcji — od predykatu (ang. predicate).

Predykat to funkcja, która coś testuje. Przyjmuje pojedynczy argument i zwraca true, jeżeli spełnia on jakiś warunek.

Przykładowo, możemy mówić o predykacie parzystości. Byłaby to funkcja, która przyjmuje pojedynczy argument i zwraca true jeżeli jest on parzysty. Jej implementacja mogłaby wyglądać tak:

1
2
3

auto isEven(int const toTest) -> bool {
    return toTest % 2 == 0;
}

isEven() to ewidentnie predykat. Przyjmuje pojedynczego inta i zwraca true, jeżeli jest podzielny przez dwa.

Super, ale jaki to ma związek z std::ranges::find_if()?

Bardzo dobre pytanie. Wpierw jednak odpowiedzmy na inne — jak się wywołuje funkcje?

Za pomocą jej nazwy.

Okej, czyli aby wywołać isEven() trzeba napisać taki kod, tak?

1
2
3

auto main() -> int {
    isEven;
}

Nie… trzeba jeszcze dać nawiasy.

Jasne:

1
2
3

auto main() -> int {
    isEven();
}

No i jeszcze argument.

Mamy to:

1
2
3

auto main() -> int {
    isEven(6);
}

A zatem, aby wywołać funkcję, trzeba:

  • użyć jej nazwy;
  • użyć nawiasów okrągłych;
  • przekazać wszystkie potrzebne argumenty w nawiasach.

Jest to dosyć oczywiste. Dlaczego zatem jest to teraz omawiane?

Dlatego, że pierwszy z tych listingów się skompiluje. Tak, to:

Jest legalnym kodem w C++. Użyliśmy nazwy isEven, ale nic z nią nie zrobiliśmy. To tak samo, jakbyśmy stworzyli jakąś zmienną i użyli jej nazwy bez żadnego kontekstu:

    auto x = 10;
    x;  // tutaj

Za chwilę dojdziemy do konkluzji — obiecuję. Przyjrzyjmy się jeszcze tylko bardzo ważnemu, acz dla większości ponownie oczywistemu, stwierdzeniu:

Przekazujemy zmienne przez argumenty, aby przekazać dane.

Być może jest to std::ranges::sort(). Przekazujemy do niego jakiś wektor. Jakieś dane, które ma posortować.

Być może jest to std::ranges::find(). Przekazujemy do niego jakiś std::set. Jakieś dane, wśród których ma czegoś szukać.

Być może jest to isEven(). Przekazujemy do tej funkcji pojedynczego inta. Jakieś dane, które będą w konkretny sposób weryfikowane.

Wiemy już, jak przekazać do funkcji dane. Ale co w przypadku, gdy chcemy przekazać zachowanie?

std::ranges::find_if() przyjmuje co najmniej dwa argumenty:

  1. Zakres danych, gdzie ma szukać elementu spełniającego warunek.
  2. Instrukcje, według których ma weryfikować, czy dane spełniają warunek.

Jak przekazać zachowanie? Jak przekazać instrukcje? Jak przekazać kod będący logiką warunku?

Przekazując funkcję.

Przekazujemy funkcje przez argumenty, aby przekazać zachowanie.

#include <algorithm>
#include <vector>

#include <fmt/base.h>

auto isEven(int const toTest) -> bool {
    return toTest % 2 == 0;
}

auto main() -> int {
    auto numbers = std::vector<int>{1, 3, 5, 6, 7, 8};

    auto const firstEvenNumberPosition = std::ranges::find_if(numbers, isEven);

    if (firstEvenNumberPosition != numbers.end()) {
        fmt::println(
                "The first even number is: {}",
                *firstEvenNumberPosition
        );
    } else {
        fmt::println("No even numbers found");
    }
}

1

The first even number is: 6

Naturalnie, najbardziej interesującym fragmentem jest inicjalizacja zmiennej firstEvenNumberPosition. Odpowiada za to następujący fragment kodu:

1

std::ranges::find_if(numbers, isEven);

Należy zwrócić szczególną uwagę na fakt, że po nazwie isEven nie występują nawiasy okrągłe precyzujące argumenty. Nie chcemy wywołać tej funkcji. Chcemy ją przekazać. To std::ranges::find_if() będzie jej używało. To ten algorytm będzie przekazywał każde kolejne liczby z numbers do isEven(). Jak tylko isEven() zwróci true, to std::ranges::find_if() zwróci nam iterator do elementu, który właśnie wysłał do tego predykatu. Iterator do elementu, dla którego isEven() zwróciło true. Iterator do elementu, który spełnił przekazany przez nas predykat.

Problemem, który może się kiedyś pojawić, jest fakt, że isEven():

  • jest wywoływane tylko w jednym miejscu w kodzie;
  • jej (pojedyncze) użycie jest relatywnie daleko od implementacji — nie ma sensu implementować funkcji “gdzieś daleko” (załóżmy, że listing kodu jest znacznie większy), gdy jest używana tylko raz — lokalnie.

Powinniśmy jak najbardziej ograniczać zakres widoczności używanych narzędzi. Dlatego nie tworzymy wszystkich zmiennych jako globalne, tylko umieszczamy je w ciałach funkcji. Dlatego nie deklarujemy zmiennych pętli (np. auto i = 0) na początku funkcji, tylko w nawiasach (np. for (auto i = 0; ...)).

Niedobrze. Błąd mówi o tym, że nie możemy definiować funkcji w środku innej funkcji. Co teraz?

Teraz skorzystamy z lambdy.

Lambdy

Jeżeli tworząc funkcję dodamy w odpowiednim miejscu fragment = [], to stanie się coś bardzo ciekawego. Przykładowo:

1
2
3

auto isEven(int const toTest) -> bool {
    return toTest % 2 == 0;
}

Można zmienić na:

1
2
3

auto isEven = [](int const toTest) -> bool {
    return toTest % 2 == 0;
};  // notice the semicolon (;)

Efektywnie dodaliśmy tylko = [] po jej nazwie (oraz średnik na końcu). Co to zmieniło?

Przede wszystkim isEven nie jest już funkcją. isEven jest zmienną. Zmienną, która została zainicjalizowana lambdą.

W środku funkcji nie można definiować innych funkcji. Ale można deklarować i definiować zmienne. Lambda to obiekt, który może zachowywać się jak funkcja. Przykładowo:

1
2
3
4
5

auto main() -> int {
    auto useless = []() -> void { };

    useless();
}

Powyższy kod efektywnie nie zrobi nic. Stworzy obiekt o nazwie useless, który jest lambdą. Literał []() -> void { } tworzy lambdę, która nic nie robi. Taką lambdę można wywołać jak zwykłą funkcję. Gdybyśmy użyli funkcji, to wyglądałoby to tak:

1
2
3
4
5

auto useless() -> void { };

auto main() -> int {
    useless();
}

Lambdy mogą robić wszystko to, co funkcje (i więcej!). Przykładowo oto lambda (wraz z jej użyciem), która wyświetla znany nam wszystkim tekst:

#include <algorithm>
#include <functional>
#include <ranges>
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto const words = std::vector<std::string>{
            "those", "are", "extremely",
            "random", "words", "in",
            "this", "particular", "example"
    };

    auto getSortedCopyByStringLengths = [](std::vector<std::string> copy) {
        std::ranges::sort(copy, std::ranges::less(), std::ranges::size);
        return copy;
    };

    auto const sortedCopy = getSortedCopyByStringLengths(words);

    fmt::println("{}", words);
    fmt::println("{}", sortedCopy);
}

#include <algorithm>
#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto const numbers = std::vector<int>{1, 3, 5, 6, 7, 8};

    auto isEven = [](int toTest) -> bool {
        return toTest % 2 == 0;
    };
    auto const firstEvenNumberPosition = std::ranges::find_if(numbers, isEven);

    if (firstEvenNumberPosition != numbers.end()) {
        fmt::println(
                "The first even number is: {}",
                *firstEvenNumberPosition
        );
    } else {
        fmt::println("No even numbers found");
    }
}

W związku z tym, że lambdy potrafią zachowywać się tak samo, jak funkcje, nic dziwnego, że powyższy kod poprawnie wyświetla The first even number is: 6.

std::ranges::find_if() produkowało poprawny wynik przy pomocy funkcji isEven(). Skoro lambda isEven potrafi się zachować tak samo, jak wspomniana funkcja, to nic dziwnego, że std::ranges::find_if() produkuje tak samo poprawny wynik, gdy z niej korzysta.

Warto jeszcze dodać, że lambdę można użyć od razu w miejscu jej przeznaczenia. To znaczy, zamiast pisać kod tak:

1
2
3
4

auto isEven = [](int const toTest) -> bool {
    return toTest % 2 == 0;
};
auto firstEvenNumberPosition = std::ranges::find_if(numbers, isEven);

Można napisać go tak:

1
2
3
4
5

auto firstEvenNumberPosition = std::ranges::find_if(
        numbers, [](int const toTest) -> bool {
            return toTest % 2 == 0;
        }
);

Podsumowując, lambdy pozwalają na ominięcie problemu braku możliwości definiowania funkcji w funkcjach. Tworzą obiekty, które mogą zachowywać się jak funkcje.
