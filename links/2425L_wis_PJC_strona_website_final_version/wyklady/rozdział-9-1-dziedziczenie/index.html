Idea dziedziczenia

Dziedziczenie zwykle wprowadza się jako sposób na uniknięcie duplikacji kodu przy tworzeniu nowych typów. Przykładowo, mając prosty szablon Pair:

template <typename T, typename U>
struct Pair {
    T x;
    U y;
};

Widzimy, że patrząc na klasy Point oraz Pixel:

struct Point {
    double x;
    double y;
};

struct Pixel {
    int x;
    int y;
};

Ewidentnie mamy do czynienia z jakimś rodzajem duplikacji kodu. Mimo tego, że typy są inne, to jednak nazwy ich pól i przeznaczenia tych pól są takie same.

Dzięki dziedziczeniu można uniknąć wielokrotnego powtarzania deklaracji tych pól:

template <typename T, typename U>
struct Pair {
    T x;
    U y;
};

struct Point : Pair<double, double> { };

struct Pixel : Pair<int, int> { };

W języku C++ dziedziczenie oznaczamy dwukropkiem (:), a nie jakimś słowem kluczowym (jak np. w Javie, gdzie używamy extends).

Przykładowo struct A : B { }; mówi, że tworzona klasa A dziedziczy z klasy B.

W wielu językach dziedziczenie jednocześnie reprezentuje relację “bycia” czymś. Przykładowo, jeżeli klasa Cat dziedziczy z Animal, to oznacza to, że kot jest w pewnym sensie zwierzęciem. Przykładowo w Javie pozwalało to na tworzenie tablicy Animal i umieszczanie w niej obiektów typu Cat. Taki mechanizm również pozwalał na polimorficzne wywoływanie metod.

W języku C++ dziedziczenie niekoniecznie implikuje relację “być”. Dodatkowo dziedziczenie wcale nie musi sugerować użycia (ani nawet pozwalać na użycie) polimorfizmu.

Dziedziczenie publiczne

Najczęściej spotykanym dziedziczeniem w obecnych aplikacjach napisanych w językach obiektowych jest dziedziczenie publiczne. Znamy je już z Javy. Gdy struktura po czymś dziedziczy, to dziedziczy publicznie. Jeżeli jednak chcemy, aby klasa publicznie dziedziczyła, to musimy to sprecyzować używając słowa kluczowego public:

// example that uses `struct`
namespace strukt {
    struct Base { };
    
    struct Derived : Base { };
}

// example that uses `class`
namespace clazz {
    class Base { };

    class Derived : public Base { };
}

Dziedziczenie publiczne to takie, do którego jesteśmy przyzwyczajeni. Reszta programu “wie”, że Derived dziedziczy po Base. Gdy funkcja oczekuje argumentu Base, można tam wysłać obiekt Derived. Gdy Base składa się z pól i metod, to Derived je odziedziczy i, o ile nie są one prywatne, będzie mogła z nich bezpośrednio korzystać.

Warto zwrócić uwagę, że dziedziczenie publiczne jest wymagane, gdy chcemy polimorficznie wywoływać nadpisane metody z perspektywy zmiennej typu bazowego. To dlatego, że jeżeli reszta programu “nie wie”, że jakaś klasa dziedziczy z innej, to oczekując obiektu tej innej klasy, nie przyjmiemy obiektu klasy dziedziczącej.

Dziedziczenie prywatne

Dziedziczenie prywatne nie występuje w Javie. Jest to sposób na uzyskanie tej samej funkcjonalności, co inna klasa, bez informowania “reszty świata” o tym, że jakiekolwiek dziedziczenie ma miejsce. Przykładowo, możemy chcieć prywatnie dziedziczyć z std::vector:

#include <vector>

#include <fmt/base.h>

struct MyVector : private std::vector<int> {
    auto add(int const n) -> void {
        push_back(n);
    }

    auto print() const -> void {
        for (auto b = begin(); b != end(); ++b) {
            fmt::print("{} ", *b);
        }
    }
};

auto main() -> int {
    auto v = MyVector();
    v.add(1);
    v.add(2);
    v.add(3);
    v.print();
}

Nie możemy jednak w takim przypadku wysłać obiektu typu MyVector w miejsce, które oczekuje std::vector<int>. To dziedziczenie odpowiada wyłącznie za delegowanie implementacji części elementów do innej klasy, a nie za reprezentację relacji “być” czy za udostępnienie zachowania polimorficznego.
