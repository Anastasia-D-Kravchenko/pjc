Skrócony zapis szablonu funkcji

Przyjrzyjmy się ponownie szablonowi z poprzedniej części rozdziału:

template <typename T, typename U>
auto printBigger(T const& first, U const& second) -> void {
    if (first > second) {
        std::cout << first;
    } else {
        std::cout << second;
    }
    std::cout << '\n';
}

W przypadku gdy placeholdery typów są używane w tak prosty sposób (później dowiemy się, jaki to jest nieprosty sposób), można je zastąpić składnią o nazwie skrótowy szablon funkcji (ang. abbreviated function template). Stosuje się w tym celu słowo kluczowe auto. Kod z listingu wyżej można zapisać w następujący sposób:

1

auto printBigger(auto const& first, auto const& second) -> void {
    if (first > second) {
        std::cout << first;
    } else {
        std::cout << second;
    }
    std::cout << '\n';
}

Jak widać, jest to ewidentnie prostszy sposób. Pomijamy jakieś wymyślne template czy typename. Dlaczego zatem zaczęliśmy od tego trudniejszego sposobu tworzenia szablonów? Są dwa powody:

  1. Częściej używa się notacji template <...> z uwagi na to, że notacja z auto nie pozwala na wiele przydatnych konstrukcji1.
  2. Mając wprowadzony typename T, a konkretnie placeholder T, łatwiej jest pojąć ideę “dopasowania”, zwłaszcza w przypadku argumentów różnego typu.

Ograniczenia płynące ze stosowania skrótowych szablonów

Jak już zostało to wcześniej wspomniane, auto, które zastępuje składnię template <...>, ma pewne ograniczenia. W poprzedniej części rozdziału, w przypadku omawianego szablonu printBigger(), zastosowaliśmy dwa placeholdery (typename T, typename U) w celu zezwolenia na to, aby szablon akceptował argumenty różnych typów.

Co jednak, gdy chcemy wymusić przyjmowanie dwóch argumentów tego samego typu? Na przykład chcemy uniknąć wszelkiego rodzaju konwersji (zarówno w ciele) i mieć gwarancję, że argumenty mają dokładnie ten sam typ. Stosując “oryginalną” notację szablonów jest to bardzo proste:

1
2

template <typename T>
auto acceptsTwoSameTypeArguments(T first, T second) -> void { }

Jednak jest to niemożliwe bardzo trudne do osiągnięcia przy stosowaniu auto.

W takich sytuacjach należy rozważyć stosowanie klasycznego sposobu tworzenia szablonów.

Lambdy a szablony

Jak już wiemy, lambdy mają unikalny, nieznany nam typ. Jak to zatem jest, że taki algorytm jak std::ranges::count_if() jest w stanie przyjąć lambdę? Przecież, aby napisać funkcję, która przyjmuje jakiś argument, trzeba sprecyzować jego typ, prawda?

Prawda. Tylko że std::ranges::count_if() nie jest funkcją. Jest szablonem funkcji2. Wprowadza placeholder typu, który akceptuje dowolny zakres oraz drugi placeholder typu, który akceptuje predykat. Predykat, który może być dowolnego typu.

Aby dokładniej zrozumieć przykład, zaimplementujmy nasz własny count_if():

#include <vector>

#include <fmt/ranges.h>

namespace pjc {
    template <typename T>
    auto count_if(std::vector<T> const& source, auto const predicate) -> int {
        auto counter = 0;

        for (auto const& element : source) {
            if (predicate(element)) {
                counter += 1;
            }
        }

        return counter;
    }
}

auto main() -> int {
    auto const ints  = std::vector<int>{1, 2, 3, 4, 5};
    auto const count = pjc::count_if(ints, [](int const i) { return i % 2 == 0; });
    fmt::println("{}", count);
}

Aby nasz count_if() nie kolidował nazwą z std::ranges::count_if(), umieściliśmy go w nowo stworzonej przestrzeni nazw pjc. Jego implementacja jest bardzo prosta:

  • Stosujemy template <typename T> do wprowadzenia placeholdera T, który będzie użyty jako typ elementu przyjmowanego wektora, aby móc przyjmować dowolny wektor. Musimy tak to zrobić, bo nie możemy napisać std::vector<auto>. Później, używając skróconego zapisu, wprowadzamy parametr będący predykatem.
  • Iterujemy po wszystkich elementach źródłowego wektora i jeżeli jakiś element spełnia przyjęty predykat (wywołany predykat z tym argumentem zwróci true), zwiększamy licznik o 1.
  • Zwracamy licznik.

Tak naprawdę większość elementów z biblioteki standardowej języka C++ to szablony. Są one uznawane za jeden z najważniejszych elementów języka. Często w Internecie można się spotkać ze skrótem STL, czyli Standard Template Library.

Szczegóły działania szablonów w STL

Po zapoznaniu się z powyższym przykładem z pewnością może nasunąć się kilka ważnych pytań:

std::ranges::count_if() działa nie tylko z wektorami, ale też i z std::set czy choćby z samym std::string. Nasz pjc::count_if() przyjmuje tylko wektor. Dlaczego?

Dla uproszczenia. Oczywiście można by zamiast:

1
2

template <typename T>
auto count_if(std::vector<T> const& source, auto const predicate) -> int { ... }

Zrobić:

1

auto count_if(auto const& source, auto const predicate) -> int { ... }

W takiej sytuacji source mogłoby być dowolnym kontenerem. W podobny sposób działają narzędzia biblioteki standardowej — bardzo rzadko przyjmują konkretny typ.

Ale skąd w takiej sytuacji wiemy, że ktoś poda jako pierwszy argument jakiś kontener? Co stoi na przeszkodzie, żeby wywołać ten count_if() z, przykładowo, intem a nie wektorem intów? A skoro już przy tym jesteśmy, to w sumie co zabrania użytkownikowi podać jako predicate nie lambdę, nie funkcję, a też coś kompletnie bezsensownego, np. int? Co się stanie, jeżeli spróbujemy użyć szablonu tak:

1
2
3

auto const notRange     = int();
auto const notPredicate = int();
pjc::count_if(notRange, notPredicate);

Bardzo dobre pytanie, a odpowiedź całkiem prosta — kod się nie skompiluje. Warto jednak się przyjrzeć temu, dlaczego tak jest. Otóż nic nie stoi na przeszkodzie, żeby nagłówek auto count_if(auto& source, auto predicate) -> int pozwolił na to, aby source oraz predicate były intami. Problem w tym, że w ciele funkcji mamy następujący kod:

1
2
3

for (auto const& element : source) {
    if (predicate(element)) {
        counter += 1;
    }
}

Serdeczne wyrazy współczucia każdemu, kto spróbował zrozumieć, jak kompilator próbuje nam “pomóc”. Istotny fragment mówi o tym, że:

  • Zakresowa pętla for () wymaga… zakresu. int nie jest zakresem, bo nie można na nim wywołać .begin() (lub przekazać go do wolnej funkcji begin()).
  • predicate nie może być użyty jako funkcja. No tak, w końcu to int.

Czyli jedyne istotne fragmenty to sam początek i sam koniec błędu.

Tak kryptyczne błędy kompilacji są niestety codziennością przy pracy z szablonami. Są to bardzo potężne, ale też i bardzo trudne w analizie narzędzia, dlatego kompilatory czasem nie dają rady zwrócić czytelnych i dobrych błędów.

  1. Tak naprawdę, gdyby zastosować odpowiednie, dodatkowe narzędzia, to za pomocą auto da się osiągnąć mniej więcej to samo, co za pomocą template <...>, ale z uwagi na skalę trudności tych manewrów, można skorzystać z przybliżenia, że korzystanie z tej bardziej wymownej wersji pozwala na więcej. ↩

  2. Tak naprawdę jest niebloidem, ale jeżeli ktoś nie wie, co to znaczy, to śmiało może myśleć o std::ranges::count_if() jako o zwykłym szablonie funkcji. ↩
