Komparator

Co może być skomplikowanego w std::ranges::less? Jak trudne może być zrozumienie tego, co tak naprawdę kryje się pod zaprezentowanym niżej wywołaniem?

1

std::ranges::sort(someRange, std::ranges::less());

Aby odpowiedzieć na to pytanie, musimy się dokładnie zapoznać z tym, jak działają komparatory.

W C++ komparator przyjmuje dwa parametry i zwraca bool. Jeżeli, według jakiegoś ustalonego warunku, lewy argument powinien być uznawany za “mniejszy”, to komparator zwraca true. Jeżeli obydwa argumenty uznajemy za identyczne lub prawy z nich powinien być “pierwszy”, to komparator zwraca false.

W bardzo dużym uproszczeniu (oraz założeniu, że mamy do czynienia z zakresem typu std::vector<std::string>), powyższe wywołanie jest równe następującemu:

1
2
3

std::ranges::sort(words, [](std::string const& left, std::string const& right) {
   return left < right;
});

Wyrażenie left < right wywołuje odpowiednią implementację operatora < dla typów std::string, który zwróci true, jeżeli lewy operand jest mniejszy leksykograficznie. Z jednej strony ma to sens, z drugiej nie za bardzo pomaga w intuicyjnym zrozumieniu, jak powinniśmy tworzyć komparatory. Przyjrzymy się problemowi z drugiej strony i pokażmy, jak wygląda sprawa z std::ranges::greater:

1

std::ranges::sort(someRange, std::ranges::greater());

1
2
3

std::ranges::sort(words, [](std::string const& left, std::string const& right) {
   return left > right;
});

std::ranges::greater reprezentuje logikę, która wpierw porządkuje “większe” elementy.

Jak widać wyżej, można czasem pomijać precyzowanie typu zwracanego przez lambdy. Przez funkcję też. Brak sprecyzowania zwracanego typu (np. brak -> void czy -> bool) spowoduje, że kompilator spróbuje samemu go dopasować patrząc na instrukcję return. Brak returna będzie implikował zwracanie void. Warto zwrócić uwagę na fakt, że nie działa to w momencie, gdy rozdzielamy deklarację od definicji funkcji. Domyślnie powinniśmy zawsze precyzować typ zwracany “normalnych” funkcji.

Efektywnie nasze komparatory różnią się tylko w jednym miejscu. Tylko jednym znakiem. Operator < a operator >. left < right a left > right.

Na początek trudno jest znaleźć intuicyjny sens w tym zachowaniu, więc spróbujmy spojrzeć na to z perspektywy algorytmu std::ranges::sort(). Dla niego komparator to narzędzie, które wykorzystuje poprzez wysyłanie mu dwóch obiektów pobranych z zakresu, który sortuje. Jeżeli komparator powie true, to “lewy” obiekt powinien być przed “prawym”. Jeżeli powie false, to “prawy” obiekt powinien być przed “lewym”.

Zobaczmy, co powie powyższy komparator na następujące wywołanie:

#include <string>

#include <fmt/ranges.h>

auto main() -> int {
    auto const comparator = [](std::string const& left, std::string const& right) {
        return left > right;
    };

    auto const left  = std::string("hello");
    auto const right = std::string("there");

    fmt::println("{}", comparator(left, right));
}

1

false

Gdy comparator otrzymuje "hello" jako lewy argument oraz "there" jako prawy argument, zwraca on false. Oznacza to, że "hello", według tego komparatora, nie jest mniejsze od "there".

#include <algorithm>
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "hello", "there", "and", "welcome"
    };

    std::ranges::sort(words, [](std::string const& left, std::string const& right) {
       return left.size() < right.size();
    });

    fmt::println("{}", words);

    std::ranges::sort(words, [](std::string const& left, std::string const& right) {
        return left.size() > right.size();
    });

    fmt::println("{}", words);
}

#include <algorithm>
#include <ranges>
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "hello", "there", "and", "welcome"
    };

    std::ranges::sort(words, std::ranges::less(), [](std::string const& s) {
        return s.size();
    });

    fmt::println("{}", words);

    std::ranges::sort(words, std::ranges::greater(), [](std::string const& s) {
        return s.size();
    });

    fmt::println("{}", words);
}

Funkcje transformujące

Funkcje transformujące niewiele się różnią od projekcji. Przyjmują jakiś argument i zwracają coś innego — wyliczonego na podstawie tego argumentu. Zwykle się je stosuje wraz z algorytmem std::ranges::transform():

#include <algorithm>
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "hello", "there", "and", "welcome"
    };

    auto const capitalize = [](std::string copy) {
        auto const differenceBetweenLowerAndUpperCase = 'a' - 'A';
        copy.front() -= differenceBetweenLowerAndUpperCase;
        return copy;
    };

    fmt::println("{}", words);
    std::ranges::transform(words, words.begin(), capitalize);
    fmt::println("{}", words);
}

1
2

["hello", "there", "and", "welcome"]
["Hello", "There", "And", "Welcome"]

capitalize jest lambdą, która przyjmuje jakiś tekst przez kopię, zakłada, że zaczyna się on małą literą, a następnie modyfikuje jego pierwszy element tak, żeby był on wielką literą.

Algorytm std::ranges::transform() w formie pokazanej wyżej przyjmuje poza funkcję transformującą jeszcze dwa argumenty — zakres źródłowy oraz iterator na elementy, która ma nadpisywać. W tym przypadku nadpisujemy “źródło”. Można jednak produkować zupełnie inne wartości. Załóżmy, że mając wektor słów, chcemy otrzymać inny wektor, który będzie się składał z ich długości:

#include <algorithm>
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "hello", "there", "and", "welcome"
    };

    auto lengths = std::vector<int>(words.size());
    
    std::ranges::transform(words, lengths.begin(), [](std::string const& s) {
        return s.size();
    });
    fmt::println("{}", lengths);
}

1

[5, 5, 3, 7]

Zamiast “ręcznej” projekcji można by oczywiście użyć std::ranges::size — w końcu jest to obiekt-funkcja (taka trochę lambda, ale nie do końca…), która pobiera jakiś obiekt i zwraca jego wielkość (.size()).
