Wskaźniki

Wskaźniki wprowadzają sporo zamieszania składniowego. Czy fakt, że są one wymagane przy dynamicznej alokacji pamięci, jest jedynym powodem, dlaczego się je stosuje?

Nie. Wskaźnik pozwala na nieco więcej rzeczy. Na przykład na referowanie do wielu różnych obiektów w czasie swojego życia.

Jeden wskaźnik referujący do wielu obiektów

Wskaźniki można przepinać tak, aby mogły wskazywać na różne dane w czasie swojego życia. Nie można było tego osiągnąć przy pomocy referencji:

#include <fmt/base.h>

auto main() -> int {
    auto x   = 10;
    auto y   = 20;
    auto ptr = &x;
    fmt::println("{}", *ptr);
    ptr = &y;
    fmt::println("{}", *ptr);

    *ptr /= 10;
    ptr = &x;
    *ptr /= 10;

    fmt::println("{} {}", x, y);
}

W powyższym przykładzie mamy do czynienia z dwoma intami — x oraz y. Przy pomocy pojedynczego wskaźnika ptr wyświetlamy wartości obydwu tych intów. Osiągamy to dzięki przypisaniu do ptr adresu pamięci obiektu x (przy pomocy ptr = &x) i dzięki późniejszemu przypisaniu do ptr adresu pamięci obiektu y (przy pomocy ptr = &y).

Składnia używania wskaźników jest niewątpliwie dosyć skomplikowana, więc przyjrzyjmy się pozornie podobnym przykładom i wyjaśnijmy różnice między nimi.

Tak wygląda nadpisanie samego wskaźnika
1

ptr = ...;
Tak wygląda nadpisanie obiektu, na który wskazuje wskaźnik
1

*ptr = ...;

Jeżeli nadpisujemy sam wskaźnik, to zmieniamy adres w pamięci, który przechowuje. Wtedy wskazuje on na inny obiekt.

Przykładowo, przyglądając się zawartości pamięci naszego programu przy wywołaniu następujących operacji:

1

auto main() -> int {
    auto x   = 10;
    auto y   = 20;
    auto ptr = &x;
    ptr = &y;
}

Wpierw, w linijkach 2 i 3 tworzone są dwa inty:

Później tworzymy ptr i zapisujemy w nim adres w pamięci obiektu x. Sprawia to, że ptr wskazuje na x:

  PTR(ptr) --> X

Jeżeli jednak nadpisujemy obiekt, na który wskazuje wskaźnik, to adres przechowywany przez wskaźnik się nie zmienia. Zmienia się tylko zawartość obiektu, na który wskazuje.

Rozważmy taki przykład:

auto main() -> int {
    auto x   = 10;
    auto ptr = &x;
    *ptr = 20;
}

Tutaj rozkład pamięci jest jeszcze prostszy:

  PTR(ptr) --> X("x<br/>⠀10⠀")

Następnie, operacja *ptr = 20 sprawi, że pamięć będzie wyglądała tak:

graph LR
  PTR(ptr) --> X("x<br/>⠀20⠀")

Wskaźniki a referencje

Nie zauważymy różnicy między bezpośrednim nadpisaniem obiektu a nadpisaniem obiektu przy użyciu referencji lub wskaźnika. Mając:

    auto x = 10;
    auto y = 20;
