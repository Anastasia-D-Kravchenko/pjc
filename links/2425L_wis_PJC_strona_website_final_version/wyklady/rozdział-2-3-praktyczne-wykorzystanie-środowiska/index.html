#include <iostream>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>{1, 2, 3, 4, 5, 6, 7};

    for (auto element : numbers) std::cout << element << ' ';
    std::cout << '\n';

    numbers.erase(numbers.begin()); // removing the first element

    for (auto element : numbers) std::cout << element << ' ';
    std::cout << '\n';

    numbers.erase(numbers.end() - 1); // removing the last element

    for (auto element : numbers) std::cout << element << ' ';
    std::cout << '\n';

    numbers.erase(numbers.begin() + 1, numbers.begin() + 3);
    
    for (auto element : numbers) std::cout << element << ' ';
}

Prezentował on mechanizm działania metody .erase(), ale nie na tym się będziemy teraz koncentrować. Skoncentrujemy się na innym, powtarzalnym fragmencie kodu. Na wyświetlaniu zawartości kontenera numbers.

W tym momencie z pewnością bardzo frustrującą cechą języka C++ jest to, że nie da się w wygodny sposób wyświetlić zawartości kontenera (chyba że to std::string, ale z oczywistych powodów jest on wyjątkiem). Poniższy kod się nie skompiluje:

#include <iostream>
#include <vector>

auto main() -> int {
    auto numbers = std::vector<int>{1, 2, 3, 4, 5, 6, 7};

    std::cout << numbers << '\n';
}

Istnieje oczywiście sposób na dopisanie kodu, dzięki któremu będzie można używać std::vector (lub praktycznie dowolnego kontenera) z std::cout, ale po co mamy to robić, skoro:

  1. jest to bardzo trudne;
  2. korzysta to z elementów, których jeszcze jakiś czas nie poznamy;
  3. już ktoś to kiedyś zrobił.

Skorzystajmy zatem z gotowego rozwiązania, które dołączymy do naszego projektu. Naszym celem będzie skorzystanie z biblioteki {fmt}, dzięki której będziemy mogli skompilować poniższy kod:

#include <fmt/ranges.h> // for printing ranges (containers, collections, etc.)

auto main() -> int {
    auto numbers = std::vector<int>{1, 2, 3, 4, 5, 6, 7};

    fmt::println("{}", numbers);
}

CMake

O CMake było już trochę powiedziane w rozdziale dotyczącym wprowadzenia do C++. Jest to narzędzie do automatyzacji budowania projektów — między innymi C++owych. Jego ogromnym plusem jest popularność i stopień adaptacji.

Dla osób, które wiedzą, czym jest Javowy Maven, to można myśleć o CMake jako o C++owej wersji Mavena.

Dużym plusem Mavena jest możliwość pobierania i konfiguracji zewnętrznych zależności — na przykład bibliotek programistycznych, które pomagają programiście w lepszym osiągnięciu celu.

Pobieranie i konfiguracja zewnętrznej zależności

Gotowe biblioteki programistyczne mają wiele zalet, między innymi:

  • Oszczędzanie czasu. Zamiast spędzać czas i wysilać się przy tworzeniu jakiegoś narzędzia, można skorzystać z gotowej biblioteki napisanej przez kogoś innego.
  • Przemyślana architektura. Tworząc nowe narzędzie samemu, często możemy zapomnieć o jakiś małych detalach, które będą problematyczne w przyszłości. Gdy jakaś biblioteka jest publikowana i coraz to więcej osób zaczyna z niej korzystać, te osoby jednocześnie zgłaszają propozycje usprawnień tej biblioteki.
  • Przetestowanie. Im popularniejsza biblioteka i im więcej osób z niej korzysta, tym większa pewność, że jest ona niezawodna.

W związku z tym warto poznać chociażby jeden sposób na integrację zewnętrznej biblioteki z naszymi projektami w C++.

Komendy FetchContent

Dotychczas nasz plik CMakeLists.txt wyglądał mniej więcej tak:

4
5

cmake_minimum_required(VERSION 3.26)
project(PJC)

set(CMAKE_CXX_STANDARD 20)

add_executable(Main main.cpp)

Dla przypomnienia:

  • Komenda cmake_minimum_required() wraz z argumentem VERSION informuje, której wersji CMake używamy. W tym przykładzie jest to wersja 3.26, ale jeśli ta liczba delikatnie odbiega od naszej domowej konfiguracji, to nie będzie to problematyczne — wystarczy ją skorygować zgodnie z informacją podaną w ewentualnym błędzie.
  • Komenda project() precyzuję nazwę projektu, której można potem używać (dla nas nieistotne w tym momencie).
  • Komenda set() wraz z argumentem CMAKE_CXX_STANDARD ustawia wersję języka C++ naszego projektu na C++20, ponieważ użyliśmy argumentu 20.
  • Komenda add_executable() tworzy nam plik wykonywalny (.exe na Windowsie, a na Unixowych systemach plik z możliwością uruchomienia). W tym przypadku tworzymy plik o nazwie Main(.exe), który bazuje na pliku z kodem w C++ o nazwie main.cpp.

Wspomniana już wcześniej biblioteka fmt została napisana w konfiguracji z CMake oraz opublikowana na portalu GitHub. Oznacza to, że dzięki bardzo prostej komendzie z rodziny komend FetchContent będziemy mogli ją pobrać i dołączyć do projektu.

Aby użyć FetchContent należy wpierw dołączyć je do naszego pliku za pomocą komendy include(). Działa ona podobnie do C++owego #include:

1
2
3

cmake_minimum_required(VERSION 3.26)
project(PJC)

set(CMAKE_CXX_STANDARD 20)

include(FetchContent)   # here

add_executable(Main main.cpp)

Następnie użyjemy trzech komend:

  1. FetchContent_Declare();
  2. FetchContent_MakeAvailable();
  3. target_link_libraries().

FetchContent_Declare() sprecyzuje, co i skąd chcemy pobrać. Będzie to biblioteka {fmt} pobierana z linku do GitHuba w wersji 11.0.2.

Aby FetchContent mógł pobrać zależność z repozytorium GitHub, trzeba mieć zainstalowane na komputerze narzędzie Git.

FetchContent_MakeAvailable() pobierze i zbuduje sprecyzowaną przez FetchContent_Declare() zależność (bibliotekę fmt w odpowiedniej wersji).

target_link_libraries() połączy1 zbudowaną bibliotekę z naszym plikiem wykonywalnym stworzonym przez add_executable().

cmake_minimum_required(VERSION 3.26)
project(PJC)

set(CMAKE_CXX_STANDARD 20)

FetchContent_Declare(
        fmt
        GIT_REPOSITORY  https://github.com/fmtlib/fmt
        GIT_TAG         11.0.2
)

FetchContent_MakeAvailable(fmt)

add_executable(Main main.cpp)
target_link_libraries(Main fmt)

Bardzo istotna jest kolejność komend. Nie możemy użyć FetchContent_XYZ() przed include(FetchContent). Nie możemy zbudować biblioteki przy pomocy FetchContent_MakeAvailable() bez deklaracji, co chcemy budować (FetchContent_Declare()). Nie możemy dołączyć zbudowanej biblioteki przy pomocy target_link_libraries() bez wcześniejszego zbudowania jej oraz bez wcześniejszego stworzenia celu (ang. target — reprezentuje coś tworzonego przez nasz projekt — w naszym przypadku jest to plik wykonywalny Main).

Po modyfikacji pliku CMakeLists.txt często zdarza się, że zmiany nie są widoczne w projekcie. Dzieje się tak, gdy programista zapomina załadować zmian konfiguracyjnych. W prawym górnym rogu IDE (patrząc na plik CMakeLists.txt) powinien pojawić się komunikat sugerujący załadowanie zmian z odpowiednim przyciskiem. Alternatywnie można skorzystać ze skrótu klawiszowego Ctrl+Shift+O.

Tak przygotowana konfiguracja powinna odpowiednio pobrać, zbudować i przygotować bibliotekę {fmt} do użycia z naszym projektem.

Biblioteka {fmt}

Biblioteka {fmt} służy do ułatwienia pracy z wyświetlaniem tekstu (albo z wysyłaniem go do plików) w aplikacjach C++owych. Wspomnieliśmy już kiedyś, że z std::cout jest wiele problemów. To prawda — dlatego powstała bardzo dobra alternatywa w postaci biblioteki, którą właśnie dołączyliśmy do projektu.

#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto numbers = std::vector<int>{1, 2, 3, 4, 5, 6, 7};

    fmt::println("{}", numbers);

    numbers.erase(numbers.begin()); // removing the first element

    fmt::println("{}", numbers);

    numbers.erase(numbers.end() - 1); // removing the last element

    fmt::println("{}", numbers);

    numbers.erase(numbers.begin() + 1, numbers.begin() + 3);

    fmt::println("{}", numbers);
}

Warto zwrócić uwagę na dwa istotne fakty:

  • Zamiast dołączać nagłówek <iostream>, dołączamy nagłówek <fmt/ranges.h>. Oczywiście, gdybyśmy potrzebowali std::cin do inputu (którego {fmt} nie zastępuje), wciąż musielibyśmy zostawić polecenie #include <iostream>.
  • Biblioteka {fmt} formatuje std::vector w dosyć przyjemny dla oka sposób. Umieszcza go w nawiasach kwadratowych i oddziela kolejne elementy przecinkiem i spacją.

Dobrze byłoby również wspomnieć, dlaczego nagłówek z {fmt} wygląda, jakby był ścieżką do pliku ranges.h z folderu fmt. Efektywnie tak właśnie jest.

Biblioteka {fmt} składa się z kilku plików, które możemy dołączać dyrektywą #include zależnie od tego, czego potrzebujemy. Plik ranges.h oferuje formatowanie różnych zakresów, ale jeżeli interesuje nas wyłącznie klasyczny output najprostszych typów danych (prymitywy, std::string itp.), to wystarczy dołączyć plik base.h (znajdujący się w fmt, więc pełne polecenie wyglądałoby tak: #include <fmt/base.h>).

#include <set>

#include <fmt/ranges.h>

auto main() -> int {

Z jednej strony jest to plusem (bo w matematycznej notacji zbiory deklaruje się właśnie przy pomocy klamer, np.: $ \set{1,2,3} $), ale z drugiej strony programista może chcieć sterować tym zachowaniem, na przykład stosując identyczne zasady formatowania dla zbioru i wektora.

Zgodnie z informacją, którą można znaleźć w dokumentacji biblioteki, aby std::set sformatować tak samo jak std::vector, możemy skorzystać z fmt::join(), które potrafi sformatować dowolny obiekt, po którym można iterować:

#include <set>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto vector = std::vector<int>{1, 2, 3};
    auto set    = std::set<int>{1, 2, 3};

    fmt::println("{}", vector);
    fmt::println("[{}]", fmt::join(set, ", "));
}

Aby dobrze zrozumieć, co się tutaj dzieje, należy dowiedzieć się, co konkretnie oznacza {} w {fmt}.

{} to tak zwany symbol zastępczy (ang. placeholder). fmt::println() wyświetli to, co zostanie umieszczone w tekście przekazanym przez argument:

auto main() -> int {
    fmt::println("Hello World");
}

Hello World

Jeżeli jednak we wspomnianym tekście zostanie znaleziony {}, to {fmt} będzie szukało kolejnego argumentu, który zostanie odpowiednio sformatowany. Posiłkując się przykładem z ich dokumentacji:

1

4
5

#include <fmt/base.h>

auto main() -> int {
    fmt::println("The answer is {}", 42);
}

1

The answer is 42

Jest to bardzo obszerna i wygodna w użyciu biblioteka, którą będziemy stopniowo poznawać.

Od tej pory, wszystkie przykłady z wyświetlaniem tekstu będą korzystały z biblioteki {fmt}.

Wróćmy jednak do przykładu. Jak to jest, że fmt::println("[{}]", fmt::join(set, ", ")) dla set przechowującego dane 1 2 3 wyświetla [1, 2, 3]?

Kluczem jest połączenie faktu, że gdy {} zostanie zastąpione przez sformatowanie fmt::join(set, ", "), to dla omawianych danych zostanie tam “wstawiony” tekst 1, 2, 3. Skąd się zatem wzięły nawiasy kwadratowe?

Obejmują one placeholder {} w oryginalnym tekście — fmt::println("[{}]", ...). Gdy wyświetlamy tekst "[{}]", to coś, co zastąpi {} będzie objęte przez nawiasy kwadratowe.

Niewątpliwie używanie {fmt} wymaga od nas więcej nauki, ale gdy raz się dobrze pozna te bibliotekę, to można tworzyć kod, który jest zdecydowanie zwięźlejszy, czytelniejszy i często szybszy. Same plusy!

Częste błędy w użytkowaniu {fmt}

W ramach użytkowania {fmt} częstym błędem są próby wyświetlenia pojedynczej wartości bez uzycia tekstu z placeholderami, np. tak:

    auto x = 5;
    fmt::println(x);
}

Taki kod się nie skompiluje.

#include <fmt/base.h>

auto main() -> int {
    auto x = 5;
    fmt::println("{}", x);
}
