Rozdział 1.2 - Pierwsze programy w C++

Opublikowano Feb 25, 2025
Autor Filip Kwiatkowski
12 min czytania

Hello World

Po udanej konfiguracji narzędzia warto szybko zaczerpnąć dużej dawki praktyki. Standardowo na pierwszy ogień pójdzie najpopularniejsza aplikacja, czyli “Hello World”.

W zależności od edycji i konfiguracji edytora, domyślnie wygenerowany projekt może zawierać inaczej wyglądający plik main.cpp. Nie należy się tym przejmować — wystarczy usunąć zawartość wygenerowanego pliku i wkleić tą zaprezentowaną poniżej.

Pierwszy plik z kodem C++, któremu się przyjrzymy, wygląda następująco:

1
2
3
4
5

#include <iostream>

auto main() -> int {
    std::cout << "Hello World";
}

Jego skompilowanie i uruchomienie wynikowej aplikacji poskutkuje wyświetleniem na ekranie klasycznego Hello World. Przeanalizujmy kolejno jego elementy:

  1. Najważniejsza jest linijka nr 4. Przy pomocy relatywnie dziwnej składni wyświetla ona na konsoli sprecyzowany tekst.
  2. Następna w kolejności jest definicja funkcji main(), która okala linijki od 3 do 5. Tak samo, jak w Javie, punktem wejściowym programu w C++ jest funkcja główna. Nagłówek auto main() -> int należy czytać: deklaruję (auto)1 main, który jest funkcją bezargumentową (()) zwracającą (->) int2.
  3. Ostatnim interesującym fragmentem kodu jest pierwsza linijka, czyli #include <iostream>. Wkleja ona do naszego pliku main.cpp zawartość pliku iostream, który jest częścią biblioteki standardowej języka C++. Znajduje się w nim, między innymi, obiekt std::cout, którego użyliśmy do wyświetlenia tekstu na konsolę.

Wyświetlanie tekstu

Do wyświetlania tekstu używa się obiektu std::cout. W niedalekiej przyszłości zostanie on zastąpiony prostszą alternatywą, dlatego nie będziemy się na nim zbyt mocno koncentrować. Warto jednak zapoznać się z najbardziej podstawowymi przykładami jego użycia.

auto main() -> int {
    std::cout << "Hello World";
    std::cout << "Hello World";
}

W powyższym przykładzie skopiowaliśmy znajomą już linijkę wyświetlającą tekst. Warto zwrócić uwagę, że wynikiem uruchomienia takiego kodu jest pojedyncza, następująca linijka:

W czwartej linijce kodu pokazanego powyżej można zauważyć komentarz. Tak samo, jak w Javie, C++ wspiera komentarze jednoliniowe (przy użyciu składni //) oraz wieloliniowe (przy użyciu składni /* */).

W Internecie można się spotkać z alternatywnym sposobem dodawania znaku nowej linii — przy użyciu std::endl. Nie jest to jednak polecany sposób. Nie dość, że wymaga więcej pisania, to jeszcze wykonuje dodatkowe operacje, których programista może nie być świadomy3.

Chcąc wyświetlić dłuższy fragment tekstu, można go dla czytelności rozbić na wiele poleceń wyświetlających napisy tak, jak zostało to zaprezentowane powyżej. Nie trzeba jednak powtarzać nazwy obiektu std::cout. Można łączyć4 polecenia wyświetlania tekstu. Poniższe programy poskutkują wyświetleniem tego samego, następującego tekstu:

Powtarzające się użycia strzałek (<<) wysyłają na ekran5 kolejne fragmenty tekstu.

Naturalnie tekst to nie jedyne, co programista może chcieć wyświetlić. Obiekt std::cout potrafi wyświetlić również wiele innych typów danych, co prezentuje poniższy fragment kodu:

    std::cout << "Hello World" << '\n'
              << 123 << ' ' << 321.0 << "\n"
              << true << false << " is " << 10;
}

Warto zauważyć, że wyświetlanie wartości logicznych (typu bool) przy pomocy std::cout skutkuje wyświetleniem liczb 1 i 0, zamiast tekstu true oraz false. Można zmienić to zachowanie, ale nie jest to ani wygodne, ani efektywne. To kolejny powód (których w tym rozdziale jeszcze przybędzie), dla którego szybko zrezygnujemy z używania std::cout.

Wczytywanie danych

Mając opanowane podstawy wyświetlania, należy teraz opanować podstawy wczytywania danych. Aby jednak wczytać dane, trzeba mieć je gdzie zapisać. Trzeba mieć zaalokowane odpowiednie miejsce w pamięci, do którego będziemy mogli się odwoływać. Do tego służą zmienne.

Stary i nowy styl programowania w C++

Język C++ przeszedł wiele zmian na przestrzeni lat. W ramach tego przedmiotu przedstawiana będzie alternatywna składnia deklarowania zmiennych oraz funkcji. Prezentuje to poniższy listing kodu.

1
2
3
4

auto main() -> int {
    int x  = 10;    // 1
    auto y = 10;    // 2
}

W powyższym przykładzie nie ma efektywnej różnicy między stworzeniem zmiennej x oraz y. Sposób 1 jawnie precyzuje typ zmiennej jako int, a sposób 2 dedukuje ten typ z typu literału (wartość 10).

Podczas PJC będziemy preferować sposób nr 2.

Dlaczego? Różni się od tego z Javy i w tym przykładzie wymaga więcej pisania. Poza tym skąd wiem, jaki będzie typ zmiennej?

Dlatego, że jest on bezpieczniejszy. Czasami wymaga więcej pisania, ale czasami wręcz przeciwnie. Niemniej jednak łączy on bezpieczeństwo wraz z konsekwentnością (czasem trzeba go użyć).

Warto też zwrócić uwagę, że alternatywnym sposobem na zapis funkcji main() z omawianych listingów jest ten przypominający składnię z Javy, czyli:

1
2
3

int main() {
    
}

Używanie auto main() -> int { } zamiast int main() { } niesie za sobą mniej korzyści niż używanie auto x = 10 zamiast int x = 10. Jednak z uwagi na kilka przekonujących przykładów (np. lambdy, które będą omawiane w przyszłości), w ramach nowoczesnego C++ warto rozważyć używanie składni z auto. Styl ten będzie stosowany w ramach przedmiotu PJC.

Wróćmy jednak do przykładu ze zmiennymi typu int. Należy zrozumieć, jakie niebezpieczeństwa może nieść za sobą stosowanie “starego” stylu. Tym niebezpieczeństwem jest Zachowanie Niezdefiniowane — w skrócie UB (ang. Undefined Behavior).

Zachowanie Niezdefiniowane (ang. Undefined Behavior), potocznie nazywane UB, to coś, czego należy się wystrzegać za wszelką cenę programując w C++. Program, który przejawia takie zachowanie, może zrobić dosłownie cokolwiek. UB może mieć wpływ na kod wykonany przed nim, po nim lub nawet na fragment kodu w zupełnie innym pliku.

Przykładem UB jest odczytanie niezainicjalizowanej zmiennej. Poniższy przykład kodu przedstawia poprawne stworzenie i wyświetlenie zmiennej typu int:

3

#include <iostream>

auto main() -> int {
    int x = 10; // using the old style to demonstrate an example
    std::cout << x;
}

Natomiast następny kod przedstawia niepoprawne stworzenie i wyświetlenie (niezainicjalizowanej) zmiennej:

1

#include <iostream>

auto main() -> int {
    int x;  // using the old style to demonstrate an example
    std::cout << x;
}

Co wyświetli powyższy kod?

Początkujący programista C++ ma wiele potencjalnych odpowiedzi na to pytanie:

  • Liczbę 0.
  • Dowolną liczbę.
  • Tekst null.
  • Kod się nie skompiluje.
  • Kod scrashuje.

Wszystkie powyższe odpowiedzi (z wyjątkiem tej, która mówi o niepomyślnej kompilacji) są prawidłowe (choć istnieje bardzo małe prawdopodobieństwo, że wyświetli się null — może się wyświetlić dowolny tekst, choć int nie ma nic wspólnego z (Javowym) nullem).

Zapomnienie o inicjalizacji zmiennej jest częstszym błędem, niż mogłoby się wydawać. Zobaczmy zatem, jak zachowa się program, gdy spróbujemy popełnić ten sam błąd, stosując nowy styl:

1
2
3
4
5
6

#include <iostream>

auto main() -> int {
    auto x;  
    std::cout << x;
}

Powyższy kod się nie skompiluje. Słowo kluczowe auto nie pozwoli na deklarację zmiennej bez jej inicjalizacji, jednocześnie broniąc programistę przed potencjalnym UB.

To ogromny plus. Zamiast mieć kompilujący się błąd, który może psuć nasz program “po cichu”, otrzymujemy jawny błąd kompilacji mówiący o tym, że zapomnieliśmy zainicjalizować zmienną.

Stosując styl z auto, warto przedstawić kilka prostych przykładów inicjalizacji zmiennych:

1
2
3
4
5

auto main() -> int {
    auto x = 0;         // 1
    auto y = int();     // 2
    auto z = int(0);    // 3
}

Powyższy listing przedstawia najczęstsze przypadki inicjalizacji zmiennych w C++ przy użyciu auto:

  1. Typ zmiennej x jest dedukowany na podstawie typu literału 0.
  2. W przypadku zmiennej y podajemy typ jawnie. W ten sposób zmienna jest jednocześnie inicjalizowana wartością 0.
  3. Zmiennej z również podaliśmy jawnie typ, ale jednocześnie sprecyzowaliśmy przypisywaną wartość. Wygląda to nieco jak użycie konstruktora, choć tak naprawdę nic takiego się tutaj nie dzieje.

Obiekt std::cin

Umiejąc już tworzyć zmienne, czas na wczytanie danych do programu. W tym celu zostanie wykorzystany obiekt std::cin. Wspomniany wcześniej nagłówek <iostream> udostępnia go wraz z poznanym już std::coutem. Jego użycie jest bardzo proste, zakładając, że składnia wyświetlania danych została już opanowana:

#include <iostream>

auto main() -> int {
    auto number = int();

    std::cout << "Input: ";
    std::cin >> number;
    std::cout << "Output: " << number << '.';
}

Zakładając, że po uruchomieniu powyższego kodu użytkownik wpisze przykładowo liczbę 1024, program wyświetli następujący tekst:

1

Input: 1024
Output: 1024.

W zależności od konfiguracji środowiska i systemu operacyjnego, czasem konsola niepoprawnie wyświetla białe znaki (np. spacje), gdy łączy się je z danymi wprowadzanymi od użytkownika. Nie należy się tym przejmować.

Jak widać, wczytywanie danych jest bardzo proste. Wystarczy stworzyć zmienną i później przy pomocy std::cin wprowadzić do niej wartość.

Łatwo zapamiętać regułę kierunku strzałek (<< oraz >>) przy pomocy analizy obiektów (np. zmiennych). W przypadku fragmentu std::cout << "Input: ", tekst Input: jest wysyłany do wyjścia. Stąd strzałki kierują się od niego do standardowego wyjścia. W przypadku fragmentu std::cin >> number, jakieś dane z wejścia są pobierane i zapisywane do zmiennej. Stąd strzałki kierują się od standardowego wejścia do zmiennej.

Proste operacje sterujące i modyfikujące

Poznany już wcześniej język Java odziedziczył po C++ wiele elementów składni. Do tej grupy należą, między innymi:

  • Wybrane operacje sterujące, takie jak:
    • if ();
    • while ();
    • do { } while();
    • for ();
    • operator ? :.
  • Operatory arytmetyczne (+, -, *, /, %), logiczne (&&, ||, …) i bitowe (&, |, ~, …).

Dlatego nie będziemy koncentrować się na powtórzeniu wszystkich tych elementów. Tam, gdzie język C++ różni się od Javy (np. brak wyrażenia switch ()6 lub if () z inicjalizacją), wspomniane różnice będą zaznaczane, o ile będą one istotne dla przykładu.

#include <iostream>

auto main() -> int {
    auto number    = 0;
    auto sum       = 0;
    auto operation = ' ';

    std::cout << "Enter a number: ";
    std::cin >> number;
    sum += number;

    while (true) {
        std::cout << "Enter an operation "
                  << "(+ to add, - to subtract, / to divide, "
                  << "* to multiply, or q to quit): ";
        std::cin >> operation;

        switch (operation) {
            case '+':
                std::cout << "Enter a number to add: ";
                std::cin >> number;
                sum += number;
                std::cout << "Current total: " << sum << '\n';
                break;
            case '-':
                std::cout << "Enter a number to subtract: ";
                std::cin >> number;
                sum -= number;
                std::cout << "Current total: " << sum << '\n';
                break;
            case '*':
                std::cout << "Enter a number to multiply: ";
                std::cin >> number;
                sum *= number;
                std::cout << "Current total: " << sum << '\n';
                break;
            case '/':
                std::cout << "Enter a number to divide: ";
                std::cin >> number;
                if (number != 0) {
                    sum /= number;
                    std::cout << "Current total: " << sum << '\n';
                } else {
                    std::cout << "Cannot divide by zero. Quitting...\n";
                    return 0;
                }
                break;
            case 'q':
                std::cout << "Quitting...\n";
                return 0;
            default:
                std::cout << "Invalid operation. Quitting...\n";
                return 0;
        }
    }
}

Warto zwyczajnie skopiować powyższy kod, wkleić go do pliku main.cpp i uruchomić, a dopiero potem zacząć go analizować. Nie kryje się za nim nic szczególnego. Służy jedynie jako demonstracja podobieństwa podstawowych instrukcji między Javą a C++.

return w main()

Na koniec warto jeszcze zwrócić uwagę, że nagłówek funkcji main() ewidentnie wskazuje na to, że zwraca ona wartość typu int. Gdzie jest zatem polecenie return X, gdzie X to jakaś liczba?

Takie polecenie nie znajdzie się nigdzie w listingach powyżej. To dlatego, że w C++ formalnie nie trzeba precyzować wartości zwracanej. Bywa to jednak bardzo niebezpieczne, ponieważ w większości przypadków skutkuje to UB.

Istnieją dwa wyjątki:

  • Funkcje zwracające void nie muszą mieć nigdzie sprecyzowanego słowa return (ale mogą — w postaci return; — aby wcześniej zakończyć działanie funkcji).
  • Główna funkcja programu (main()), jeżeli nie zwróci żadnej wartości, to domyślnie zwraca wartość 0.

Język C++ pozwoli na pominięcie słowa kluczowego return w definicjach funkcji. Jeżeli jednak funkcja zwraca coś innego niż void i nie jest to funkcja główna programu, to taki zabieg poskutkuje Zachowaniem Niezdefiniowanym (UB).

  1. auto nie do końca znaczy jedynie deklaruję, choć formalnie jest to tak zwany specyfikator typu (ang. type specifier). W ramach uproszczenia będziemy jednak tłumaczyć to słowo kluczowe przy deklaracjach funkcji i zmiennych jako słowo, które wprowadza deklarację czegoś. ↩

  2. Skoro main() zwraca int, to gdzie return? Zostało to wyjaśnione na końcu. ↩
