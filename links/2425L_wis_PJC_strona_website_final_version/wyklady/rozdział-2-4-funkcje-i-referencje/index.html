Funkcje w C++

Jednym z najistotniejszych elementów programistycznych są funkcje. Pozwalają one nadać nazwę jakiemuś fragmentowi kodu i, używając tej nazwy, zwięźle precyzować, jaki rodzaj operacji ma zostać w danym miejscu wykonany.

Funkcje w C++ pełnią taką samą funkcję jak w Javie. Raz napisana funkcja może być wywoływana wiele razy z odpowiednimi argumentami. Przyjrzyjmy się przykładowi poniżej:

#include <fmt/base.h>

auto sayHello() -> void {
    fmt::println("Hello!");
}

auto main() -> int {
    sayHello();
    sayHello();
}

2

Hello!
Hello!

Popularną praktyką programistyczną (która jest sugerowana nawet w ponadczasowym “Clean Code” Roberta C. Martina) jest definiowanie funkcji po tym, jak jej użyjemy. Chodzi o to, żeby czytając kod od góry do dołu, nie zastanawiać się, po co nam funkcja sayHello(). Celujemy w to, aby osoba czytająca kod wpierw zobaczyła main(), zrozumiała, jak (i po co) jest używane sayHello(), a potem (dopiero jak będzie miała taką potrzebę) przeczytała kod dalej i zapoznała się z jej definicją.

Zróbmy zatem odpowiedni refactoring i umieśćmy definicję funkcji sayHello() pod main()em:

1

#include <fmt/base.h>

auto main() -> int {
    sayHello();
    sayHello();
}

auto sayHello() -> void {
    fmt::println("Hello!");
}

Niestety, ten kod się nie skompiluje. Zależnie od używanego kompilatora tekst błędu może się różnić, ale koniec końców będzie wskazywał na coś podobnego do tego:

1

error: 'sayHello' was not declared in this scope

Jak to? Przecież funkcja sayHello() jest zadeklarowana i zdefiniowana w ramach tego pliku. Przecież jest w linijce nr 8.

To prawda. O ile w Javie nie jest to problematyczne, to w C++ niestety taka konstrukcja nie przejdzie pomyślnie procesu kompilacji. To dlatego, że kompilator nie będzie szukał deklaracji po reszcie pliku lub projektu.

Aby użyć stworzonego bytu (zmiennej, funkcji, klasy, itd.) w języku C++, należy go wcześniej zadeklarować.

Deklaracja i definicja to nie to samo.

Deklaracja
(ang. Declaration) Instrukcja informująca kompilator o istnieniu danego bytu.
Definicja
(ang. Definition) Instrukcja informująca kompilator o wszystkich szczegółach danego bytu.

W naszym przypadku problem polega na tym, że kompilator, próbując skompilować ciało funkcji main(), nie wie o tym, że istnieje funkcja o nazwie sayHello(). W poprzedniej wersji kodu, gdy cała definicja była umieszczona nam main()em, kompilator wiedział wszystko.

Wróćmy jeszcze do pierwotnej wersji kodu.

#include <fmt/base.h>

// Declaration and definition
auto sayHello() -> void {
    fmt::println("Hello!");
}

auto main() -> int {
    sayHello(); // usage
    sayHello(); // usage
}

Zgodnie z komentarzem z linijki nr 3, gdy pojawia się definicja funkcji, która nie była wcześniej deklarowana, jest ona jednocześnie jej deklaracją.

No dobrze, ale czy można w końcu umieścić ciało sayHello() pod main()em, czy nie?

Można. Wystarczy rozdzielić funkcję na definicję i deklarację:

#include <fmt/base.h>

// Declaration
auto sayHello() -> void;

auto main() -> int {
    sayHello(); // usage
    sayHello(); // usage
}

// Definition
auto sayHello() -> void {
    fmt::println("Hello!");
}

Deklaracja funkcji polega na sprecyzowaniu jej nagłówka bez ciała. Później funkcję można zdefiniować (podając nagłówek i ciało).

Nie jest to idealne rozwiązanie, ale wciąż jest lepsze niż definiowanie wszystkich funkcji w odwrotnej kolejności niż ta, która interesuje programistę.

Referencje

Załóżmy następujące zadanie:

Napisz funkcję modify(), która pobierze przez argument zmienną typu int. Funkcja powinna zwiększyć wartość przekazanej liczby o 10.

A teraz załóżmy, że dostaliśmy to zadanie na przedmiocie PPJ, czyli rozwiązujemy je w Javie. Mając taki kod:

1
2
3
4
5
6
7

public class Main {
    public static void main(String[] args) {
        int x = 5;
        modify(x);
        System.out.println(x);
    }
}

Nie jest możliwym, aby zaimplementować funkcję modify() tak, aby instrukcja drukująca z linijki nr 5 wyświetliła cokolwiek innego niż 5.

Java wszystkie swoje argumenty przekazuje przez kopię (ale z uwagi na semantykę referencji, gdy przekazujemy zmienną typu złożonego, przekazywana jest kopia samej zmiennej referencyjnej, więc pracujemy na oryginalnym obiekcie). Modyfikując parametr typu prymitywnego, dowolne zmiany wykonane na nim nie będą miały jakiegokolwiek wpływu na oryginalny argument.

Teraz wróćmy do C++ i powtórzmy to samo zadanie. Czy istnieje sposób, aby zdefiniować funkcję modify() tak, aby poniższy kod wyświetlił 15?

1
2
3
4
5

9

#include <fmt/base.h>

auto modify(int x) -> void;

auto main() -> int {
    auto x = 5;
    modify(x);
    fmt::println("{}", x);
}

Bez drobnej modyfikacji — nie. Ale z drobną modyfikacją (która tyczy się tylko funkcji modify()) — tak.

Narzędziem, które nam w tym pomoże, są referencje. Przyjrzyjmy się przykładowemu ich użyciu:

1
2
3
4

auto main() -> int {
    auto  x   = 5;
    auto& ref = x;
}

ref to referencja i — jak widać — jawnie ją deklarujemy dodając znak ampersand (&) przy auto.

Fantastycznie, ale co ona robi? Jak się jej używa? Co ona nam daje? Czemu chcielibyśmy jej użyć? Jaki konkretnie jest typ zmiennej referencyjnej?

To bardzo dobre pytania. Zacznijmy zatem od krótkiej definicji, a później szczegółowo na nie odpowiedzmy.

Referencja to alias jakiegoś obiektu. Druga nazwa. Drugi byt, który pozwala się odnosić do istniejącego już obiektu. Referencja jest zawsze połączona z jakimś obiektem.

Przejdźmy zatem do szczegółowych odpowiedzi na przed chwilą zadane pytania.

Co robi referencja?

Deklarując referencję, otrzymujemy nowy byt, który pozwala na wykonywanie operacji na oryginalnym obiekcie. Sama w sobie referencja nie robi nic. Dopiero coś z nią robiąc możemy zobaczyć, po co ona jest.

Jak się jej używa?

Dokładnie tak samo, jak obiektu, z którym jest połączona. Przykładowo:

#include <fmt/base.h>

auto main() -> int {
    auto  x   = 10;
    auto& ref = x;

    fmt::println("{} {}", x, ref);

    x = 15;

    fmt::println("{} {}", x, ref);

    ref = 20;

    fmt::println("{} {}", x, ref);
}

10 10
15 15
20 20

Jak widać, próbując w jakiś sposób nadpisać referencję do zmiennej x, tak naprawdę nadpisujemy wartość x. Odczytując wartość referencji ref tak naprawdę odczytujemy wartość zmiennej x.

Dowolna operacja na referencji skutkuje wykonaniem tej operacji na obiekcie, z którym jest połączona.

W pamięci powyższego programu istnieje tylko jeden obiekt typu int — nasz x1. Sama referencja nie jest nigdzie przechowywana.

W związku z tym, że dowolna operacja na referencji będzie wykonana na połączonym obiekcie, a nie na samej referencji, to nie istnieje sposób, żeby referencję połączyć z innym obiektem (“przepiąć”):

1
2
3
4
5
6
7

auto main() -> int {
    auto  x   = 5;
    auto  y   = 10;
    auto& ref = x;

    ref = y;
}

Instrukcja ref = y nie “resetuje” referencji ref tak, aby była połączona z obiektem y. Instrukcja ta efektywnie nadpisuje wartość zmiennej x wartością zmiennej y. Jest ona efektywnie tym samym co x = y.

Co ona nam daje?

Oferuje nam sposób na dostęp do oryginalnego obiektu używając innego bytu.

Czemu chcielibyśmy jej użyć?

Bo potrzebujemy tego do rozwiązania zadania przedstawionego na początku tego rozdziału.

Przyjrzyjmy się jeszcze raz tworzeniu referencji:

1

auto& ref = x;

Tworzony jest tutaj byt ref, który daje nam pełny dostęp do obiektu x.

Przeczytajmy powyższe zdanie jeszcze raz — powoli.

Tworzony jest tutaj byt ref, który daje nam pełny dostęp do obiektu x.

A teraz zastanówmy się, co by się stało, gdyby ref było parametrem funkcji, a x było jej argumentem:

#include <fmt/base.h>

// changed the paremeter's type from int to int&
auto modify(int& ref) -> void;

auto main() -> int {
    auto x = 5;
    modify(x);
    fmt::println("{}", x);
}

auto modify(int& ref) -> void {
    ref += 10;
}

W linijce nr 8 wywołujemy funkcję modify(). Argumentem tej funkcji jest obiekt x. Zmienna ta inicjalizuje parametr ref, którego typem jest int&, czyli referencja do inta.

Efektywnie w ramach ciała funkcji modify(), parametr ref jest referencją do jakiejś zewnętrznej zmiennej. Jakiegoś obiektu “z zewnątrz”.

A skoro każda operacja wykonana na referencji skutkuje wykonaniem tej operacji na obiekcie, z którym referencja jest połączona, to instrukcja ref += 10 będzie skutkowała zmodyfikowaniem wartości oryginalnej zmiennej x.

Dzięki referencjom jesteśmy w stanie pisać funkcje, które modyfikują wartości oryginalnie przekazanych danych.

Jaki konkretnie jest typ zmiennej referencyjnej?

Odpowiedź na to pytanie częściowo padła w przykładzie kodu z poprzedniego podrozdziału, ale dla kompletności powtórzmy ją tutaj. W poniższym przykładzie:

1
2
3
4

auto main() -> int {
    auto  x   = 5;
    auto& ref = x;
}

Typem zmiennej ref jest int&. Referencja do obiektu typu int. Czytamy “od prawej do lewej”.

Powrót do funkcji

Wróćmy jeszcze na chwilę do funkcji. Pozostały nam jeszcze dwa tematy, które należy omówić.

Przeciążanie funkcji

C++, podobnie jak Java, wspiera przeciążanie funkcji. W przypadku obydwu tych języków funkcję przeciążamy tworząc drugą o takiej samej nazwie, ale o innej liczbie / o innych typach parametrów.

Nie można przeciążać funkcji tylko na typie zwracanym. Jeżeli jednak dodajemy legalne przeciążanie (różniące się parametrami od innych), to można w nim zmienić typ zwracany.

W C++ można przeciążać niestatyczne metody (funkcje w klasach) nie tylko bazując na różnych parametrach, ale nie należy się tym na ten moment przejmować. Ten fragment tematu będzie rozwinięty przy obiektowości.

Domyślne argumenty

Załóżmy, że chcemy napisać funkcję, którą można wywołać z jednym, dwoma, trzema lub czterema argumentami. Na przykład wyświetlamy wektor i chcemy zaoferować możliwość sprecyzowania własnego znaku oddzielającego elementy, własnego prefiksu i własnego sufiksu.

Przykładowo, {fmt} domyślnie wyświetla wektor w znany nam, następujący sposób:

1
2
3
4
5
6
7

#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    fmt::println("{}", std::vector<int>{1, 2, 3});
}

1

[1, 2, 3]

W tym przypadku prefiksem jest [, sufiksem jest ], a znakami oddzielającymi elementy są , (przecinek i spacja).

Celem jest napisanie takiej funkcji, która będzie pozwalała na wygodne modyfikowanie tych znaków. Przykładowo, możemy chcieć wyświetlić @1 2 3# zamiast [1, 2, 3].

Oczywiście możemy to osiągnąć przy pomocy odpowiednich specyfikatorów oraz narzędzi z samego {fmt}:

#include <fmt/ranges.h>

auto main() -> int {
    auto vec = std::vector<int>{1, 2, 3};
    fmt::println("@{}#", fmt::join(vec, " "));
}

@1 2 3#

Dodatkowo zależy nam, aby można było pomijać niektóre argumenty. Przykładowo, jeżeli nie podamy prefiksu i sufiksu, to [ i ] powinny być domyślnymi znakami okalającymi dane. Podobnie z , jako znakami oddzielającymi. Przykładowo, poniższe dwa wywołania powinny wyświetlić dokładnie to samo, czyli [1, 2, 3]:

Argumenty domyślne są małym i prostym elementem języka, ale trzeba zapamiętać kilka zasad, które ich dotyczą:

  • Lista parametrów z domyślnymi argumentami musi być na końcu listy wszystkich parametrów. Nie można po argumencie domyślnym dodać parametru bez domyślnej wartości.
  • Domyślne argumenty precyzujemy po znaku =.
  • Domyślne argumenty precyzujemy tylko w deklaracji funkcji. Jeżeli tworzymy jednocześnie deklarację i definicję (czyli nigdzie wcześniej nie tworzymy samej deklaracji bez ciała), to również możemy je sprecyzować. Natomiast, jeżeli sprecyzowaliśmy je w deklaracji i mamy do czynienia z rozdzieloną deklaracją i definicją, to nie powtarzamy ich w definicji.
