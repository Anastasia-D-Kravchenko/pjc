Typy zdefiniowane przez użytkownika

Tworzenie własnych typów pozwala programiście na dokładne wyrażenie intencji. Wszystko mogłoby być zapisywane jako int czy std::string, ale wtedy cały kontekst działania programu musiałby w każdym momencie pracy nad kodem czynnie istnieć w umyśle programisty. Typy pozwalają na przełożenie części z tych informacji z umysłu, na proste do przeanalizowania konstrukcje w kodzie.

W poprzedniej części rozdziału dowiedzieliśmy się, po co nam typy wyliczeniowe. Dodatkowo zobaczyliśmy, że stosując typ wyliczeniowy, który nie oferuje żadnego innego zakresu wartości niż ten wbudowany (w tamtym przypadku — bool), również możemy poprawić czytelność (i czasem bezpieczeństwo) naszego kodu.

Teraz poznamy sposób na tworzenie dowolnych (a nie tylko enumeracyjnych) typów zdefiniowanych przez użytkownika. Będziemy mogli:

  • zamiast myśleć o dwóch std::stringach i intcie, myśleć o człowieku (Person);
  • zamiast myśleć o dwóch intach, myśleć o punkcie (Point);
  • zamiast myśleć o wektorze double, dwóch std::stringach i intcie, można myśleć o studencie z ocenami (Student).

I tak dalej, i tak dalej…

Tworzenie własnej klasy

W języku C++ mamy dwa słowa kluczowe do tworzenia czegoś, co intuicyjnie rozumiemy jako “klasa”. Są to class oraz struct. Przyjrzyjmy się dwóm sposobom definiowania klas:

1

class Point { };

1

struct Point { };

Obydwie te deklaracje są równoważne.

Oczywiście nie możemy zdefiniować klasy (lub tak naprawdę czegokolwiek) dwa razy, więc umieścimy je w osobnych przestrzeniach nazw, aby móc łatwiej rozumować o ich różnicach:

namespace clazz {

namespace strukt {
    struct Point { };
}


auto main() -> int {
    auto const p1 = clazz::Point();
    auto const p2 = strukt::Point();
}

p1 i p2 są oczywiście różnymi typami, choć ich “reprezentacja” jest identyczna — obydwa są “puste”.

Takie “puste” klasy czasem mają sens, choć nie w tym przypadku — dodajmy do nich jakieś pola:

namespace clazz {

    struct Point {

auto main() -> int {
    auto p1 = clazz::Point();
    auto p2 = strukt::Point();

    p1.x = 1;
    p1.y = 2;

    p2.x = 1;
    p2.y = 2;
}

Jedyną różnicą między class i struct jest to, że przy class wszystko jest domyślnie prywatne, a przy struct wszystko jest domyślnie publiczne.

To tyle. To jedyna różnica.

Oczywiście nic nie stoi na przeszkodzie, aby w class użyć słowa kluczowego public lub w struct użyć słowa kluczowego private, aby jedno zachowywało się jak drugie:

namespace clazz {
    class Point {
    public:
        int x;
        int y;
    };
}

namespace strukt {
    struct Point {
    private:
        int x;
        int y;
    };
}


auto main() -> int {
    auto p1 = clazz::Point();
    auto p2 = strukt::Point();

    p1.x = 1;
    p1.y = 2;

    p2.x = 1;
    p2.y = 2;
}

Problem wciąż jest taki sam, ale teraz dotyczy dostępu do .x i .y obiektu p2, a nie p1.

Jak również można zauważyć, w przeciwieństwie do Javy, w C++ nie używamy public czy private przy każdym polu. Te słowa kluczowe wprowadzają sekcję elementów, które są publiczne lub prywatne (istnieje też protected, ale o nim nie będziemy zbytnio mówić).

Po co w C++ są dwa takie słowa kluczowe? Którego lepiej używać?

Bardzo dobre pytania. Słowo kluczowe struct musi istnieć, bo język C++ chce być jak najbardziej kompatybilny wstecznie z językiem C. Oznacza to, że docelowo cały kod napisany w C powinien móc być skompilowany (i zachowywać się tak samo) przez kompilator C++. Nie jest to w 100% prawda, ale docelowo do tego dąży architektura C++. class zostało dodane, aby programiści mogli łatwiej rozróżnić ideę “prostej struktury” od “klasy w rozumieniu programowania zorientowanego obiektowo”. Koniec końców to rozróżnienie okazało się być mało istotne. Niestety, zostaliśmy z dwoma słowami kluczowymi.

Co do drugiego pytania, to można zapamiętać następującą wskazówkę:

Jeżeli nasz typ nie ma reprezentować jakiegoś wewnętrznego zachowania (brak ograniczonych inwariantów), to warto użyć struct. Jeżeli typ ma mieć metody, które pilnują zachowania inwariantów, to warto użyć class.

Abstrakcja punktu w matematyce nie stawia jakichkolwiek ograniczeń na współrzędne, a zatem warto użyć struct.

Konstrukcja obiektów własnych klas

W poprzednim listingu stworzyliśmy obiekty p1 i p2, którym następnie spróbowaliśmy przypisać wartości współrzędnych. Wiemy jednak, że istnieje prostszy sposób na osiągnięcie tego celu — można skorzystać z konstruktorów.

Rzecz w tym, że przy tak prostych typach, C++ nie wymaga od nas definicji konstruktorów. Pozwala nam na inicjalizację wartościami w tej samej kolejności, w jakiej zostały one zadeklarowane w klasie:

#include <string>

struct Point {
    int x;
    int y;
};

struct Person {
    std::string name;
    std::string surname;
    int age;
};


auto main() -> int {
    auto point  = Point(3, 14);
    auto person = Person("Dio", "Brando", 121);
}

Gdybyśmy point i person (albo p1 i p2 z poprzednich przykładów) oznaczyli jako const, to modyfikacja ich pól (.x i .y oraz .name, .surname i .age) oczywiście zakończyłaby się błędem kompilacji. const obiekt “blokuje” modyfikację jego pól.

Semantyka wartości

Należy pamiętać o semantyce wartości w języku C++. Operujemy na obiektach, a nie odniesieniach do nich (jak w Javie). Oznacza to, że poniższy listing wyświetli dwie różne linijki tekstu:

#include <fmt/base.h>

struct Point {
    int x;
    int y;
};


auto main() -> int {
    auto point1 = Point(3, 14);
    auto point2 = point1;

    point1.x = 1;
    point1.y = 61;

    fmt::println("{} {}", point1.x, point1.y);
    fmt::println("{} {}", point2.x, point2.y);
}

W przypadku Javy zostałyby jednak wyświetlone dwie, identyczne linijki.

W C++ point1 i point2 są zupełnie osobnymi obiektami. Jeden jest użyty do stworzenia drugiego, ale po tej konstrukcji, ich relacja znika. point2 jest całkowicie niezależną kopią. Dlatego zmiany w niej nie są widoczne dla pierwszego obiektu.

#include <fmt/base.h>

struct Point {
    int x;
    int y;
};


auto main() -> int {
    auto point1  = Point(3, 14);
    auto& point2 = point1;  // auto& vs auto

    point1.x = 1;
    point2.y = 61;

    fmt::println("{} {}", point1.x, point1.y);
    fmt::println("{} {}", point2.x, point2.y);
}
