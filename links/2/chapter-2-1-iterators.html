Chapter 2.1 - Iterators

Posted Mar 6, 2025
By Filip Kwiatkowski
14 min read

Iterators

Not all containers support indexing.

Sometimes we don’t want to sort (or reverse) the entire container. Sometimes we want to apply a standard algorithm to a subset of data.

So, how do we access data from a container that doesn’t support indexing? How can we apply a standard algorithm to a subset of a container?

The answer to both questions is: by using iterators.

What is an iterator?

An iterator is an abstraction of data access. So far, when interacting with specific elements of a container (or array in Java), we have used indexing.

Indexing is not always sufficient. Some containers (and collections in other languages, such as Java) do not support indexing. Sometimes this is because they do not specify any order of data (so what would it mean for one element to be at index 4 and another at index 7?), and sometimes because indexing implies fast access to data (we provide a number and expect the position of the element to be immediately available). However, this is not always the case.

These are not exhaustive examples, but for now, they should be sufficient to understand that indexing is not a universal way of accessing data.

Iterators provide a universal way of accessing data. Containers do not always support indexing.

An iterator can be thought of as an arrow pointing to some data or as a note with an address and detailed information about what is located at that address.

All containers in C++ provide methods .begin() and .end()1, which return iterators to their beginning and end, respectively.

Using iterators

Okay, but how do we use iterators?

Most often, by calling the .begin() method and storing the returned iterator. The example below illustrates this:

#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2};

    auto iterator = vec.begin();
}

Line 6 contains the declaration of the iterator variable. As the name suggests, it is an iterator of some kind. The type of this variable is std::vector<int>::iterator. This name tells us absolutely nothing. In reality, it is an alias2 for a type whose actual name we do not know. Therefore, we will not be interested in its specific name or declaration. The only thing that interests us is what we can do with such an iterator.

As mentioned several times already, iterators allow access to data. To access the element pointed to by the iterator, we use the dereference operator, denoted by *:

#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2};

    auto iterator = vec.begin();

    std::cout << *iterator;
}

This code prints 3. This is because .begin() returns an iterator pointing to the first element of the container.

Iterators can also be used to modify data:

#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2};

    auto iterator = vec.begin();

    *iterator = 10;

    std::cout << vec.front();
}

The operation shown above can be expressed more concisely (though not always more clearly) as follows: *vec.begin() = 10.

The above listing displays the number 10, which should not be surprising. We obtain an iterator to the first element, then by using it (and *), we access the element it points to and overwrite this element with the value 10. The mentioned element is still in the same place — at the beginning of the vector. Therefore, when displaying it using vec.front(), we see the number 10.

Accessing data (using *) is the most important feature of an iterator. Next in line is moving it (using ++ and similar operators).

Let’s analyze the following code listing along with its output:

#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2};

    auto iterator = vec.begin();

    *iterator = 10;
    ++iterator;
    *iterator = 20;

    for (auto element : vec) {
        std::cout << element << ' ';
    }
}

1

10 20 1 4 2

In the above listing, the method producing an iterator was called only once. We created only one variable that is an iterator. However, two elements in the vector vec underwent changes.

This is because a single iterator is not usually associated with a single element. It is a kind of piece of paper with an address that we can erase and overwrite. Alternatively, you can think of an iterator as an arrow that allows us to access certain elements. Arrows can be moved. When you move an arrow and then use it to access data, it is natural to assume that you will access some completely new data.

This is exactly what happened in lines 9-11. Initially, the iterator pointed to the number 3 in the vector. It was then replaced with the number 10. Next (line 10), the iterator was moved one place to the right — to the element containing the number 5. Repeating the overwrite operation changed this number to 20.

Incrementing an iterator results in moving it to the next element. For iterators pointing to containers represented by a block of memory (e.g., std::string or std::vector), this operation can be considered as “moving the iterator to the right”.

Some iterators can only be incremented using ++. Some also support --. Yet others also support += or -=. For now, we limit ourselves to analyzing std::vector and std::string, whose iterators support all of these operations. For example:

As you can see above, you can practically “jump” between elements and modify them freely using iterators.

Executing standard algorithms on container fragments

What is a real-life example of operations I might want to perform now, for which I will need iterators?

Executing operations on container fragments, and in the near future — accessing elements from containers that do not support indexing.

Let’s sort the first half of a vector and reverse its second half:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2, 0};

    std::ranges::sort(vec.begin(), vec.begin() + vec.size() / 2);
    std::ranges::reverse(vec.begin() + vec.size() / 2, vec.end());

    for (auto element : vec) {
        std::cout << element << ' ';
    }
}

1

1 3 5 0 2 4

At first glance, there’s nothing suspicious in the above example. It’s clear that vec.begin(), vec.begin() + vec.size() / 2 represents the first half of the vec vector, and vec.begin() + vec.size() / 2, vec.end() represents the second half.

And if it’s not immediately obvious, it can be relatively straightforward to deduce. Since .begin() returns an iterator to the first element, and iterators can be moved, by moving the obtained iterator “forward” (“to the right”) by half of the elements in the entire container (vec.size() / 2), we obtain an iterator to the middle element.

The same iterator is used to specify the beginning of the range operated on by the std::ranges::reverse() algorithm. It’s worth emphasizing this by refactoring the code and storing repetitive expressions in a variable:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2, 0};

    auto middle = vec.begin() + vec.size() / 2;
    
    std::ranges::sort(vec.begin(), middle);
    std::ranges::reverse(middle, vec.end());

    for (auto element : vec) {
        std::cout << element << ' ';
    }
}

“On paper,” everything is very simple — we define the middle of the range and use it to split the mentioned range into two parts, on which we operate with separate algorithms.

However, an inevitable question arises:

In the vec vector, there are 6 elements. Which one does middle point to? Additionally, since middle is used both in std::ranges::sort() and std::ranges::reverse(), which algorithm affects the element it points to? Both? Neither? One of them? If so, which one?

middle, of course, points to the element with the original value 4. The iterator to the beginning (.begin()) is moved 3 elements to the right (vec.size() / 2) — that’s how we obtained middle.

However, to answer the rest of the questions, one must delve into the topic of right-open ranges and how surprising the iterator returned by .end() is.

Open-closed intervals (ranges)

In mathematics, we know what an open-closed interval means. It’s the same as a left-closed range, and it’s described by the following formula: \([x, y)\).

Ranges in C++ are open-closed. This means that the element pointed to by the iterator representing the beginning of the range will be included when executing a given algorithm, while the element pointed to by the iterator representing the end of the range will not be included.

Typically, it’s best to look at an example to illustrate the above statement. Let’s create a simple vector and two iterators pointing to some of its internal elements:

Simple iterator arithmetic clearly shows that first points to the element storing the value 22, and last points to the element storing 55.

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{11, 22, 33, 44, 55, 66};

    auto first = vec.begin() + 1;
    auto last  = vec.begin() + 4;

    std::ranges::reverse(first, last);
}

Beginner C++ programmers often assume that since first points to 22 and last to 55, reversing the elements between first and last will result in the vec vector being ordered like this: 11 55 44 33 22 66.

However, that’s not the case.

The actual state of vec after executing the reversal algorithm on line 11 is: 11 44 33 22 55 66. The number 55 remains where it was, just before last.

This is because the element pointed to by last is not included in the execution of std::ranges::reverse() on line 11.

So why pass it at all? Why is it done so strangely?

You can read for hours about the pros and cons of such ranges. Several interesting examples can be found here.

However, the fact remains that users (i.e., “normal people”) don’t think in terms of one-sided open ranges. For example, when saying “from Monday to Friday,” one means a full five days — including both Monday and Friday.

Therefore, it takes some time to get used to the idea that standard algorithms expect ranges where the “ending iterator” points to an element not considered by the algorithm.

For now, the most significant argument in favor of accepting such notation and the practice of representing ranges is the fact that the end of one subrange is automatically the beginning of the next.

Thanks to the fact that ranges in C++ are open-closed, when dividing a range into subranges, the iterator representing the end of one of them automatically becomes the beginning of the next one. Then, there’s no need to perform selective operations like + 1 to calculate the next element.

Let’s return to the example of sorting one half of a vector and reversing the other:

#include <algorithm>

auto main() -> int {
    auto vec = std::vector<int>{3, 5, 1, 4, 2, 0};

    auto middle = vec.begin() + vec.size() / 2;

    std::ranges::reverse(middle, vec.end());

    for (auto element : vec) {
        std::cout << element << ' ';
    }
}

middle points to 4. std::ranges::sort() sorts everything from 3 to 4 exclusively, i.e., 3, 5, 1. std::ranges::reverse() reverses the remaining elements (including 4), so it’s: 4, 2, 0.

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{11, 22, 33, 22, 33, 11};

    auto middle = vec.begin() + vec.size() / 2;

    std::ranges::sort(vec.begin(), middle);
    std::ranges::sort(middle, vec.end());

    auto bothHalvesEqual = std::ranges::equal(
            vec.begin(), middle,
            middle, vec.end()
    );

    std::cout << bothHalvesEqual;
}

The algorithm is very simple. Once again, we obtain an iterator to the “middle,” sort both halves, and use std::ranges::equal() to check if they are the same.

The std::ranges::equal() algorithm checks if two arbitrary ranges are identical. It can be used, for example, to compare std::vector<char> with std::string.

What is .end()?

.begin() and .end() return iterators to the beginning and the end of a given interval (range). Standard algorithms operate on open-closed intervals, meaning they “don’t touch” the element pointed to by the iterator representing the end. .begin() returns an iterator to the first element of the range.

These are all facts we’ve learned earlier. What we don’t yet know is what .end() specifically returns.

Let’s look at the following code snippet, which reverses an entire vector, but instead of passing its name to the algorithm, we pass iterators to its beginning and end:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{1, 2, 3};

    std::ranges::reverse(vec.begin(), vec.end());

    for (auto element : vec) {
        std::cout << element << ' ';
    }
}

The result is the output 3 2 1. This is the same as if we had executed std::ranges::reverse(vec) instead of std::ranges::reverse(vec.begin(), vec.end()).

The range from range.begin() to range.end() represents all the elements in range.

How do we reconcile this? How is it that algorithms ignore the element pointed to by the iterator representing the end, yet the pair .begin()-.end() represents all the elements?

The iterator returned by .end() points to the element after the last one.

That’s it. That’s the whole philosophy. These are a set of often unintuitive facts that nonetheless work together to create a relatively convenient tool in the form of C++’s standard algorithms and data structures.

In the future, there will be more examples utilizing these peculiarities of ranges and iterators. For now, it’s worth examining an example that uses iterators to display all the elements in a vector. This is roughly how a range-based for () loop is compiled:

#include <algorithm>
#include <iostream>
#include <vector>

auto main() -> int {
    auto vec = std::vector<int>{1, 2, 3};

    for (auto iter = vec.begin(); iter != vec.end(); ++iter) {
        std::cout << *iter << ' ';
    }
}

As seen, reaching the end of the range (.end()) represents the end of the data on which some algorithm (in this case, a raw for () loop) was supposed to operate. It’s a kind of “guard” indicating the end of work.
