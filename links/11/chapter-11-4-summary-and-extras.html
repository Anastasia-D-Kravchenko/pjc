Chapter 10.4 - Summary and extras

Posted May 20, 2025
By Filip Kwiatkowski
2 min read

Raw vs. smart pointers

Raw pointers should generally only be used as “nullable, rebindable references.” We should use them when we want to refer to external data but can’t use references. For example, as class member variables or as elements of containers.

Smart pointers (like std::unique_ptr) should be used when we need dynamic memory allocation. For example, when we want to create long-lived objects stored in a polymorphic container. It’s important to remember that a unique pointer cannot be copied. To access the data it points to, consider using its .get() method, which will return a raw pointer to it.

Ideally, we wouldn’t have to use either smart or raw pointers. Whenever possible, it’s best to use “plain” objects and containers.

Raw pointer as an iterator

A raw pointer, T*, supports:

  • dereferencing (*);
  • pre-increment and post-increment (++ptr and ptr++);
  • pre-decrement and post-decrement (--ptr and ptr--);
  • addition and subtraction with numbers (ptr + 10, ptr - 3, etc.);
  • indexing, which is directly translated to arithmetic along with dereferencing (ptr[3] is exactly the same as *(ptr + 3)).

All of these characteristics make it meet the requirements of a so-called contiguous iterator, one that points to elements adjacent to each other in memory.

The sizeof operator

The sizeof() operator returns the number of bytes occupied by objects of a given type (e.g., sizeof(int) or sizeof(bool)) or by a specific object (e.g., sizeof(n), where n is some variable).

Representation of bytes of an object

Using reinterpret_cast<char*>(somePointer) returns a pointer to the bytes of the object pointed to by somePointer. This allows you to inspect the values of individual bytes, for example, of ints:

#include <fmt/base.h>

int main() {
    int someInt = 1337;

    char* start = reinterpret_cast<char*>(&someInt);
    char* stop  = reinterpret_cast<char*>(&someInt) + sizeof(someInt);

    while (start != stop) {
        fmt::print("{:#x} ", *start);
        ++start;
    }

    return 0;
}

However, it’s important to remember that if an object holds pointers to data, simply analyzing the bytes that make up that pointer won’t allow us to correctly analyze the objects it points to.

Writing and reading binary data

std::fstream with the std::ios::binary flag allows for writing and reading binary data. The .read() and .write() methods expect a pointer to bytes and the number of bytes to overwrite/copy.

It’s worth using binary data if you care about the speed and predictability of reading and writing data.
