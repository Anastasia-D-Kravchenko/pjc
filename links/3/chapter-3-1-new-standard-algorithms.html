Locating elements in containers

When we want to check if a certain element is present in a container, we have two options:

  1. Be sad that we’re using C++20 instead of C++23, which introduced std::ranges::contains().
  2. Use std::ranges::find().

Let’s go with the second option.

The std::ranges::find() algorithm searches for a given element in a given range. It doesn’t return a bool, but an iterator to the found object.

An example usage looks like this:

#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto const numbers = std::vector<int>{3, 5, 1, 4, 2};

    auto const iter = std::ranges::find(numbers, 1);

    fmt::println("{}", *iter);
}

How to protect ourselves from such errors? How can we ensure that std::ranges::find() found the element?

We should compare the returned iterator with the end of the provided range:

#include <algorithm>
#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto const numbers = std::vector<int>{3, 5, 1, 4, 2};

    auto const iter = std::ranges::find(numbers, 9);

    auto const present = iter != numbers.end();

    if (present) {
        fmt::println("{}", *iter);
    } else {
        fmt::println("No such element");
    }
}

The expression iter != numbers.end() checks whether a certain element has been found. Let’s take a closer look at why it was designed this way.

The .end() iterator

As we’ve learned before, standard algorithms operate on right-open ranges. This brings several benefits. For containers to work correctly with algorithms, their .end() must return an iterator pointing to the element past the last one. There is no element under .end(). It points to a non-existent element. Therefore, it’s an ideal candidate for signaling the absence of an element.

Searching for elements in subranges

What if we’re looking for elements not in the entire container, but in its parts (subranges)? For example, imagine that a user wants to enter 21 numbers and find out in how many consecutive groups of three numbers the number 0 appears.

In other words, we need to read 21 values, divide them into groups of three, and check in how many of such groups the number 0 appears.

It would be most convenient to divide the container, from which we’ll read all the numbers (e.g., some std::vector), into the mentioned groups and call std::ranges::find() on each of them, but before C++23, there’s no convenient, out-of-the-box way to solve the problem this way. However, instead we can use iterators representing the mentioned, three-element groups as subranges. For example:

#include <algorithm>
#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto const numbers = std::vector<int>{1, 2, 3, 4, 5, 6, 7};

    auto const iter = std::ranges::find(
            numbers.begin(), numbers.begin() + 3,
            5
    );
}

iter represents the result of searching for the number 5 in the first three elements of the vector numbers (numbers.begin(), numbers.begin() + 3). If such an element doesn’t exist, then std::ranges::find() will return the end of the range it was supposed to operate on.

However, the end, in this case, is not numbers.end(). It’s numbers.begin() + 3. It was the iterator pointing to the end of the subrange the invoked algorithm was supposed to work on. So, to check if the number 5 is present in the first three elements, you need to compare iter with numbers.begin() + 3:

        fmt::println("5 not found in the first three elements!");

Armed with this knowledge, we can apply the algorithm to the original problem. We’ll iteratively compute iterators representing consecutive three-element subranges until we reach the end of the vector:

#include <algorithm>
#include <iostream>
#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto numbers = std::vector<int>(21);

    for (auto i = 0; i < numbers.size(); i++) {
        std::cin >> numbers[i];
    }

    auto zeroCounter = 0;

    for (auto start = numbers.begin(); start != numbers.end(); start += 3) {
        auto end = start + 3;

        auto const iterToZero = std::ranges::find(start, end, 0);

        if (iterToZero != end) {
            zeroCounter += 1;
        }
    }

    fmt::println("There were {} groups with zeros", zeroCounter);
}

Detailed analysis of the presented algorithm

Let’s proceed to analyze the algorithm presented above.

1

auto numbers = std::vector<int>(21);

    std::cin >> numbers[i];

In the above listing, we create a vector that holds 21 elements. We use a constructor that immediately creates a container of the appropriate size, whose elements are then overwritten using a loop.

auto zeroCounter = 0;

// [...]

fmt::println("There were {} groups with zeros", zeroCounter);

Later, the program creates a variable as a counter, which will be updated in a loop searching for triplets with zeros (omitted above — // [...]). Then the mentioned counter is displayed.

The essence of the program is based on the following loop:

1
2
3
4
5

for (auto start = numbers.begin(); start != numbers.end(); start += 3) {

// [...]

}

The loop is based on the variable start, which is an iterator to the beginning of a given triplet of elements where we are looking for the number 0. For now, it’s irrelevant what happens in the body of the loop. What’s important is that after checking whether there is a 0 in a given triplet, we move to the next triplet. We achieve this by shifting the start iterator three places to the right — using start += 3.

When we “jump” like this until we reach numbers.end(), we know that we have run out of elements, and it’s time to exit the loop.

The body of the loop is relatively simple:

1
2
3
4

for (auto start = numbers.begin(); start != numbers.end(); start += 3) {
    auto end = start + 3;

    auto const iterToZero = std::ranges::find(start, end, 0);

    if (iterToZero != end) {
        zeroCounter += 1;
    }
}

Using start, it’s easy to calculate the end of a given group. We simply obtain an iterator three elements ahead, i.e., start + 3. We store this value in end. In this way, start and end form a pair of iterators representing three elements, in which we search for the number 0 using the std::ranges::find() algorithm. If we find it (i.e., the value returned by the algorithm is different from end), we increment the previously introduced counter by 1.

Finding the smallest and the largest element in a container

Sometimes, we are interested in finding the smallest number in a given vector or the “largest” character in a string (i.e., the furthest letter alphabetically). Naturally, it would be trivial to find such an element using a loop, but it’s definitely better to use standard algorithms. In this section, we’ll learn about four of them:

  • std::ranges::max()
  • std::ranges::max_element()
  • std::ranges::min()
  • std::ranges::min_element()

std::ranges::max() and std::ranges::min() return a copy of the largest or the smallest element, respectively. The versions with the _element() suffix return iterators.

For example:

#include <algorithm>
#include <vector>

#include <fmt/base.h>

auto main() -> int {
    auto numbers = std::vector<int>{11, 1, 1111, 111};

    auto const maxNumber = std::ranges::max(numbers);
    auto const maxIter   = std::ranges::max_element(numbers);

    auto const minNumber = std::ranges::min(numbers);
    auto const minIter   = std::ranges::min_element(numbers);

    fmt::println(
            "min: {}\nmax: {}\nminElement: {}\nmaxElement: {}",
            minNumber, maxNumber,
            *minIter, *maxIter
    );
}

As you can see, both the “basic” version and the one with the _element() suffix allow us to obtain the smallest or largest number. However, it’s important to note that when specifying the arguments to display, we needed to use dereferencing with the returned iterators (line 18).

Algorithms with the _element() suffix may sound like unnecessary additions. Not only is their name longer, but you also have to remember to use * when using them. Why are they utilized?

First and foremost, it’s important to remember that using iterators allows us to avoid copying potentially large elements. They give us direct access to the found element. For example, if we wanted to swap the largest and smallest elements, std::ranges::min() or std::ranges::max() would be of no use:

#include <algorithm>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto numbers = std::vector<int>{11, 1, 1111, 111};

    auto const maxIter = std::ranges::max_element(numbers);
    auto const minIter = std::ranges::min_element(numbers);

    fmt::println("{}", numbers);
    std::ranges::swap(*maxIter, *minIter);
    fmt::println("{}", numbers);
}

1
2

[11, 1, 1111, 111]
[11, 1111, 1, 111]

As you can see, because iterators give us direct access to elements, we can use them to overwrite elements in the container. In this case, we used the std::ranges::swap() algorithm, which swaps the values of two objects.

When dealing with iterators, it’s worth considering the usage of std::ranges::iter_swap() instead of std::ranges::swap() paired with dereferences:

1

std::ranges::iter_swap(maxIter, minIter);

The above code does exactly the same thing as the previously presented code with “classic” swapping:

1

std::ranges::swap(*maxIter, *minIter);

It’s advisable to use the version intended for iterators. This is because it’s harder to make a mistake when using it. For example, if we omitted dereferencing in the original example, i.e., did this:

1

std::ranges::swap(maxIter, minIter);

It wouldn’t change our vector in any way. Now maxIter would point to the smallest element, and minIter to the largest one. Such a mistake is not possible when using std::ranges::iter_swap() because it’s intended only for use with iterators. Attempting to use it with non-iterator objects will fail:

1

std::ranges::iter_swap(*maxIter, *minIter); // compilation error!

In summary, when we want to swap the values of any two objects, we use std::ranges::swap(), but when we have two iterators and want to swap the values of the objects they point to, it’s best to use std::ranges::iter_swap().
