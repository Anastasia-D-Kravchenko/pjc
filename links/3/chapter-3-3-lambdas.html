Finding an element based on an arbitrary criteria

In the past, we learned about the std::ranges::find() algorithm. With its help, we can find an element in a specified range. An element that is equal to the one we provide as an argument to the mentioned algorithm. This is very useful when we want to check if such an element exists in the container — especially if we later want to do something with that element. For example, we may want to remove all numbers with a certain value from a vector.

Let’s recall how to use std::ranges::find() by checking if the given vector contains numbers: 2, 4, or 6:

#include <algorithm>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto numbers = std::vector<int>{1, 2, 3, 4, 5, 6, 7, 8};

    auto const posOf2 = std::ranges::find(numbers, 2);
    auto const posOf4 = std::ranges::find(numbers, 4);
    auto const posOf6 = std::ranges::find(numbers, 6);

    auto const twoPresent  = posOf2 != numbers.end();
    auto const fourPresent = posOf4 != numbers.end();
    auto const sixPresent  = posOf6 != numbers.end();

    if (twoPresent or fourPresent or sixPresent) {
        fmt::println("2, 4, or 6 is / are present");
    }
}

This code, of course, displays the message from line number 18.

However, it’s hard not to notice a common feature of these three presented numbers. They are all even numbers.

Let’s assume we have a different task — one that doesn’t focus on the numbers 2, 4, or 6 specifically, but on a more general representation of the problem:

How to find an even number in a given container?

Very straightforwardly. By using the modulo operator (%):

#include <vector>

auto main() -> int {
    auto const numbers = std::vector<int>{1, 3, 5, 6, 7, 8};

    for (auto number : numbers) {
        if (number % 2 == 0) {
            fmt::println("found an even number: {}", number);
            break;
        }
    }
}

found an even number: 6

All’s good, although:

  • We’re using a raw loop that requires us to analyze its entire body to be sure of what it actually does.
  • We’re using the break statement, which, if possible, should be limited because it can introduce complex logic flows that are difficult to analyze. Maybe not in this example, but still, some argue that it should be avoided like the plague.

So let’s use a standard algorithm instead, which clearly suggests that we’re looking for a number that is even. The algorithm will be similar to the already mentioned std::ranges::find(). It’s called std::ranges::find_if(). However, we first need to understand what a predicate is.

Predicates

We’ve already learned about comparators and projections. In the further part of this chapter, we’ll learn exactly how to implement them, although we’ll start with a different type of function — the predicate.

A predicate is a function that tests something. It takes a single argument and returns true if it satisfies some condition.

For example, we can talk about the predicate that would test whether a number is even. This would be a function that takes a single argument and returns true if it is even, and false otherwise. Its implementation could look like this:

1
2
3

auto isEven(int const toTest) -> bool {
    return toTest % 2 == 0;
}

isEven() is clearly a predicate. It takes a single int argument and returns true if it’s divisible by two.

Great, but what does it have to do with std::ranges::find_if()?

A very good question. But first, let’s answer another one — how do we call functions?

By using their name.

Okay, so to call isEven(), you need to write this code, right?

1
2
3

auto main() -> int {
    isEven;
}

No… you need to include the parentheses.

Sure:

1
2
3

auto main() -> int {
    isEven();
}

And the argument.

Got it:

1
2
3

auto main() -> int {
    isEven(6);
}

So, to call a function, you need to:

  • use its name;
  • use parentheses;
  • pass all necessary arguments within the parentheses.

This is quite obvious. So why is this being discussed now?

Because the first of the above listings will compile. Yes, this one:

1

    return toTest % 2 == 0;

Is a valid C++ code. We used the name isEven, but we didn’t do anything with it. It’s like creating a variable and using its name without any context:

1

auto main() -> int {
    auto x = 10;
    x;  // here
}

We’ll reach the conclusion in a moment — I promise. Let’s just take a look at a very important, albeit obvious to most, statement:

We pass variables through arguments to pass data.

Perhaps it’s std::ranges::sort(). We pass some vector to it. Some data for it to sort.

Perhaps it’s std::ranges::find(). We pass some std::set to it. Some data among which it should look for something.

Perhaps it’s isEven(). We pass a single int to this function. Some data that will be verified in a specific way.

We already know how to pass data to functions. But what if we want to pass behavior?

std::ranges::find_if() takes at least two arguments:

  1. The range of data where it should search for an element that satisfies the condition.
  2. Instructions according to which it should verify whether the data meets the condition.

How do we pass behavior? How do we pass instructions? How do we pass code that represents the logic of a condition?

By passing a function.

We pass functions through arguments to pass behavior.

The following code will find and display the first even value from the numbers vector:

#include <algorithm>
#include <vector>

#include <fmt/base.h>

auto isEven(int const toTest) -> bool {
    return toTest % 2 == 0;
}

auto main() -> int {
    auto numbers = std::vector<int>{1, 3, 5, 6, 7, 8};

    auto const firstEvenNumberPosition = std::ranges::find_if(numbers, isEven);

    if (firstEvenNumberPosition != numbers.end()) {
        fmt::println(
                "The first even number is: {}",
                *firstEvenNumberPosition
        );
    } else {
        fmt::println("No even numbers found");
    }
}

1

The first even number is: 6

Naturally, the most interesting part is the initialization of the variable firstEvenNumberPosition. It’s the following code snippet:

1

std::ranges::find_if(numbers, isEven);

It’s crucial to note that after the name isEven, there are no parentheses specifying any arguments. We don’t want to call this function. We want to pass it. It will be used by std::ranges::find_if(). It’s this algorithm that will pass each subsequent number from numbers to isEven(). As soon as isEven() returns true, std::ranges::find_if() will return an iterator to the element that was just sent to this predicate. An iterator to the element for which isEven() returned true. An iterator to the element that satisfied the predicate we passed.

A potential issue that may arise is the fact that isEven():

  • is only called in one place in the code;
  • its (single) usage is relatively far from its implementation — it doesn’t make sense to implement a function “far away” (let’s assume the code listing is much larger) when it’s only used once — locally.

We should limit the scope of used tools as much as possible. That’s why we don’t create all variables as globals, but place them in function bodies. That’s why we don’t declare loop variables (e.g., auto i = 0) at the beginning of a function, but within the parentheses (e.g., for (auto i = 0; ...)).

With that in mind, let’s move the isEven() function right next to its usage:

Not good. The error tells us that we can’t define a function inside another function. What now?

Now we’ll use lambdas.

Lambdas

If we add = [] in the appropriate place when creating a function, something very interesting will happen. For example:

1
2
3

auto isEven(int const toTest) -> bool {
    return toTest % 2 == 0;
}

Could be changed to:

1
2
3

auto isEven = [](int const toTest) -> bool {
    return toTest % 2 == 0;
};  // notice the semicolon (;)

Effectively, we only added = [] after its name (and a semicolon at the end). What did this change?

First of all, isEven is no longer a function. isEven is a variable. A variable that has been initialized with a lambda.

You can’t define other functions inside a function. But you can declare and define variables. A lambda is an object that can behave like a function. For example:

1
2
3
4
5

auto main() -> int {
    auto useless = []() -> void { };

    useless();
}

The above code effectively does nothing. It creates an object named useless, which is a lambda. The literal []() -> void { } creates a lambda that does nothing. Such a lambda can be called like a regular function. If we were to use a function, it would look like this:

1
2
3
4
5

auto useless() -> void { };

auto main() -> int {
    useless();
}

Lambdas can do everything that functions can (and more!). For example, here’s a lambda (along with its usage) that displays a text familiar to all of us:

#include <algorithm>
#include <functional>
#include <ranges>
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto const words = std::vector<std::string>{
            "those", "are", "extremely",
            "random", "words", "in",
            "this", "particular", "example"
    };

    auto getSortedCopyByStringLengths = [](std::vector<std::string> copy) {
        std::ranges::sort(copy, std::ranges::less(), std::ranges::size);
        return copy;
    };

    auto const sortedCopy = getSortedCopyByStringLengths(words);

    fmt::println("{}", words);
    fmt::println("{}", sortedCopy);
}

auto main() -> int {

    auto isEven = [](int toTest) -> bool {
        return toTest % 2 == 0;

    if (firstEvenNumberPosition != numbers.end()) {

        fmt::println("No even numbers found");

Given that lambdas can behave just like functions, it’s no wonder that the above code correctly displays The first even number is: 6.

std::ranges::find_if() produced the correct result using the isEven() function. Since the lambda isEven can behave the same way as the mentioned function, it’s no surprise that std::ranges::find_if() produces an equally correct result when using it.

It’s worth noting that a lambda can be used directly at its point of use. That is, instead of writing code like this:

1
2
3
4

auto isEven = [](int const toTest) -> bool {
    return toTest % 2 == 0;
};
auto firstEvenNumberPosition = std::ranges::find_if(numbers, isEven);

We can implement it like so:

1
2
3
4
5

auto firstEvenNumberPosition = std::ranges::find_if(
        numbers, [](int const toTest) -> bool {
            return toTest % 2 == 0;
        }
);

In summary, lambdas allow us to bypass the issue of not being able to define functions within functions. They create objects that can behave like functions.
