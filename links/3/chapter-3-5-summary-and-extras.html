Chapter 3.5 - Summary and extras

Posted Mar 16, 2025
By Filip Kwiatkowski
8 min read

New standard algorithms and controlling elements

We’ve learned about:

  • std::ranges::find(), which returns an iterator to the searched element.
  • std::ranges::max() and std::ranges::min(), along with their _element() suffixed versions:
    • the “basic” versions return the largest or smallest object from the range;
    • the _element() suffixed versions return an iterator to the largest or smallest element.
  • std::ranges::less and std::ranges::greater, which are types representing comparator logic.
  • std::ranges::size, an object-function that returns the size of the passed argument — very useful in projections.
  • std::ranges::find_if(), which is a sibling algorithm to std::ranges::find(). The difference between them is that the “basic” version searches for an identical element to the one passed, while the _if() suffixed version takes a predicate and searches for the first element that satisfies that predicate.
  • std::ranges::transform(), which allows the transformation of one range into another.

Intuitively understanding the workings of comparators, projections, or predicates can be somewhat difficult, so it’s worth trying to work on the principle of association. For example, one could say that a sorting algorithm works like this:

std::ranges::sort(WhatToSort, HowToSort, ByWhat)

And a transforming algorithm works like this:

std::ranges::transform(What, WhereToWrite, HowToChange) 1

Lambdas

Lambdas solve the problem of the inability to define local functions. They are function objects.

Unique and hidden type of a lambda

Seeing such code for the first time:

1
2
3
4
5
6
7
8
9

#include <fmt/base.h>

auto main() -> int {
    auto useless = []() -> void { };

    auto greeter = []() -> void {
        fmt::println("Hello World!");
    };
}

One might wonder what type the objects useless and greeter are. After all, auto allows us to omit the type — we can do auto x = int(), but at the same time, we can initialize this variable directly with some literal, e.g., auto x = 0;.

What would creating a variable useless or greeter without using auto look like?

It wouldn’t look good. It’s impossible to “manually” specify the type of such a variable. A lambda literal (i.e., []() {} with return type or arguments decorations) has a unique type generated by the compiler. We cannot manually introduce it.

There are alternatives using type erasure mechanisms, but they are less efficient. So it’s worth remembering one thing:

When creating variables that are lambdas, use auto.

Furthermore, two identical lambdas have different types!

For example, when we create a lambda, there’s nothing stopping us from copying it:

1
2
3
4

auto main() -> int {
    auto lambda = []() { };
    auto copy   = lambda;
}

Both lambda and copy have the same type — auto can deduce it and substitute it appropriately. However, when we try to initialize copy with an identical lambda, and then overwrite one with the other, the code won’t compile:

1
2
3
4
5
6

auto main() -> int {
    auto lambda  = []() { };
    auto another = []() { };

    lambda = another;
}

1
2
3
4
5
6
7

main.cpp:5:14: error: no match for 'operator=' (operand types are 'main()::<lambda()>' and 'main()::<lambda()>')
    5 |     lambda = another;
      |              ^~~~~~~
main.cpp:2:21: note: candidate: 'constexpr main()::<lambda()>& main()::<lambda()>::operator=(const main()::<lambda()>&)'
    2 |     auto lambda  = []() { };
      |                     ^
main.cpp:2:21: note:   no known conversion for argument 1 from 'main()::<lambda()>' to 'const main()::<lambda()>&'

That’s because even though lambda literals may look the same, each lambda literal represents a unique type.

Alternative to reading vector elements

In the earlier part of the chapter, a code snippet was presented that read elements from the user into a vector:

1
2
3
4
5

auto numbers = std::vector<int>(21);

for (auto i = 0; i < numbers.size(); i++) {
    std::cin >> numbers[i];
}

Alternatively, the same can be achieved using a range-based loop that utilizes references to elements:

1
2
3
4
5

auto numbers = std::vector<int>(21);

for (auto& number : numbers) {
    std::cin >> number;
}

As you can see, references can be used not only as local variables or parameters but also in loop variables. number here refers to each element of numbers. Without the ampersand (which denotes a reference — &), number would be a copy of each subsequent element.

Safe advancing of iterators

In one of the tasks discussed in this chapter, there was a segment where we moved a given iterator three places to the right. This was accomplished with the following code snippet:

1

start += 3

That was part of a loop that executed until start != numbers.end(). However, what if numbers didn’t have a number of elements divisible by 3? Such iterator incrementation would go beyond the range, resulting in Undefined Behavior. It’s worth considering a safer alternative:

1

std::ranges::advance(start, 3, numbers.end())

The std::ranges::advance() algorithm moves the iterator passed as the first argument by the number of places specified in the second argument, but ensures that this advancement does not go beyond the third argument. Effectively, this is a safer alternative for scenarios where we are unsure whether the advancement would exceed the end of the range.

Inverses of algorithms and comparators

Reversing the algorithm and the comparator will yield the same result.

This means that the following two code listings will effectively do the same thing:

1

std::ranges::max(someRange);

1

std::ranges::min(someRange, std::ranges::greater());

That’s because std::ranges::min() when seeking the “smallest” element effectively looks for one that is “smallest” according to the provided comparator. std::ranges::greater() “sets up” largest elements first, but std::ranges::min() is unaware of this. Hence the above equivalence of operations arises.

The std::ranges::minmax_element() algorithm

In this chapter, there was an example of swapping the positions of the smallest and largest values in a given container. It looked something like this:

1
2
3
4

auto maxIter = std::ranges::max_element(numbers);
auto minIter = std::ranges::min_element(numbers);

std::ranges::iter_swap(maxIter, minIter);

The code for this can be simplified. There’s an algorithm called std::ranges::minmax_element() that returns a pair of iterators — one pointing to the smallest and one pointing to the largest element.

This algorithm exists because there’s a faster way to find such a pair “at once” than searching for one first and then the other separately.

You can use it as follows:

1
2

auto elements = std::ranges::minmax_element(numbers);
std::ranges::iter_swap(elements.min, elements.max);

The presented code can be further modified using so-called structured bindings. You don’t need to know about them as they will be explained in more detail in the chapter on maps:

1
2

auto [min, max] = std::ranges::minmax_element(numbers);
std::ranges::iter_swap(min, max);

Effectively, this breaks down the object into two local variables.

The default-value literal — {}

Empty braces can not only denote an empty container, as in the case of std::vector<int>{}, std::string{}, or std::set<float>{}, but they can also represent a default-constructed value when the type of that value is obvious. Let’s look at a few examples:

Explicit return type

The two functions below are equivalent:

1
2
3

auto makeInt() -> int {
    return 0;
}

1
2
3

auto makeInt() -> int {
    return {};
}

The compiler knows that makeInt() is supposed to return an int — after all, we wrote -> int. Therefore, it knows that {} will be used to create the default value — 02.

Argument

When the argument in a function is known and can be “default-constructed”, you can use {} to create a temporary value. Assuming the following function:

1

auto acceptInt(int n) -> void { }

You can call it by passing 0 as an argument in two different ways:

1

acceptInt(0);

1

acceptInt({});

It’s not particularly useful for ints, but when the type is long, such a shortened notation can greatly simplify the code. For example:

1
2
3
4

#include <vector>

auto acceptVector(std::vector<int> vec) -> void { }

auto main() -> int {
    acceptVector({});
}

#include <algorithm>
#include <functional>   // std::ranges::less
#include <ranges>       // std::ranges::size
#include <string>
#include <vector>

#include <fmt/ranges.h>

auto main() -> int {
    auto words = std::vector<std::string>{
            "those", "are", "extremely",
            "random", "words", "in",
            "this", "particular", "example"
    };

    std::ranges::sort(words, {}, std::ranges::size);

    fmt::println("{}", words);
}

We know that the second argument for std::ranges::sort() is a comparator, whose default type is std::ranges::less. So, it’s enough to use {} to create a temporary object of this type — there’s no need to write std::ranges::less().
